# 決定ログ(DECISIONS)

壁打ち(相談)や実装中に決まったことを、**日付つきで**記録する場所です。
新しい決定は下に追記してください。過去の決定を変える場合は、元の記録は消さずに、新しい決定として「○番を変更」と書いてください。

---

## 書式例

```markdown
### D-000 (YYYY-MM-DD) 決定の見出し
- **決定**:何を決めたか
- **理由**:なぜそう決めたか
- **影響**:どのファイル・作業に関係するか(任意)
```

---

## 決定一覧

### D-001 (2026-10-02) 言語・ライセンス・リポジトリ名
- **決定**:言語は Python、ライセンスは MIT、リポジトリ名は `npb-pennant-simulator` とする。

### D-002 (2026-10-02) 公開リポジトリには架空データのみを置く
- **決定**:公開リポジトリには、架空の球団・選手のデータのみを置く。球団名の実名も含めない。

### D-003 (2026-10-02) 実在データの収集コードは作らない
- **決定**:実在データの収集コード(スクレイピング等)は作らない。選手データは手作り、またはプログラムによる生成とする。

### D-004 (2026-10-02) セーブデータ方式の採用
- **決定**:セーブデータ方式を採用する。実名はユーザーが入力し、セーブデータの中にのみ存在する。

### D-005 (2026-10-02) セーブデータはリポジトリ外に保存
- **決定**:セーブデータはリポジトリの外に保存し、`.gitignore` でも除外する。

### D-006 (2026-10-02) セーブデータの形式
- **決定**:セーブデータは JSON 形式とする。形式のバージョン番号と乱数のシードを含める。

### D-007 (2026-10-02) 入力必須項目
- **決定**:ユーザーの入力必須項目は球団名のみ。選手は自動生成を基本とする。

### D-008 (2026-10-02) 球団名の入力方法
- **決定**:球団名の入力は対話式とする。空欄の球団は架空の初期名で補う。

### D-009 (2026-10-02) 画面と本体の分離
- **決定**:画面部分とシミュレーション本体は分離する。

### D-010 (2026-10-02) 3段階の開発
- **決定**:開発は3段階(①計算本体 → ②CLI → ③GUI)で進める。GUI の具体的な方式は段階③の前に決める。

### D-011 (2026-10-02) 公開サイト化する場合の扱い
- **決定**:公開サイト化する場合は、セーブデータの保存場所と権利の整理を別途行う。

### D-012 (2026-10-02) LICENSE の著作権者名
- **決定**:MIT ライセンスの著作権者名は `yuusukekokubu-a11y`(GitHub のユーザー名)とする。
- **理由**:公開リポジトリのため、本名を出さずに済む形にした。

### D-013 (2026-10-02) マージ報告 Issue の番号の付け方
- **決定**:マージ報告 Issue のタイトルは、報告書だけの独自連番とする。書式は `報告#<連番> マージ報告: <要約>`。
- **理由**:GitHub では PR と Issue が同じ通し番号を共有するため、GitHub の番号をそのまま使うと報告の連番が飛び飛びになる。
- **影響**:CLAUDE.md、`.github/ISSUE_TEMPLATE/merge_report.md`
