## 作り直しの方針(能力表示型のペナントモードへ。これから置き換える)

ここに書いた方針は、作り直し ①〜④ の PR で実装します。それまでは、下の各分野の決定が今のコードの決まりです。置き換える決定は、その段階の PR で一覧から外します(D-345)。

- 選手の能力を画面に出して遊ぶ、能力表示型のペナントモードに作り直す。セイバーメトリクスは成績の「セイバー」切り替えに残す。試合の計算・成績と指標・順位表・保存の仕組み・ブラウザで動く仕組み・選手の自動生成・加齢と引退は土台として残す。リポジトリには特定の市販ゲームの名前や独自の用語を書かない。(D-334)
- Issue #90 の論点(主力級も金額で残る・ほかの球団も同じ条件で引き留める・期待の上限 1.25 倍は妥当)は、作り直しの FA で扱う。(D-332)
- ①:プロの選手の能力はいつでも見える。ドラフト・外国人の候補は見立ての数字で見せる。(D-335、D-418)
- ①:能力の項目は 野手 弾道・ミート・パワー・走力・肩力・守備力・捕球、投手 球速・コントロール・スタミナ・変化球。特殊能力は後から足せる形。細部は ① の開始時に決める。(D-336)
- ①:伸びやすさは裏に残して画面に出さない。天井(潜在能力)はなくし、成長と衰退の釣り合いを作り直す。(D-337)
- ①:答え合わせモードはなくす。(D-338)
- ①:今までのセーブデータは使えなくなる(読み込むと分かりやすく出す)。(D-344)
- ①:能力は 1〜100 の整数とランク(S 90〜・A 80〜・B 70〜・C 60〜・D 50〜・E 40〜・F 20〜・G 〜19)。一軍の平均はおよそ 60。弾道 1〜4、球速 km/h、変化球は球種ごとの変化量 1〜7。(D-347)
- ①:新しい項目にない能力(選球眼・走塁判断・回復力・走者抑制・打球抑制・投手のゴロ/フライ傾向)は全員平均にそろえる。打者のゴロ/フライ傾向は弾道から。(D-348)
- ①:見せる能力が正本で、試合の計算は換算した内部の能力を使う(式は変えない。換算表は設定ファイル)。(D-349)
- ①:成長は毎年の「年齢による増減 × 伸びやすさ + 揺れ」。潜在能力は持たない。成長タイプと伸びやすさは隠し情報。校正は今までどおり。(D-350)
- ①:投手は 2〜4 個の球種を持ち、変化球を球種ごとの変化量で見せる。試合は合計の強さを使う。(D-351)
- ①:答え合わせモードをなくし、プロの能力を常に見せる(プロのスカウト評価は見せない)。ドラフト候補は ③ まで今の評価の形を新しい項目で出す。保存形式は版 14。(D-352)
- ③:FA は、権利を持つ選手が確率的に宣言 → あなたを含む各球団が年俸と年数を提示 → 選手が金額を中心に、元の球団への愛着も少し考えて選ぶ。(D-341)
- ③:自由契約市場は、能力を見て獲得でき、年俸は自動の簡単な形で残す。(D-343)
- ③ のあと、バランス調整の前に 打順 → 特殊能力 → 育成・外国人選手 → トレード を足す。現役ドラフトと、新規開始の設定で選べる追加の選択肢(例:自動 FA)も足す。怪我と試合中の采配は入れない。(D-364、D-372)

## 全体の設計(画面と計算の分離・差し替え口)

- 画面とシミュレーション本体は分離する。操作は計算本体の関数(`pennant.api`)として用意し、画面はそれを呼ぶだけの薄い層にする。(D-009、D-080、D-107)
- 打席結果の計算は差し替え可能な部品にする。(D-015)
- 他球団の判断(ドラフト・自由契約・獲得など)と監督の采配(一軍の選抜・スタメン・継投など)は、差し替え可能な関数にする。(D-019、D-061、D-078、D-205)
- 計算本体は Python 標準のライブラリだけで作る。ファイルの読み書きは書かず、保存の差し替え口(`storage.py`)を通す。(D-083、D-101)
- 初期データ(生成の数値・名前の部品・打席の計算の数値など)は JSON で `src/pennant/data/` に置き、読み込み時に検証する。差し替えもできる。(D-050)
- 最終形(WAR・複数年・球団経営)を見据え、後で要る記録は最初から持てる形にする。球種別の分析は WAR の後の将来目標で、追加の余地だけ残す。(D-018、D-025)
- ファイルの分け方は保守②のまま(画面は `web/js/` の画面ごと、橋渡しは `api/` の分野ごと)。どこに何を書くかは DESIGN 2.1 で確定。(D-291、D-295)
- オフの手続きの計算は、土台(`procedure.py`)→ 契約の段階(`contract_stage.py`)→ 市場(`market.py`)→ 指名と完了(`draft.py`)の一方向に分ける。名前は今までどおり `draft` からも使える。(D-302)
- src と web の 1 ファイルは 800 行以内が目安。超えるなら分けるのが基本で、分けないときは理由を DESIGN に記録する(tests と scripts は対象外)。(D-288)
- 画面は入口の `web/app.js` と、画面ごと・部品ごとの `web/js/*.js`(ES モジュール:import と export でつなぐファイル。ビルドなしで公開できる)に分ける。橋渡しは `src/pennant/api/` に分野ごとの部品(Mixin)で分け、`Game` はそれらを合わせた 1 つのクラスにする(呼ぶ名前は分ける前と同じ)。置き場所の決まりは DESIGN 2.1。(D-291)

## 球団職員

- 12 球団すべてが職員を持つ:監督 1・コーチ 3(打撃・投手・守備走塁)・スカウト 1。名前(架空)・年齢・腕(内部は 1〜100、画面は S〜E のランク)・特徴(監督の好み・元選手)・年俸・契約の残り年数。70 歳でやめる。値は `data/staff.json`。(D-469、D-473)
- 監督:采配の腕は継投の見極めが少しうまい程度(腕の段階 −2〜+2。終盤の接戦で疲れた先発を引っ張らない・救援は総合を先に見る。腕が低いと先発を引っ張る)。試合の前の状態に腕の段階を記録する。方針の好み(なし・若手・勝ちにいく・バント多め・盗塁積極的・打って勝つ)は、AI がチーム方針を決めるときに入る(あなたが決めた方針には効かない)。方針は年度の確定と職員の段階の後に決め直す。(D-470)
- コーチ:年度の確定で、分野(打撃 = ミート・パワー、投手 = 球速・コントロール・スタミナ・変化球、守備走塁 = 走力・肩力・守備力・捕球)の伸びを、12 球団の同じ役割のコーチの平均より腕が 1 点高いごとに 0.5% 増やし、衰えを 0.25% 減らす(平均と同じで標準。リーグの水準を動かさない)。一軍・二軍・育成すべて。設備と練習の重点と掛け合わせる。(D-471)
- スカウト:見立てのずれに 1 − 0.007 ×(腕 − 60)を掛ける(0.6〜1.4)。新規開始のずれの大小は全体の基準のまま。(D-472)
- 効きは、腕のいい職員でも設備を 1 段階上げたくらい。(D-473)
- 雇い方:オフの手続きの「職員」の段階(契約の次、FA の前)。職員の市場(前の年の残り・契約切れ・解任・架空の新人 15・引退した選手のうち通算 WAR の高い 6 人まで。40 人まで)から、希望を前年の順位が低い球団から 1 人ずつ(自由契約市場と同じ形)。年俸はランクの表(監督は 2 倍)で資金から出す(設備の維持費と同じく、年俸に使える額から引く)。締めた後の空きは最も安い候補で埋める。AI も自動で雇う。(D-474)
- 契約は 1〜3 年。職員の段階で解任できる(残りの年俸は払う)。AI は最下位 40%・5 位 15% で監督を代える。契約が切れた職員は市場に戻る。(D-475)
- どの球団の職員も、チームのページからいつでも入れ替えられる(市場の候補と。今の職員は解任の扱い)。触った他球団は「あなたが決めた」になり、AI は監督を代えない。「AI に戻す」で次のオフから AI が雇う。(D-476)
- 画面:職員の段階(自球団の職員・市場・希望・解任・締める)、チームのページの職員の表と入れ替え、記録室の「監督」(監督ごとの通算の勝敗・優勝・日本一と、コーチ・スカウトの所属の履歴)。(D-477)
- 新規開始は事前運転と校正の後に初期の職員を付ける(事前運転では職員の市場を回さない)。テンプレートは作り直す。(D-478)
- 指紋は版 38。30 年の安定で、職員の効きで能力の水準や戦力の差が崩れないことを確かめる。(D-480)

## 試合の計算(打席・走塁・采配)

- 試合は打席単位で計算する。(D-015)
- 打席は2段階で決める:①三振・四球・死球・本塁打・インプレー(打球が前に飛ぶ)のどれか ②インプレーなら打球の種類・方向・担当ポジションを決め、守備の能力でアウト・安打・失策を決める。BABIP(インプレーの打球が安打になる率)は②だけで決まる。(D-035、D-038)
- 打者と投手の能力はオッズ比法(リーグ平均と比べた倍率を打者側と投手側で掛け算する方法)で合成する。リーグ平均の率は架空の設定値で、10 点あたりの倍率は校正して決める。(D-036)
- 左右の相性はリーグ共通の補正(同じ側は投手有利)。両打ちは有利な側で打つ。選手ごとの左右差は後から足せる形。(D-037)
- 打球の落下地点や速度の座標は再現しない。野手が処理できない打球は別の割合で扱う。(D-038)
- 内野手が担当した安打は、投手・捕手・二塁・遊撃は単打だけ、一塁・三塁は単打中心で二塁打を少し(三塁打なし)。(D-072)
- 再現するプレーは打席の結果・進塁・併殺・犠牲フライ・盗塁・暴投・捕逸・送りバント。ボーク・牽制は未導入で、後から足せる形にする。(D-045、D-427、D-458)

- 特殊能力は良いもの・悪いものの対(野手:チャンス・対左投手・走塁・パワーヒッター/アベレージヒッター、投手:ピンチ・対左打者・奪三振・重い球/一発気味)。野手の「バント◯/×」は送りバントのときだけミート ±15(◯ 10%・× 8%。D-460)。内部の能力に条件つきで足す(仮置き)。作るときに確率で付き、毎年のオフに低い確率で変わる。候補は見せない。種類は `data/skills.json` で足せる。(D-374、D-460)
- 育成選手は支配下 70 人とは別枠で 1 球団 20 人まで。試合に出ない。ドラフトの後の育成ドラフト(仮置き 4 巡)で取り、年俸は育成の年俸(仮置き 300 万円)。あなたは市場の段階で支配下に上げられ、AI と最低人数の補充は総合の高い育成選手を先に上げる。3 シーズンで上がらなければ自由契約。(D-375)
- 外国人選手は新規開始で各球団 5〜6 人。毎年のオフの「外国人」の段階(FA の後・ドラフトの前)で、見立ての能力が見える候補(仮置き 24 人。D-418)を、市場と同じ方式(希望 + 前年の順位が低い球団から)で獲得する。年俸は内部の評価の段階の表、契約 1 年。一軍に登録できる外国人は 4 人まで。(D-376)

## 指標(基本・セイバー・基準値)

- 指標は3弾に分ける:①個人の記録だけで出せるもの ②リーグ全体の基準値が要るもの(wOBA・wRC+・OPS+・FIP・球場補正)③守備・走塁・ポジション補正が要るもの(WAR)。(D-018、D-026)
- 打席ログには、結果の種類と走者・アウトの状況(24 通り)を必ず記録し、後から過去の分も計算できるようにする。(D-026)
- 成績と指標は打席ログ(と登板の記録)からその都度計算し、別に数え上げない。集計の単位は今はシーズン通算と試合ごと。(D-096)
- 打者の記録に犠打(成功した送りバントだけ)。犠打は打席に入れ、打数・出塁率と wOBA の分母・BABIP の分母に入れない。バントの打席は走塁の得点・守備の得点の数に入れない。成績の打撃の基本の表に「犠打」の列。(D-459)
- 勝利・敗戦・セーブ・ホールドは公式記録の簡易版の基準で決める。ホールドは登板中に点を取られてもリードを保てば付く。(D-067、D-094、D-105)
- 自責点は、得点した走者の出塁・進塁に失策が関わっていなければ、その走者を出した投手に付ける(簡易版)。打点は併殺打と失策による得点を除き、押し出しは含める。(D-067、D-095)
- 規定打席はチーム試合数 × 3.1(四捨五入)、規定投球回はチーム試合数 × 1.0。(D-096)
- 指標の定義(表示名・解説・区分(基本/セイバー)・計算式・表の列と並び順・元の数の解説)は `metrics.json` にまとめ、SPEC の用語集とずれないようテストで照合する。(D-097、D-109、D-119)
- OPS は「基本」の区分。セイバーの表には OPS+ を置く。(D-130)
- サヨナラ安打の公式の数え直しは再現せず、解説に注記する。(D-098)
- wOBA(打撃の結果を得点の価値で重みづけした出塁率に近い指標)は、RE24(走者とアウトの24状況ごとの得点期待値)から線形加重(結果ごとの得点価値)を求めて作り、目盛りはリーグの出塁率に合わせる。(D-063、D-123)
- RE24 と線形加重の細部:失策による出塁は重み 0、サヨナラで打ち切られた半イニングは集計から外す。(D-123)
- wRC+・OPS+ は 12 球団合算のリーグ平均を 100 にする。(D-124)
- FIP(守備の影響を除いた投手の指標)は標準の係数(13・3・2)+ FIP 定数。係数の出どころは設定で切り替えられる形。球場補正はしない。(D-125、D-144)
- 初年度の基準値は、新規開始時に見えない試運転のシーズンを1回回して求める(成績は出さず保存しない)。「既定値を使う(速い)」選択肢と、既定値 `baselines.json` も持つ。(D-121、D-122)
- シーズン中の基準値は「比重 × 今シーズンの値 +(1 − 比重)× 出発点」で混ぜる。比重 = 累積打席 ÷(累積打席 + 20,000)。出発点は前シーズンの最終値(初年度は試運転の値)。(D-063、D-091、D-126)
- 基準値と指標の計算はすべて分数(Fraction)で行い、小数の誤差を出さない。(D-127)
- 指標を足す方法は A:定義データだけ / B:元の数を足す / C:打席ログに情報を足す、の3段階。C は節目にまとめて行う。(D-128)
- 通算の指標のうち基準値に依存するもの(wRC+・FIP など)は、シーズンごとの値を打席数(投手は投球回)で加重平均する。通算の WAR は合計。(D-192)
- カスタム指標(利用者が式を書く機能)は M2 の後に検討する候補。(D-129)

## 球場

- 各球場は本塁打と BABIP の「真の倍率」を持ち、オッズ比法の中の倍率として試合に入れる。真の倍率は隠し情報で、答え合わせ用に保持する。(D-064、D-136)
- 倍率の範囲は本塁打 0.85〜1.15、BABIP 0.97〜1.03(設定値。BABIP の範囲は据え置き)。各リーグ6球場の平均をちょうど 1.0 にそろえる。(D-136、D-153)
- 倍率は両チームの打者に掛かり、ホームの有利とは別。野手が処理できない打球の割合と失策率には掛けない。(D-136)
- 倍率は整数の千分率で持ち、リーグのシードから SHA-256 で導いた別の乱数で作る。(D-137)
- 真の倍率は答え合わせモードの段階1以上で球場のページに見せる。(D-138)
- 指標に使う球場補正は、結果から推定する。同じチームの本拠地とアウェイを比べ、複数シーズンを合算し、1.0 に向けて縮める(平均への回帰)。リーグ平均は 1.0 にそろえ、計算は分数。(D-064、D-140)
- 縮める定数は「1 シーズンの打席数 ×(推定の標準誤差 ÷ 想定する球場差)²」。対象は本塁打(9,100 打席)と BABIP(26,300 打席)だけ(仮置き)。(D-145、D-148)
- wRC+・OPS+ に使う補正は、得点ベースの1つの値。縮めた本塁打と BABIP の推定から、期待 wOBA を通じて組み立てる(直接推定した得点の比は検証用の表示だけ)。(D-141、D-147)
- その換算に使う基準値は `baselines.json` の固定値のまま。20 シーズン以上でずれが大きいときだけ見直す。(D-154、D-189)
- 選手の球場補正は、球場ごとの打席数で重みづけした平均。(D-142)
- 今シーズンの補正は前のシーズンまでの推定を使い、シーズン中は変えない。1 シーズン目は 1.0。(D-064、D-143)
- 推定の良し悪しは「全部 1.0 と推定した場合」との誤差の比較で判断し、相関は参考値。BABIP 単独の推定は「参考値」と注記する。(D-150、D-153、D-159)
- 球場 × シーズンの集計(整数)をセーブデータの履歴に残し、打席ログを捨てても推定を続けられるようにする。(D-146)

## WAR

- WAR の部品は 打撃・走塁・守備・ポジション補正・控え水準(控え選手の水準)・1 勝あたりの得点。(D-070、D-156)
- 盗塁・盗塁死の得点(得点期待値の変化 − リーグ平均)は走者の走塁に、その逆は捕手の守備に入れる。捕逸の得点(リーグ平均との差)も捕手の守備に。暴投は投手の失点に入るので別に数えない。記録は打者に盗塁・盗塁死、投手に暴投、捕手に盗塁企図・盗塁阻止・捕逸。暴投の点は自責点、捕逸の点は自責点にしない。(D-430)
- 走塁・守備に使う得点期待値表は、基準値の RE24(混ぜた値)をそのまま使う。(D-161)
- 打撃の得点 =((wOBA − リーグの wOBA)÷ 目盛り +(1 − 球場補正)× リーグの 1 打席あたりの得点)× 打席数。(D-162)
- 走塁の得点は、打席ごとの得点期待値の変化を「同じ状況」の平均と比べ、選択の余地があった走者に等分して付ける。打者自身の進塁は含めない。(D-163)
- 守備の得点は、担当した打球をポジション × 打球の種類ごとのリーグ平均のアウト率と比べ、アウト1つの価値を掛ける。球場の倍率と打球の質は反映しない(観測できる記録だけで計算)。(D-164)
- 守備の得点は縮めずに入れ、守備の能力の効きも変えない。複数年の WAR を見て再判断する。(D-171、D-181、D-195)
- ポジション補正(点/125 試合)は 捕手 +3.5・遊撃 +2.5・二塁/三塁/中堅 +1.5・左翼/右翼 −1.5・一塁 −2.5・指名打者 −4.5。守備アウト数(指名打者は打席数)で按分する。(D-168、D-180)
- ポジション補正は出場量で重みづけした合計を 0 にし、値を変えるときは控え水準も同時に調整する。(D-175)
- 控え水準は設定値(野手 0.0306 点/打席、先発 0.82・救援 0.53 点/9 回)。WAR の合計の目標は「勝ち数の合計 − .290 × チーム試合数の合計」、野手:投手 = 約 6:4。(D-169、D-176)
- 1 勝あたりの得点 = 2 × 1 チーム 1 試合あたりの得点(ピタゴラス勝率、指数 2)。(D-170、D-176)
- 打者の WAR =(打撃+走塁+守備+ポジション補正+控え水準)÷ 1 勝あたりの得点。(D-171)
- 投手の WAR は FIP 版(球場補正なし)と失点版(球場補正あり、チームの守備の得点の投手の分を差し引く)の両方を出す。(D-070、D-171)
- 選手 × シーズンの得点と WAR は打席ログから再集計し、内訳つきで分数で持つ(保存形式は変えない)。(D-165、D-172)

## 複数年(年度の確定・履歴・事前運転)

- シーズンの間は「年度の確定(基準値・球場補正の更新)→ 加齢 → 成長・衰退 → 引退 → オフの手続き → 次のシーズンの準備」の順(オフの手続きの中身は D-201 以降)。怪我はまだ入れない。(D-071、D-201)
- 新規開始では、初期選手の生成の後に、試合なしで年度の確定の処理だけを数十年分回し(事前運転)、一軍相当の平均が 50 になるよう潜在能力に役割ごとの定数を足す(校正)。(D-190、D-197)
- 校正の定数は、スカウト評価のずれの大きさ(小・中・大)ごとに持ち、後から入る新人にも足す。引退の判定は校正前の目盛りで行う。旧版のセーブには適用しない。(D-197、D-209)
- 事前運転では、志望の判定(更改で断る選手)も FA も行わない。FA 権の年数は新規開始時に補う。(D-254、D-265)
- 事前運転の短縮(20 年にするなど)は、スマホの新規開始の時間を測ってから決める(REQUESTS の候補)。(D-228)
- 受け入れ条件:複数の世界を 30 年回し、一軍相当の平均能力・リーグの成績・WAR の合計・年齢の分布・人数の構成に傾向がないこと。補充の仕組みを変えたら、この確認と校正をやり直す。(D-071、D-188、D-196)
- 新規開始時の一軍の平均 50 ± 0.5 は、1 つの値だけ超える場合は許容する(報告はする)。(D-219)
- 年度の確定は戻せないので、確認の画面で直前の状態の保存を案内する。取り消し機能は作らない(候補)。(D-185、D-194)
- 引退などで減った分は、ドラフトと市場で取る。新しく作った選手で埋める自動補充はしない。(D-184、D-201、D-391)
- 年度ごとの集計(成績・WAR・内訳・順位表)は全シーズン保存し、打席ログは直近 1 シーズン(`log_seasons`)だけ残す。ログのない過去の試合のページは開けない。(D-071、D-189、D-193)

## 新規開始のテンプレート(用意したリーグ)

- 用意したリーグ(テンプレート)は 1 つ。中身は今の新規開始と同じ状態(事前運転 25 年済みの架空の 12 球団と選手・契約・資金・設備・FA 権の年数・チーム方針と、試運転の基準値)。リーグの歴史は入れず、記録は 1 シーズン目から。紹介は前の年(試運転のシーズン)の各リーグの優勝球団と、戦力の最も高い・低い球団。(D-462)
- 置き場所は `src/pennant/data/templates/`:セーブデータと同じ形の `standard.sav`(1 日目の前の状態)と、情報の `standard.json`(版・リーグのシード・紹介)。パッケージに入れ、ブラウザでも読む。(D-463)
- 「新しく始める」の最初に「用意したリーグで始める(すぐ)」「新しくリーグを作る(20 秒ほど)」の 2 つのボタン。その後は名前の段 → 設定の段。用意したリーグでは、詳しい設定にリーグのシード・基準値の求め方・スカウト評価のずれを出さない。(D-464)
- テンプレートで選べるのは 球団名・リーグ名・球場名・自球団・自球団の資金力・仕組みの選択肢。シーズンのシードは毎回変わる(入れたらそれを使う)。始めた後はふつうの新規開始と同じに動き、保存形式は変えない。(D-465)
- 資金力を選んだら、その規模の球団のうち総年俸が最も少ない球団と規模を入れ替え(大 3・中 6・小 3 を保つ)、資金・設備・初期の年俸を新規開始と同じ方法で求め直す。外国人・育成をなしにしたら、その選手を取り除き、外国人がいたポジションに新人を、取り除く前の人数と 65 人の少ない方まで入れる。(D-466)
- 作り直しは `scripts/make_template.py`。選手の作り方・事前運転・契約・試合の計算・保存形式が変わったら作り直す。速いテストで版の一致、重いテストで「作り直したものと同じ」を確かめる。(D-467)

## ドラフトとスカウト

- 操作する球団は 1 つで、新規開始時に選ぶ。選ばなければ観戦のみで、オフの手続きはすべて自動。(D-198)
- 1 巡目は全球団が同時に入札し、重なったら抽選(外れた球団は入札し直す)。2 巡目からは前年の勝率が低い球団から順に、巡ごとに逆にする。1 球団 10 巡まで(空き枠の分まで)、候補は 120 人。何人取るかは球団が決め、一度パスしたらその年の指名は終わり(選択終了)。AI は支配下が目安(65 人くらい)に届くまで、届いていても最低 4 人指名する。(D-078、D-202、D-369、D-397)
- 指名した時点で入団する(入団拒否なし)。新人の年俸は巡ごとの表で決める。(D-078、D-232)
- 上限は 70 人(下回ってもよい)。指名は空き枠の分まで。ポジションは一軍に必要な最低人数だけ守る。(D-203、D-391)
- 自由契約市場には手放された選手と FA で決まらなかった選手が並ぶ。指名されなかった候補は市場に出さず、リーグを去る。残った選手はそのオフの終わりにリーグを去る。(D-204、D-398)
- 市場の年俸は算定の年俸(1 年)で自動、選手は断らない。各球団が獲得の希望を出し、ドラフトの 2 巡目以降と同じ順(前年の順位が低い球団から)で 1 人ずつ獲得する。市場の選手は能力が見える。(D-343、D-370、D-398)
- 新規開始の事前運転では FA を行わない(宣言しない)。ドラフトと市場はゲームの中と同じ方式。(D-254、D-370)
- AI 球団もプレイヤーと同じスカウト評価(球団ごとのずれ)で判断し、真の能力は使わない。(D-205)
- AI 球団の自由契約の方針(27 歳以上・推定値 40 未満・年 3 人まで)は据え置き。年齢の下限は契約・FA と一緒に設計する。(D-217、D-227)
- ドラフト・育成ドラフト・外国人の候補は、能力の数字と特殊能力を自球団のスカウトの見立て(推定値)で見せ、入団すると本当の数字になる。A〜E の評価と一言は画面に出さない(内部の判断には使う)。同じ候補は何度見ても同じ。年齢・出身・左右・ポジションは正確に見える。対象はリーグに新しく入る選手だけで、プロの選手は本当の能力が見える。(D-368、D-418)
- 特殊能力の見立ては、持っているものを確率で見落とし、持っていないものを確率で 1 つ「ある」と見る。確率はずれの大きさに比例(中で 25%・20%。仮置き)。別の乱数の系列。(D-419)
- 評価のずれは「全項目に共通の見誤り」+「項目ごとの見誤り」の 2 層。項目の誤差は 小 3・中 5・大 8、共通の部分は 小 2・中 4・大 6(据え置き)。(D-212、D-224)
- 内部の評価(A〜E。AI の判断と外国人の年俸の段階に使う)は、ピークまでの伸びを見込んだ総合値に別の乱数の見誤りを足し、そのオフの候補全体の分位点(A 上位 10%・B 20%・C 30%・D 25%・E 15%。仮置き)で決める相対評価。(D-218、D-368)
- ずれの大きさは全球団共通の設定(既定は中)だが、球団ごとの値を持てる形にする(スカウトの腕で球団ごとに変わる。D-472)。(D-200)
- 入団した選手には入団時の評価(項目ごとの推定値を含む)を保存する。ドラフト・外国人で入った選手は、選手のページに入団時の見立てを今の数字と並べて出す。保存形式は変えない。(D-335、D-368、D-420)
- 記録室の「補強の記録」で、入団の経路・入団時の見立て(総合)と今の総合・今の所属・出場と WAR の累計を一覧にする。(D-078、D-216、D-420、D-422)
- 下のタブに「記録」を足し、記録室に歴代の順位と優勝・年ごとのタイトル・通算記録のランキング・補強の記録(当たり・外れはドラフトと外国人、出入りの記録)をまとめる。(D-422)
- 記録室:終わったシーズンの順位表と球団ごとの優勝回数。タイトルはリーグごとに打者 5 つ(首位打者・最高出塁率・本塁打王・打点王・最多安打)と投手 5 つ(最多勝・最優秀防御率・最多奪三振・最多セーブ・最多ホールド。率は規定に届いた選手だけ)。通算の上位 20 人(進行中を含み、引退した選手も)。補強の記録はドラフト(育成ドラフトを含む)と外国人の当たり・外れ、出入り(FA・トレード・市場・現役ドラフト・自由契約・支配下登録・引退)。ドラフトの振り返りの画面はなくす。保存形式・指紋は変えない。(D-423)
- 記録室のタイトルに盗塁王、通算記録に盗塁を足す。(D-432)
- これからの予定:日程の 143 試合(交流戦・オールスター)、ポストシーズン、けがと二軍、表彰、投手の起用の操作、チーム方針、12 球団の資金を選ぶ、新規開始のテンプレート(用意したリーグから選ぶ)、球団職員、個人成績の「すべて」のタブ。設備の種類を増やすは保留。財務と年度の確定の取り消しは作らない。(D-434)

## 契約と FA・資金

- 球団ごとに「資金」(70 人の年俸の合計に使える上限)を持つ。規模は 大 3・中 6・小 3 球団(新規開始のシードで割り当て)、基準額は 大 48 億・中 40 億・小 32 億円(仮置き)。総年俸が資金を超える契約(FA・市場の提示、ドラフトの指名)は結べない。お金のルールの選択はない。「収入と支出」は後の球団経営で。(D-339、D-353)
- 資金は毎年のオフの最初に、前のシーズンの順位で増減する(1 位 +5% 〜 6 位 −5%)。規模の基準額の 0.85〜1.15 倍に収める。(D-354)
- 新規開始で自球団の資金力(規模)を 自動・小・中・大・超大量 から選べる。自動は今までどおりシードで割り当て、選んだときはほかの 11 球団で 大 3・中 6・小 3 を合わせる(超大量は大として数える)。超大量は基準額の 120 倍(仮置き)。単価を求める資金の合計では、超大量を大の上限として数える。設備の初期は大と同じ。(D-410)
- 年俸は見える情報だけで決める:年俸 = 最低年俸 + 単価 × 見込みの WAR。見込みは成績(直近 3 シーズンの加重平均)と能力(見せる能力の平均からの目安。重みは満の出場 0.5 シーズン分)を混ぜ、30 歳以上は割り引く。(D-232、D-356)
- 年俸の単位は架空の「万円」。対応表・巡ごとの年俸・最低年俸は `data/contracts.json` に置く。(D-233)
- 単価は毎年のオフに「(資金の合計 ÷ 1.1 − 最低年俸の合計)÷ 見込みの WAR の合計」で求め直す。最低年俸 500 万円は仮置き。(D-355)
- 契約更改は全球団とも査定の年俸で自動。選手は受ける。1 年で下がるのは前の年俸の 25% まで。あなたは結果を一覧で見て、必要なら自由契約にするだけ。(D-340、D-357、D-358)
- 複数年契約は FA の契約と、主力級(見込みの WAR 2.0 以上・32 歳以下)の更改(2〜3 年)だけ。ほかは 1 年。複数年のあいだは査定を飛ばす。(D-233、D-360)
- 契約更改と自由契約は「契約」の1画面で行う。複数年契約中の選手も自由契約にでき、残りの契約は消える(違約金なし)。(D-236、D-272)
- 資金を超えたら、契約の段階で超過を解消する。AI は「(年俸 − 最低年俸)÷ 見込みの WAR」の大きい順に外し、解消できなければ最低人数を割っても外す。あなたは自分で選び、解消するまで次へ進めない。(D-235、D-255、D-361)
- ドラフトの指名と、年俸が最低年俸の契約(最低人数の補充・市場の最低年俸の選手)は資金に関わらず結べる。それより高い契約(FA・市場・外国人)は資金の中だけ(AI も同じ)。(D-235、D-391、D-394、D-396)
- FA で選手が選ぶ点数:年俸 ×(元の球団なら 1.1。愛着)÷(算定 × 期待の倍率)− 1 + 年数の加点 + 0.10 × 出場機会 + 0.05 × 勝てるチーム + 小さな乱数。最も高い提示を選び、−0.15 未満なら次のラウンドを待つ。全選手に共通(志望はない)。FA のブレーキは 70 人の枠と出場機会の項。同じ提示には同じ答え。(D-341、D-365)
- FA 権は、一軍に登録されたシーズンの通算 7 シーズン(設定値)で取得し、宣言したら数え直す。(D-249、D-258)
- 初期選手と旧版の選手の FA 権の年数は、年齢と履歴から別の乱数で補う。(D-258、D-264)
- 契約が満了した FA 権保持者は、見込みの WAR が高いほど高い確率で宣言する(年齢やチームの状況は使わない)。目標は宣言が年 15〜35 人、移籍が年 8〜12 人。(D-359、D-366、D-388)
- FA 市場は 3 ラウンドの提示制。選手は点数が最も高い提示を選ぶ。元の球団も同じ条件で提示する(愛着の分だけ有利)。補償はなし。決まらなければ自由契約市場へ。(D-260、D-365、D-367)
- AI 球団の FA:一軍に入る見込みがあり、見込みの WAR が一定以上の選手を、1 ラウンド 3 人まで、算定年俸 × 1.0・1.1・1.2 倍で狙う。(D-261)
- オフの手続きは 契約(更改と自由契約)→ FA → 外国人 → ドラフト(育成ドラフトを含む)→ 市場 → トレード → 現役ドラフト → 完了。各段階は保存して途中から再開できる。(D-201、D-260、D-272、D-375、D-376、D-378、D-380)
- トレードは支配下の選手どうし(1〜3 人 対 1〜3 人、お金なし)。シーズン中は全日程の 3 分の 2 まで、オフはトレードの段階。そのオフに入った選手は次の開幕まで出せない。交換の後も 70 人以内・最低人数・資金を守る。AI は価値(見込みの WAR − 年俸の分、若さの上乗せ)とチームの事情で、少し得をするときだけ受ける。AI どうしも年に数件、AI からの提案はシーズン中 2〜3 件・オフ 1〜2 件。シーズン中にトレードした球団は一軍を選び直し、試合ごとの一軍を記録する。(D-378)
- 現役ドラフト:全球団が 2 人ずつ候補を出し、前年の順位が低い球団から 1 人ずつ指名する。どの球団も 1 人出て 1 人入る。出せるのは、そのシーズンの最後の一軍に入っていなかった支配下の選手(外国人・育成・このオフに入った選手・年俸の高い選手は不可)。AI は価値の低い 2 人を出し、手薄なポジションを少し重んじて取る。契約はそのまま引き継ぎ、資金の決まりは当てない。(D-380)
- 新規開始で、仕組みの選択肢を選べる(始めた後は変えない):自動 FA(既定なし。D-390 の決まりで FA になり、元の球団は 1 ラウンド目に残留の提示をする)、現役ドラフト・トレード・外国人と育成(既定あり)。事前運転は自動 FA でも更改する。(D-381)
- 設備は 3 つ(練習:伸び、トレーナー・医療:年齢による下がり方、育成施設:育成選手の伸び)で 1〜5 段階。段階 3 が今までと同じ効きで、1 と 5 で 練習・トレーナー ±30%、育成 ±50%。資金から毎年の維持費(段階 1:0・2:5,000 万・3:1.5 億・4:3.5 億・5:7 億。仮置き)がかかり、その分だけ年俸に使える額が減る。オフの契約の段階で何段でも変えられる。新規開始は 大 3・中 2・小 2。AI は資金に応じて自動で決める。(D-383)
- バランス調整(設備の後)の目標:30 年の一軍の能力の差 ±0.3 以内、FA 移籍 年 8〜12 人、市場の AI の獲得 年 10〜20 人、自動 FA の移籍 年 15〜30 人、外国人の偏りを防ぐ、強さの差は今くらい、お金による強弱は付けてよい。(D-384)
- 自由契約市場:手放された選手の年俸は 算定 × 0.3(仮置き。最低年俸以上)。最低年俸の選手は資金に関わらず獲得できる。AI は空き枠の分まで最大 10 人、一軍か控えに入る見込みの選手を取る。(D-386)
- 外国人の偏りを防ぐ:外国人市場は外国人が少ない球団から獲得する。3 人より少ない球団は、年俸 4000 万円以下の候補なら 3 人まで資金に関わらず獲得できる。AI はトレードで外国人が 3 人より少なくなる交換を受けない。(D-387)
- FA の動き:宣言の確率は 基本 0.18 + 見込みの WAR 1 あたり 0.07(上限・下限あり)。AI の提示は見込みの WAR 0.3 以上。自動 FA では、ほかの球団の提示は 1 ラウンド 8 人まで。(D-388)
- 自由契約市場は、1 周目の後に、売れ残った選手を最低年俸で AI 球団が取る 2 周目を行う(あなたは加わらない)。校正の定数はバランス調整の後に取り直した。(D-389)
- 自動 FA:FA 権を取ったオフに、契約が残っていても必ず FA になる(契約は終わる)。その後は契約が満了するたびに FA。権利のない選手は更改する。外国人も同じ。(D-390)
- 自動補充(新しく作った選手で 70 人まで埋める)はしない。AI は 65 人くらいを目安にドラフトと市場で取る。最低人数を割る球団は、オフの終わりに市場の売れ残りから最低年俸で取る(同じポジションがいなければ、同じ投手・野手のほかのポジションで代用。あなたの球団も自動)。(D-391)
- 自動 FA のときの目標も通常と同じ(30 年の能力の差 ±0.3 以内、外国人 2 人以下の球団をほぼ出さない、移籍 年 15〜30 人)。(D-392)
- ドラフトは資金に関わらず全巡で指名できる(新人の契約は資金の外)。(D-396)
- 市場の 2 周目で目安(65 人)まで取るときは、見込みの WAR の高い選手から取る。目安を超える分は FA と同じ基準。自動 FA の AI の残留の提示は、ドラフトの上位と外国人の分を資金に残して行う。事前運転の市場も同じ方針。(D-395、D-398)
- 主ボタンは「この段階をおまかせ」(今の段階だけ AI の方針で代行し、何をしたかを一覧で出す。ドラフトと FA だけ確認を付ける)。「全部おまかせ」はメニューの中で確認つき。「次の手続きへ」は自分の操作を終えて進む意味。(D-271、D-284)
- 「FA 権の年数を出身で変える」案は候補として記録するだけ。(D-277)
- 主力級の期待:FA 市場で、宣言した選手は見込みの WAR が高いほど自分の価値を算定より高く見る(年俸の基準が上がる)。主力級は見込みの WAR 2.0 以上。(D-322)
- 期待の上げ幅には上限を付ける。FA 市場の AI も期待に合わせて提示し、主力級が誰とも契約できずにリーグを去ることを起こさない。(D-325)
- 期待の倍率 = min(1.25, 1 + 0.1 ×(見込みの WAR − 1.0))(仮置き)。保存せず見込みから毎回求める。(D-329)
- FA 市場の AI の年俸は 算定 × ラウンドの倍率 × 期待の倍率。自由契約市場には期待を使わない。(D-331)

## 画面(ブラウザ)

- 画面はブラウザの中で Python を動かす方式で、サーバーは使わない。Python は裏の計算(Web Worker)で動かし、画面を固めない。(D-081、D-107)
- 新規開始では球団名を入力欄で入れ、空欄なら架空の初期名を使う。「実名を入れたデータは共有しない」の注意を常に出す。(D-008、D-107)
- 新規開始の「詳しい設定」で、リーグのシードとシーズンのシードを別々に入れられる(空欄なら毎回ちがう値)。(D-113)
- 新規開始の「詳しい設定」で、リーグ名と球場名(球団の順)を入れられる。空欄は架空の初期名。点検は球団名と同じで、リーグ名の重複はできない。名前はセーブデータにだけ入り、読み込みでも点検する。事前運転の前に当てはめる。(D-409)
- 表を中心にし、スマホの縦持ちが基本(左端の名前の列を固定して横スクロール)。広い画面でも使いやすくする。広い画面(幅 900px 以上)ではタブを左の縦の列にし、選手・チーム・試合・球場のページを、元の画面の右に並べて出す(左右 2 列)。(D-086、D-223、D-402)
- 表示はすべて日本語で、専門用語には短い解説を付ける。下に固定のタブ(進行・順位・成績・試合・自球団。自球団は観戦のみのときは出さない)。(D-107、D-114、D-401)
- 画面の色は「ナイター」(濃い紺に金と水色)の 1 つだけで、端末の明るい/暗いの設定には従わない。色・文字・余白・角丸は CSS の変数で指定する。(D-399)
- ゲームらしい要素:球団のマーク(頭文字と球団の番号ごとの色)、進行の画面の「自球団 VS 次の相手」の得点板と大きな「1日すすめる」ボタン、順位・勝率・ゲーム差の大きな数字と連勝連敗・直近 10 試合、順位表と個人成績の 1〜3 位のメダル、個人成績の 1 位の選手のカード、選手のページのカード(能力はランクの札と数字。ゲージなし。特殊能力は右にまとめる)。(D-400)
- 上の帯は題と、保存・メニューの 2 つのアイコン(未保存は保存のアイコンに点)。「開く」はメニューの中。(D-401)
- 表の数字は等幅で右にそろえる。縦線は入れず、行は薄い横線。並べ替えた列は見出しを水色にし、▲▼ は見出しの文字の左に置いて、数値が左に寄らないようにする。(D-403)
- ロード画面:長い待ち(最初の起動・新規開始)は全画面(題・進み具合の棒・真ん中の絵・ヒントの札)。絵は「球場」(走者が塁を回る)か「歴史」(事前運転の年ごとの出来事)をメニューで選ぶ。最初の起動はいつも球場。短い待ち(画面の切り替え)は 0.3 秒を超えたら前の画面を暗くしてボールと「読み込み中…」。日を進める待ちは D-118 のまま。(D-405、D-407)
- 「歴史」に流すのは、その年の目玉の新人(総合値が最も高い入団者)・引退した名選手(引退前の総合値が最も高い選手)・戦力 1 位の球団(上位 25 人の総合値の合計)。事前運転の結果は変えない。(D-406)
- スクロールの棒の場所を常に空け、縦に長い画面と短い画面でボタンの位置を変えない。(D-408)
- 「新しく始める」「この内容で始める」は、押した瞬間にボタンに小さなボールを回して押せなくする。新規開始の名前の一覧と点検は、事前運転なしのリーグから作る(待ちを短く)。(D-411)
- 案に描いていない画面も同じ色・ボタン・表にそろえ、画面の並びと操作は変えない。見た目の変更で指紋は変えない。(D-239、D-404)
- 進行ボタン(1 日・1 週間・最後まで)は日の区切りで止められる。「止める」と進み具合は 0.6 秒を超えたときだけ出し、出したら 0.6 秒は残す。(D-107、D-118)
- 自動保存はしない。未保存のまま閉じようとしたら警告する。(D-084、D-107)
- ブラウザの保存領域に残すのは、ロード画面の形の選択(「stadium」か「history」の 1 つの値)だけ。名前やゲームの中身は残さない。(D-407)
- 進行の画面に、直近の日の全試合のスコアを出し、タップで試合のページへ。順位表では自球団の行を目立たせる。(D-107、D-117)
- 能力値・隠し情報は、答え合わせモード(既定オフ)でだけ見せる。オンの1段階目は現在の能力、2段階目は潜在能力・成長タイプ・生成時の型。公開用と答え合わせ用の関数は分ける。(D-086、D-108)
- 答え合わせモードの設定は保存しない(開き直すとオフ)。オンにするときは確認を出す。GM 版では新規開始時に決めて途中で変えない形にする。(D-108、D-114)
- 「能力」は表に数値(20〜80、5 刻み)を並べる。範囲外は端に丸めて印(80+ / 20-)を付ける。(D-115、D-197)
- 個人成績は「基本」「セイバー」「能力」「WAR」を切り替え、並べ替え・規定到達者(既定オン)・リーグ・チームで絞り込める。選手のページ・試合のページ・チームのページがある。(D-114、D-179)
- 個人成績は「打撃・守備・投球」の 3 つ。守備の表はポジション(すべて・捕手〜右翼手)ごとに 試合・守備イニング・失策・守備の得点(捕手は盗塁企図・盗塁阻止・阻止率・捕逸も)。守備の規定は、そのポジションでチームの試合数の半分以上スタメン。表は上位 30 人で、続きは「もっと見る」。両リーグをまとめた表はなく、いつも 1 つのリーグ(最初は自球団のリーグ)。(D-431)
- 表の既定の並び:打者の基本は打率順、投手は防御率順、打者のセイバーは OPS 順など(列と並び順は `metrics.json`)。(D-116、D-119、D-130)
- 切り替えをまたいで並び順と絞り込みを保ち、打者/投手の切り替えでは既定に戻す。並べた指標はいつも名前の隣の固定列に出す(表示にない指標でも。D-483)。状態は保存しない。(D-131、D-483)
- 並び順は、帯の「並び」で全指標(基本・セイバー・WAR・能力)から選べる。(D-132、D-482)
- WAR は観測できる記録だけから出すので、答え合わせモードに関係なく見える。シーズン途中は「○日目まで」と分かる表記にする。(D-179)

## 再現性(シード・指紋)

- 同じシード(乱数の出方を決める初期値)なら、端末(スマホ・PC)や Python の版が違っても同じ結果になることを必須にする。(D-006、D-088)
- 試合ごとのシードはシーズンのシードから、オフや次のシーズンのシードも `derive_seed` で導く。1 試合だけ取り出して再現できる。(D-066、D-186)
- 指紋(同じシードで同じ結果になるかを確かめる短い値。SHA-256)をテストに固定する。元にするのは離散的な結果と整数・文字列だけで、小数は入れない。(D-089)
- 版に依存する乱数の関数は使わず、`random()` だけを使った自前の処理にする。環境に依存する組み込みの hash() も使わない。(D-089、D-121)
- 保存日時は指紋に影響させない。途中で保存・読み込みしても、続けた場合と同じになることを指紋で確かめる(別の版で保存した見本ファイルも使う)。(D-100、D-103)
- 新しい要素(球場の倍率・契約・FA 権の補い・FA の選択・抽選など)は別の乱数系列で作り、既存の乱数の出方を変えない。(D-137、D-237、D-264、D-365、D-369)
- 指紋 (k) は3つの得点、(l) は WAR の集計(どちらもリーグ 1 で 3 シーズン)。(D-166、D-172)
- 特殊能力や試合の仕組みが変わって選手・結果が変わるときは、指紋を取り直して FINGERPRINT_VERSION を上げ、理由を書く(バント◯/× と送りバントで版 37、球団職員で版 38)。(D-460、D-480)
- 契約は別の乱数系列で作り、試合や AI の判断の乱数の出方を変えない。資金のある契約の流れは指紋 (o)(p) で確かめる。(D-237)

## テストと運用

- テストには pytest(Python のテスト実行ツール)を使う。CI(GitHub 上で自動でテストを走らせる仕組み)の権限は読み取りのみ、秘密情報は使わず、部品と pytest の版は固定する。(D-042)
- CI が失敗した・終わっていない PR はマージしない。Code はテストが通ったのを確かめてからマージする。(D-042、D-282、D-346)
- PR では速いテストを Python 3.10・3.12・3.14 で回す。main への取り込み後は速いテストを 3.12 だけ。同じ PR を出し直したら古い実行を止める。(D-089、D-279、D-280)
- 重いテストには印 `slow` を付ける。`pytest` は速いテストだけ、`pytest -m slow` で重いものだけ、`pytest -m ""` で全部。(D-280)
- 重いテストの境目は「1 つで 10 秒以上」または「複数シーズンを回す・作るのに 15 秒以上の準備を共有するもの」。(D-280、D-286)
- 重いテストは、計算本体(`scripts/ci_needs_slow.py` の範囲。`web/bridge.py` を含む)が変わった PR だけ 3.12 で回す。手動の実行でもいつでも回せる。画面だけの PR で回らないことは受け入れる。(D-280、D-287)
- 版をまたいだ指紋の一致の確認(`test_fingerprints_match_expected`)は速いテストに残す。(D-281)
- 重いテストのジョブ 1(約 8 分)は今のまま。(D-295)
- 速いテストは 1 つの版あたり 5 分以内が目標。1 つの版を 3 つのジョブ(まとめて回す作業の単位。指紋の一致の確認・a・b)に、重いテストも 3 つのジョブに分けて同時に走らせる。分け方は `scripts/ci_groups.py` で、新しいテストは「残り全部」のジョブに入る。部品とパッケージは増やさない。(D-280、D-285、D-293)
- 指紋は同じジョブの中で 1 回だけ作って使い回す(別の Python で確かめるテストと球場の倍率なしのテストは作り直す)。(D-294)
- 手元では、関係するテストだけを回す。速いテスト全体・3 つの版・重いテストは GitHub に任せる。受け入れ条件の測定(`scripts/inspect_*.py` など)はテストとは別に行う。保存形式の版を上げるときは、古い版の番号をリポジトリ全体で検索する。(D-279、D-412)
- 通し確認は○×を 1 つずつその場で出す。GitHub の Actions の「e2e」(手動で始める仕組み)でも回せ、結果は Summary に出す。(D-413)
- 30 年の安定の確認は、GitHub の Actions の「stability」(手動で始める仕組み)でも回せる。世界ごとに同時に回し、結果は実行のページの Summary に出す。手元で回す方法も残す。(D-363)
- 確認用の開発者向けスクリプト(`scripts/`)は残す。WAR などは、スクリプトと画面の値が一致することをテストで確かめる。(D-080、D-179)
