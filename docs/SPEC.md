## 3. 用語集
<!-- このプロジェクトで使う言葉の意味をそろえるための一覧 -->

| 用語 | 意味 |
| --- | --- |
| ペナントレース | シーズン全体を通した順位争い |
| セーブデータ | ユーザーが入力した内容や進行状況を保存したファイル。リポジトリの外に置く |
| シード(乱数のシード) | 乱数の出方を決める初期値。同じシードなら同じ結果を再現できる |
| セイバーメトリクス | 統計(データの集計・分析)を使って、選手の本当の貢献度を測ろうとする考え方。打率や勝利数のような昔ながらの数字より、得点や勝利への影響を重視する |
| 真の能力 | 各選手が内部に持つ隠し数値。画面には出ない。実際の成績は、この能力をもとに乱数で決まるため、同じ能力でも年によって成績が上下する |
| WAR | Wins Above Replacement の略。「控え水準の選手(簡単に代わりが見つかる選手)と比べて、何勝分チームに上積みしたか」を表す指標。打撃・守備・走塁・投球をまとめて1つの数字にする |
| 打率 | 安打 ÷ 打数。打数のうち、安打になった割合。高いほどよい。四球や長打の価値は入らない、昔ながらの目安 |
| 出塁率 | (安打 + 四球 + 死球)÷(打数 + 四球 + 死球 + 犠牲フライ)。アウトにならずに塁に出た割合。高いほどよい |
| 長打率 | 塁打 ÷ 打数。1打数あたりに進んだ塁の数(単打1、二塁打2、三塁打3、本塁打4)。長打が多いほど高い。高いほどよい |
| OPS | 出塁率 + 長打率。塁に出る力と長打の力をまとめた、攻撃力のおおまかな目安。高いほどよい |
| ISO | 長打率 − 打率。長打の力だけを取り出した指標。単打しか打たない打者は 0 になる。高いほどよい |
| BABIP | (安打 − 本塁打)÷(打数 − 三振 − 本塁打 + 犠牲フライ)。本塁打を除く、グラウンド内に飛んだ打球が安打になった割合。運に左右されやすく、極端な値は翌年に平均へ戻りやすい |
| K% | 三振 ÷ 打席(投手は 奪三振 ÷ 対戦打者)。打席のうち三振になった割合。打者は低いほど、投手は高いほどよい |
| BB% | 四球 ÷ 打席(投手は 与四球 ÷ 対戦打者)。打席のうち四球になった割合。打者は高いほど、投手は低いほどよい |
| 防御率 | 自責点 × 9 ÷ 投球回。9回を投げたら何点取られるかの目安。低いほどよい |
| wOBA | weighted On-Base Average(重みつき出塁率)の略。四球・死球・単打・二塁打・三塁打・本塁打に、得点への価値に応じた重みを付けて足し、(打数 + 四球 + 死球 + 犠牲フライ)で割った値。出塁率と同じ目盛りに合わせてあり、打者の攻撃力を1つの数で表す。高いほどよい |
| wRC+ | weighted Runs Created Plus の略。wOBA から求めた、打者が生み出した得点を、リーグ平均を100として表した値。120なら、平均より2割多く点を生み出している。高いほどよい |
| OPS+ | OPS をリーグ平均と比べた値。出塁率と長打率を、それぞれリーグ平均と比べて足し合わせ、リーグ平均を100として表す。高いほどよい |
| FIP | Fielding Independent Pitching の略。本塁打・四死球・三振だけから、投手の失点のしにくさを、防御率と同じ目盛りで表した値。守備や運の影響を受けにくい。低いほどよい |
| ドラフト | 新人選手を各球団が順番に指名して獲得する制度 |
| 自由契約 | 球団が選手との契約を打ち切り、その選手がどの球団とも契約できる状態になること |
| FA | Free Agent(フリーエージェント)の略。一定の年数プレーした選手が、自分の意思で他球団と契約できる権利、またはその権利を使った選手 |
| 契約更改 | シーズン後に、球団と選手が翌年の年俸などの契約内容を話し合って決め直すこと |
| GM | General Manager(ゼネラルマネージャー)の略。選手の獲得・放出・契約など、チーム編成を決める責任者。このシミュレーターでのプレイヤーの立場 |
| 標準偏差 | データのばらつきの大きさを表す数値。平均から「だいたいどのくらい離れているか」の目安。このプロジェクトの能力値では、10点が標準偏差1つ分(D-024) |
| 正規分布 | 平均付近の値が最も多く、平均から離れた極端な値ほど少なくなる、釣り鐘型のばらつき方。身長などが代表例。平均 ± 標準偏差1つ分の範囲に全体の約68%、± 2つ分に約95%が入る |
| 潜在能力 | 選手が最も力を発揮する時期(ピーク)の能力。隠し数値。現在の能力は、この潜在能力と年齢から決まる |
| 成長タイプ | 選手ごとの伸び方の違い。早熟(若くしてピーク)・標準・晩成(遅れてピーク)の3つ。隠し情報で、スカウト評価にも出ない |
| 生き残りバイアス | 生き残ったものだけを見ると偏って見える現象。プロ野球では、能力の低い選手は若いうちに引退・解雇されるため、高齢まで残っている選手は平均より能力が高くなる |
| インプレー | 打球がグラウンド内(フェアゾーン)に飛び、守備が処理する打席結果。三振・四球・死球・本塁打以外の打席がこれにあたる |
| オッズ比法 | 打者と投手の能力を組み合わせて結果の起きやすさを決める計算方法。「リーグ平均と比べて何倍起きやすいか」を打者側と投手側で掛け算する。例:三振しやすさが平均の1.5倍の打者と、三振を奪う力が平均の1.5倍の投手なら、およそ2.25倍になる |
| 左右の相性 | 投手と打者の利き腕・打席の組み合わせによる有利・不利。一般に、同じ側どうし(右投手×右打者など)は投手が有利、逆側どうしは打者が有利とされる |
| 担当ポジション | インプレーの打球を処理する野手の守備位置(例:三遊間のゴロなら遊撃手)。その野手の守備能力が、アウトになるかヒットになるかに影響する |
| 年齢カーブ | 年齢によって能力がどう上がり下がりするかを表す形。若いうちは伸び、ピークを過ぎると衰える。能力の種類ごとに形が違う(例:走力は早く衰え、技術は長持ちする) |
| RE24 | 走者の有無(8通り)× アウト数(3通り)= 24通りの状況ごとに、「その状況から、イニングの終わりまでに平均で何点入るか」(得点期待値)をまとめた表。例:無死満塁なら2点強、二死走者なしなら0.1点ほど。打席の前後で期待値がどれだけ増えたかで、その打席の得点への貢献を測れる |
| 線形加重 | 四球・単打・二塁打・本塁打などの結果ごとに、「平均で何点分の価値があるか」を RE24 から求めた値。結果の数にこの値を掛けて足し合わせると、得点への貢献をおおまかに表せる。wOBA の重みの元になる |
| パークファクター(球場補正) | 球場ごとの打ちやすさ・打ちにくさを表す倍率。1.0 が平均で、1.1 なら平均より1割ほど打ちやすい。打ちやすい球場を本拠地にする選手の成績を割り引いて、公平に比べるために使う |
| 回帰(平均への回帰) | 少ないデータから出した値は偶然の影響で極端になりやすいため、平均の方向へ引き戻して見積もること。例:1年だけの結果で 1.2 倍に見える球場も、真の倍率はもっと 1.0 に近いと考えて補正する |
| FIP 定数 | FIP を防御率と同じ目盛りにそろえるために足す数。リーグ全体の防御率と、リーグ全体の本塁打・四死球・三振から、毎シーズン計算する |
| 規定打席 | 打率などのランキング(タイトル)の対象になるために必要な打席数。チームの試合数 × 3.1 で決まる(例:125試合なら 387.5 → 388打席) |
| 規定投球回 | 防御率などのランキングの対象になるために必要な投球回。チームの試合数 × 1.0 で決まる(例:125試合なら 125回) |
| ゲーム差 | 順位表で、上のチームとどれだけ離れているかを表す数。上のチームとの「勝ちの差」と「負けの差」を足して2で割る。1ゲーム差は、直接対決1試合で追いつける差 |
| ラウンド制 | 日程の作り方の1つ。毎日、同じリーグの全チームが1試合ずつ行い、決まった日数で全チームとの対戦が一巡する。これを繰り返してシーズンの日程を作る |
| Pyodide(パイオダイド) | ブラウザの中で Python を動かす仕組み。インストールなしで、Web ページを開くだけで Python のプログラムが動く |
| GitHub Pages | GitHub のリポジトリの内容を、Web ページとして公開する機能 |
| キャッシュ | ブラウザが、一度読み込んだページやファイルを、次回すばやく表示するために一時的に保存しておくもの |
| ハードキャップ | 球団が選手に払う年俸の総額の上限のうち、絶対に超えられないもの |
| ソフトキャップ | 年俸の総額の上限のうち、超えることはできるが、超えると負担(罰金のような支払いなど)がかかるもの |
| 逆順位(ドラフト) | 前の年の順位が低い球団から順に指名する方式。弱い球団ほど良い新人を取りやすくし、戦力の差を縮める |
| スカウトの評価 | 画面に出る、選手の能力の見積もり(推定値 ± ふれ幅と天井)。真の能力とはずれがあり、ずれは球団ごとに違う(D-199、D-212) |
| 自責点 | 投手の責任による失点。失策(エラー)がなければ防げた失点は含めない。防御率の元になる |

## 4. 機能要件(何ができるか)

### 4.1 リーグ・球団
(D-021)
- 12球団・2リーグ制(各リーグ6球団)。
- 日程は「対戦相手ごとの試合数」を設定値として持つ(コードを変えずに変更できる)。
- 最初は同一リーグ内の対戦のみ:各相手25試合 × 5球団 = 計125試合。
- その後、交流戦(別リーグの6球団と3試合ずつ = 18試合)を加えて計143試合にする。
- クライマックスシリーズ(シーズン後の上位チームによるプレーオフ)は後から追加する。

### 4.2 選手
(D-017、D-022〜D-024、D-027〜D-031、D-033、D-034、D-039、D-041)

#### 人数(D-029)
- 1球団の選手は支配下70人を上限とし、70人で始める。
- 内訳の目安(設定値):投手 約32、捕手 約9、内野手 約18、外野手 約11。
- 育成選手は最初は持たない(F3 で検討)。
- 支配下の上限70人・一軍登録枠29人は確認済み(D-029 補足)。

#### 能力値
- 各選手は「真の能力」として能力値を持つ(画面には直接出さない)。
- 目盛りは **20〜80**。50 が「一軍の選手の平均」で、10点が標準偏差1つ分(D-024)。
  - 例:60 は一軍平均より標準偏差1つ分上、70 は2つ分上。新人・二軍の選手は 30〜40 台が中心。
- 能力値(固定的な力)と、状態(疲労など、試合ごとに変わる値)は分けて持つ。

**打者の能力(10項目)**(D-022)

| 区分 | 項目 |
| --- | --- |
| 打撃 | コンタクト、選球眼、長打力、打球の質 |
| 打撃の型 | ゴロ/フライ傾向(強弱ではなく「型」を表す。他の項目とは別扱い) |
| 走塁 | 走力、走塁判断 |
| 守備 | 守備範囲、肩、捕球 |

- 「打球の質」が BABIP に与える効果の大きさは設定値として調整できる。

**投手の能力(8項目)**(D-023)

| 区分 | 項目 |
| --- | --- |
| 投球 | 奪三振力、制球力、球威、打球抑制 |
| 投球の型 | ゴロ/フライ傾向 |
| 体力 | スタミナ、回復力 |
| その他 | 走者抑制 |

- 「打球抑制」は効果を小さく設定する(FIP の前提:BABIP は主に投手の責任ではない)。
- 球威と打球抑制は分けて持つ。
- 当面、球種は能力の項目に持たせない(後から追加できる設計にする。D-025)。

#### 属性(能力値以外の情報)
- 打席の左右(打者のみ。右・左・両打ち)
- 投球の左右(投手のみ。野手の投げ手は持たない。D-048)
- 打席の左右と投球の左右の間に、関係は持たせない(D-048)
- 年齢
- ポジション:第1弾は1人1つの主ポジションで固定。守備適性・兼任は F3 で扱う(D-049)
- 先発 / 救援の適性(投手)
- 投手は打席に立たないので、打撃の能力・打席の左右を持たない(D-046)

#### 潜在能力と現在の能力(D-030、D-031)
- 各選手は「潜在能力」(ピーク時の能力)を持つ。
- 現在の能力は、潜在能力から年齢カーブで出す。新人・二軍の水準の低さは年齢カーブで表す。
- 一軍の平均が 50 になるよう、全体の平均値は設定値で校正する。
- 年齢カーブは、能力の項目をグループに分けて持つ(初期案)。

| グループ | 項目 | カーブの特徴 |
| --- | --- | --- |
| 身体系 | 走力、守備範囲、スタミナ、回復力 | ピークが早く、衰退が速い |
| パワー系 | 長打力、球威、肩 | ピークは中間で、衰退はやや緩やか |
| 技術系 | コンタクト、選球眼、打球の質、捕球、走塁判断、奪三振力、制球力、打球抑制、走者抑制 | ピークが遅く、衰退が緩やか |
| 固定 | ゴロ/フライ傾向 | 年齢で変わらない |

- ピーク年齢・衰退の速さは設定値。実在の統計は写さず、一般的な傾向を参考にした仮置き値とする。
- 項目のグループ分けは、使いながら入れ替えられるようにする。

**年齢カーブの個人差**(D-033)
- 成長タイプ(早熟・標準・晩成)を各選手に割り当て、ピーク年齢を前後にずらす。成長タイプは隠し情報で、スカウト評価にも含めない。
- 年ごとの揺れを2種類に分けて持つ。
  - 能力の揺れ:成長・衰退のぶれ。翌年以降にも残る。
  - 好調・不調:その年だけの成績の上下。「状態」として扱い、翌年には残らない。
- どちらの揺れも大きさは設定値で、ゼロにもできる。

#### 自動生成(D-027、D-028、D-030)
潜在能力は次の順で作る。
1. 型を選ぶ
2. 型ごとの補正を基準値に足す
3. 正規分布の乱数を足す

- 型の補正値・出現割合、正規分布の平均・標準偏差は設定値とする。
- 補正は、型の割合を掛けて合計するとリーグ平均がほぼ変わらないよう調整する。
- **ポジション別の出現割合**(第3弾①。D-157):打者の型の割合は、ポジションごとに「足す量」(合計 0)を全体の割合に足して決める。捕手・遊撃・二塁は守備型と俊足型が多め、一塁・三塁・左翼・右翼は長距離砲が多め、中堅は俊足型と守備型が多め。「足す量」は球団の人数で重みづけした合計が型ごとに 0 で、全体の割合(各 20%)と全体の平均は変わらない。指名打者は独立したポジションではない。投手には適用しない。
- 型の補正を足す前の基準分布は全員共通。ドラフトで入る新人は、年齢にかかわらず全員同じ基準分布から作る。
- 生成時の型は、隠し情報として選手データに記録する。年齢では変わらず、計算には使わない(D-043)。
- **初期選手の作り方**(D-034、D-190、D-197):ゲーム開始時の初期選手は、年齢が高いほど潜在能力を高めにずらして作り(生き残りバイアス)、その後、試合をせずに年度の確定の処理(加齢・能力の更新・引退・補充)だけを数十年分回す(事前運転。年数は設定値)。事前運転の間は成績・WAR・球場補正の履歴を作らない。最後に、一軍相当の真の総合能力の平均が 50 になるよう、強弱の項目の潜在能力に役割ごとの定数を足す(校正。定数は設定値で、その後に入る新人にも同じ定数を足す)。乱数はシードから導き、同じシードなら同じ結果。
- 偏りを持たせる調整は、後から行えるようにする。

**打者の型(5型)**:長距離砲、巧打者、俊足型、守備型、万能型

**投手の型**:役割 × 球質 の組み合わせ

| 役割 | 球質 |
| --- | --- |
| 先発型 / 救援型 | 本格派 / 技巧派 / ゴロ打たせ型 / 変則派 / 標準型 |

- 変則派は、奪三振力↑・制球力↓・走者抑制↓ の方向で補正する(初期案)。
- 「控え型」は置かない(水準の差は年齢と潜在能力で表す)。

#### 年齢(D-039)
- 初期選手の年齢は正規分布で近似する(平均27歳前後、標準偏差5歳前後で試行中。18〜42歳に収める。D-051 で D-039 の初期案を更新)。
- 新人の入団年齢:高卒18歳、大卒22歳、社会人・独立リーグ出身23歳前後。割合は 4:4:2。
- いずれも設定値の仮置き。実在の統計は写さない。

#### 名前(D-041)
- 選手の名前は、一般的な姓と名の部品を組み合わせてプログラムが作る。部品リストに実在選手の名簿は使わない。
- 同じ球団・同じリーグの中では、名前が重複しないようにする。
- 外国人選手の名前は、最初は扱わない(F3 で検討)。
- 球団名・球場名の初期名も、一般的な地名や言葉の組み合わせで作り、実在の名前と一致しない形にする。

### 4.3 試合のシミュレーション
(D-015、D-017、D-035〜D-038、D-045〜D-047)
- **指名打者制**:両リーグとも指名打者制で、投手は打席に立たない。指名打者は守備につかない打者の枠で、担当ポジションの対象に入らない。起用は監督の自動采配が決める(D-046)。
- **第1弾で再現するプレー**:打席の結果・走者の進塁・併殺・犠牲フライ。盗塁・犠打・暴投・捕逸・ボーク・牽制は、後から追加できる設計にする(D-045)。
- ゴロ/フライ傾向は、数値が高いほどゴロが多い(D-047)。
- 試合は**打席単位**(打者1人が打席に立つごと)で計算する。
- 打席結果は、選手の「真の能力」をもとに乱数で決める。
- 打席結果は**2段階**で決める(D-035)。
  1. **第1段階**:守備が関係しない結果か、打球が飛んだかを決める。結果は「三振・四球・死球・本塁打・インプレー」のどれか。
  2. **第2段階**:インプレーの場合、打球の種類(ゴロ・ライナー・フライ)と方向を決め、守備側の能力で「アウト・安打・失策」を決める。
  - BABIP は第2段階の結果だけで決まる。
  - 第2段階では、打球の種類に加えて**担当ポジション**(どの野手が処理するか)まで決める(D-038)。
    - 担当野手の守備範囲・肩・捕球と、打者の打球の質・走力で、アウト・安打・失策を決める。
    - 野手が処理できない打球(長打など)は、別の割合で扱う。
    - 安打の内訳(単打・二塁打・三塁打)は、担当ポジションで決める(D-072)。投手・捕手・二塁手・遊撃手は単打だけ。一塁手・三塁手は単打が中心で、線を抜ける二塁打を少し認める(三塁打なし)。外野手は単打・二塁打・三塁打。野手が処理できない打球の内野手担当分も同じ。
    - 第1弾では守備の効果を単純に実装し、第3弾(WAR)で精密にする。
    - 打球の落下地点や速度を座標で再現することは行わない。
- 打者と投手の能力は**オッズ比法**で合成する(D-036)。
  - リーグ平均の率(三振率、四球率など)は、実在の成績表を写さず、一般的な水準の架空値(設定値)とする。
  - 能力値から倍率への変換は「10点あたりの倍率」を設定値とし、シーズンを繰り返し回して校正する。
- **左右の相性**はリーグ共通の補正で扱う(D-037)。
  - 同じ側どうし(右投手×右打者、左投手×左打者)は投手有利、逆側どうしは打者有利の補正を、オッズ比法の倍率として掛ける。
  - 両打ちの打者は、投手の左右の逆で打つ(常に有利な側)。
  - 補正の大きさは設定値(ゼロにもできる)。一般的な傾向を参考にした仮置き値で、実在の統計は写さない。
  - 選手ごとの左右差(個人差)は、後から追加できるようにする。
- **球場の倍率**(D-064、D-136、D-137。第2弾②a):球場ごとの本塁打と BABIP(インプレーの安打)の倍率を、その試合の球場(ホームチームの本拠地)について、オッズ比法の倍率として両チームの打者に掛ける。本塁打の倍率は第1段階の本塁打に、BABIP の倍率は第2段階の「野手が処理できる打球が安打になる」確率に掛ける(処理できない打球の割合と失策率には掛けない)。ホームの有利とは別に掛ける。倍率は整数の千分率で持ち、各リーグの6球場の平均がちょうど 1.0。範囲の初期値は本塁打 0.85〜1.15、BABIP 0.97〜1.03(設定値)。
- 打席結果は種類ごとに区別して記録する。少なくとも次を区別する:
  - 単打、二塁打、三塁打、本塁打
  - 四球、死球
  - 三振
  - ゴロアウト、ライナーアウト、フライアウト
  - 失策(打者が失策で出塁)
  - (その他、指標の計算に必要な種類は必要に応じて追加する)
- 打席ごとの記録(打席ログ)には、打席結果の種類に加えて、走者・アウト状況(24通り)を必ず記録する(D-026)。
- 打席結果を計算する部分は、差し替え可能な部品とする(計算方法を後から改良できるように)。
- 試合中の采配(選手起用や作戦)は自動とする(D-019)。

#### 1試合の進行(D-059〜D-062)
- **試合の形式**(D-062):9回まで。9回裏はホームがリードしていれば行わない。サヨナラはその場で試合終了。延長は上限(初期値12回)まで、同点なら引き分け(設定で変更可)。
- **走者の進塁**(D-059):
  - 四球・死球は押し出し。本塁打・三塁打は全員生還。
  - 単打・二塁打での進塁、ゴロでの併殺と進塁、フライでの犠牲フライ、失策での進塁は、確率表を能力(走者の走力・走塁判断、打者の走力、担当野手の捕球・肩)で補正して決める(オッズ比法)。
  - 併殺は走者1塁・2アウト未満のゴロのときだけ。犠牲フライは3塁走者・2アウト未満のフライのときだけ。
  - 走塁死は第1弾では入れない。
  - 打席ログに、各走者の進塁(どの塁からどの塁へ、アウトか)、その走者を出塁させた投手、失策による出塁・進塁かどうか、打順、イニング、点差を記録する。
- **投手の起用**(D-060):
  - 先発は、対戦打者数の上限(スタミナと疲労から決まる)か失点の上限で降板する。降板はイニングの終わりが原則で、失点の上限に達したときだけ途中で降板する(引き継いだ走者の責任は前の投手)。
  - 救援は1イニング単位。
  - 疲労は投げた打者数から計算し、回復力で日ごとに回復する。疲労が大きい投手は登板できない。球数は使わない。
- **一軍・スタメン・休養**(D-061):
  - 一軍登録は29人(投手14・野手15)。
  - スタメンは各ポジションで最も強い野手+指名打者。主力は一定確率で休み、控えが同じ打順・ポジションに入る。
  - 試合中の交代(代打・代走・守備固め)・敬遠・犠打は入れない。
  - 一軍の選抜・スタメン・打順・継投・休養は、差し替え可能な簡易ルールとする。

### 4.4 シーズン(日程・順位)
(D-021、D-066、D-087)
- **日程**:ラウンド制。毎日、同じリーグの全チームが1試合ずつ行う(1リーグ6球団なので1日3試合)。5日で総当たりが一巡し、25回繰り返して125試合。
  - ホームとアウェイは、同じ相手との対戦ごとに交互に入れ替える。
  - 休養日・3連戦・交流戦は、日程を作る部分を入れ替えて後から足す。第1弾は最小の形で作る。
- **勝率**:勝利数 ÷(勝利数 + 敗戦数)。引き分けは分母に入れない。
- **順位**:勝率の高い順。同率のときは、勝利数、直接対決の成績、の順で決める。それでも同じなら、シーズンのシードで決めた抽選の順。同順位を許す設定では、勝率が同じチームを同じ順位にする。
- **ゲーム差**:首位との差と、1つ上の順位のチームとの差の両方を出す(ゲーム差 =(上のチームの勝利数 − 勝利数 + 敗戦数 − 上のチームの敗戦数)÷ 2)。
- **疲労と先発**:先発は疲労が回復してから登板する。回復力の低い先発は、ときどき飛ばされる(1シーズンで先発の機会の約4%)。
- **先発**:6人ローテーション。疲労が大きい投手は飛ばす。
- **再現**:試合ごとの乱数のシードはシーズンのシードから決め、1試合だけを取り出して再現できる。
- **範囲外**:怪我・成長はシーズンの中では起こらない(F2・F3 で扱う)。
- **ホームとアウェイの割り振り**(D-087):各ペアの25試合のうち13試合のホーム権を持つ側を、各チームが2〜3組で持つように割り振る(各チームのホームは62試合か63試合)。割り振りはシーズンのシードで決める。
- **試合数**:設定値(既定は 25試合 × 5チーム = 125試合)。2つのリーグは同じ日に並行して試合を行う(交流戦なし)。
- **1日の流れ**:スタメンと先発を決める → 試合 → 疲労を加える → 1日を進めて回復させる。
- **シーズンの結果**:最終順位表、全試合の結果、全打席のログ。優勝は各リーグの最高勝率のチーム。ポストシーズンは後から足せるようにする。
- **サヨナラの打ち切り**:サヨナラで得点が打ち切られた打席には、そのことを打席のログに残す(公式記録の数え直しは実装⑤で決める)。
- **ホームの有利**(D-073):ホームチームの打者に小さな倍率(設定値。なしにもできる)を掛ける。ホームの勝率がおおむね52〜54%になる大きさにする。
- **一軍**(D-074):一軍29人はシーズンを通して固定(入れ替えは F3)。疲労は登板の可否と先発の打者数の上限にだけ使い、成績には効かせない。好調・不調は全能力に同じだけ足す。

### 4.5 成績・記録の表示
(D-016、D-018、D-025、D-026)
個人成績と、セイバーメトリクス系の指標を最優先の機能とする。指標は3弾に分けて実装するが、設計は最初から WAR まで見据える。

指標の弾への振り分けは、次の原則に従う(D-026)。

| 弾 | 振り分けの原則 | 目標とする指標の例 |
| --- | --- | --- |
| 第1弾 | 選手個人の記録だけで計算できる指標 | 打率、出塁率、長打率、OPS、ISO、BABIP、K%、BB%、防御率 など |
| 第2弾 | リーグ全体の集計(基準値)が必要な指標 | wOBA、wRC+、OPS+、FIP、球場補正 |
| 第3弾 | 守備・走塁・ポジション補正が必要な指標 | 守備指標、走塁指標、WAR |

指標の簡単な意味:
- 第1弾の指標(打率・出塁率・長打率・OPS・ISO・BABIP・K%・BB%・防御率)の意味は「3. 用語集」を参照。用語集の文章は、指標の定義データ(`src/pennant/data/metrics.json`)の解説と同じにする(テストで照合する。D-097)。
- **wRC+**:wOBA をもとに、リーグ平均を100として打者の得点貢献を表す指標(球場補正込み)。
- **OPS+**:OPS をリーグ平均と比べ、リーグ平均を100として表す指標(球場補正込み)。
- wOBA・FIP・WAR は「3. 用語集」を参照。

- 指標の基準値(リーグ平均など)は、実在の成績表を使わず、一般的な水準の架空値か、シミュレーション自身の結果から作る(D-003 補足)。
- wOBA と FIP は、リーグ全体の結果から決める値(wOBA の重み、FIP 定数)を使う指標のため、第2弾とする(D-018 補足、D-026)。
- 第2弾以降の指標を過去のシーズンについても計算できるよう、第1弾の時点から打席ログに必要な情報を残す(D-026)。

#### 第1弾の集計の範囲(D-067、D-094〜D-098)
- **元の数**(すべて整数で持つ。打席ログと登板の記録から、その都度計算する):
  - 打者:試合、打席、打数、安打、単打、二塁打、三塁打、本塁打、塁打、四球、死球、三振、犠牲フライ、併殺打、打点、得点
  - 投手:登板、先発、投球回(アウトの数で持つ)、対戦打者、被安打、被本塁打、与四球、与死球、奪三振、失点、自責点、勝利、敗戦、セーブ、ホールド、完投
  - チーム:得点、失点、勝敗(順位表と一致する)
- **集計の単位**(D-096):第1弾はシーズン通算と試合ごと。月別・期間別、左右別・走者の状況別は後から、ホーム・ビジター別は第2弾で足す。
- **指標の式**(定義データ `metrics.json` の計算式):
  - 打数 = 打席 − 四球 − 死球 − 犠牲フライ(犠打・打撃妨害はない)
  - 打率 = 安打 ÷ 打数、出塁率 =(安打 + 四球 + 死球)÷(打数 + 四球 + 死球 + 犠牲フライ)
  - 長打率 = 塁打 ÷ 打数、OPS = 出塁率 + 長打率、ISO = 長打率 − 打率
  - BABIP =(安打 − 本塁打)÷(打数 − 三振 − 本塁打 + 犠牲フライ)
  - K% = 三振 ÷ 打席(投手は 奪三振 ÷ 対戦打者)、BB% = 四球 ÷ 打席(投手は 与四球 ÷ 対戦打者)
  - 防御率 = 自責点 × 9 ÷ 投球回
  - 分母が 0 のときは、エラーにせず「値なし」とする。
- **規定打席・規定投球回**(D-096):規定打席 = チーム試合数 × 3.1(端数は四捨五入)、規定投球回 = チーム試合数 × 1.0。チーム試合数は、そのチームの消化試合数。
- **自責点**(簡易版。D-095):得点した走者の出塁・進塁に失策が関わっていれば、自責点にしない。関わっていなければ、その走者を出塁させた投手の自責点。
- **打点**(D-095):その打席で生還した走者(本塁打なら打者自身も)の数。併殺打と、失策によって生還した得点は打点にしない。押し出しの四球・死球は打点にする。
- **勝利・敗戦・セーブ・ホールド**(簡易版。D-094):
  - 勝利投手:勝ち越しの得点が入った時点でそのチームの投手として試合にいて、リードが最後まで保たれた投手。先発は5回以上を投げていること。先発が5回に満たない場合は、リードを最後まで保った最初の救援投手。
  - 敗戦投手:決勝点を許した投手。
  - セーブ:勝ったチームの、勝利投手でない最後の投手が、①3点以内のリードで登板し1イニング以上、②同点・勝ち越し点の走者が塁上または打席にいる状況で登板、③3イニング以上(リードを保って終える)、のどれかを満たすとき。
  - ホールド:勝った試合で、勝利投手でもセーブ投手でもない救援投手が、リードがある場面で登板し、リードを保ったまま試合終了前に降板したとき。
  - 公式記録の簡易版で、ごく一部の試合で公式と違いが出る。
- **公式記録のサヨナラ安打の数え直し**は、第1弾では再現しない(D-098)。長打率・OPS・ISO の解説に注記する。
- ランキング(タイトル)は後から作る。

#### 第2弾:wOBA・wRC+・OPS+・FIP(D-063、D-120〜D-128)
- 第2弾は、①指標(試合の計算を変えない)と②球場補正(試合の計算が変わる)の2つに分ける。①の間、球場補正は 1.0(D-120)。
- **RE24**(D-123):打席の前の走者・アウトの状況(24通り)ごとに、その打席からイニングの終わりまでの得点を平均する。サヨナラで打ち切られた半イニングは外す。
- **線形加重**(D-123):結果の種類(四球・死球・単打・二塁打・三塁打・本塁打・アウト)ごとに「打席の後の期待値 − 打席の前の期待値 + その打席の得点」を平均する。失策による出塁は、重みを付けない(アウトと同じ 0)。
- **wOBA**:(重み × 四球・死球・単打・二塁打・三塁打・本塁打の数の合計)÷(打数 + 四球 + 死球 + 犠牲フライ)。重みは「各結果の得点価値 − アウトの得点価値」に、目盛りの倍率を掛けたもの。目盛りは、リーグ全体の wOBA がリーグ全体の出塁率に等しくなるように合わせる。
- **wRC+・OPS+**(D-124):リーグ平均(12球団の合算)を100にする。球場補正は、1シーズン目は 1.0、2シーズン目から前のシーズンまでの結果で推定した値(4.7 節。D-142、D-143。画面の解説に「1シーズン目は 1.0。2シーズン目から、推定した球場補正を含みます」と書く)。
  - wRC+ = ((wOBA − リーグの wOBA)÷ 目盛り + リーグの1打席あたりの得点 +(リーグの1打席あたりの得点 − 球場補正 × リーグの1打席あたりの得点))÷ リーグの1打席あたりの得点 × 100
  - OPS+ = 100 ×(出塁率 ÷ リーグの出塁率 + 長打率 ÷ リーグの長打率 − 1)÷ 球場補正
- **FIP**(D-125):(13 × 本塁打 + 3 ×(四球 + 死球)− 2 × 三振)÷ 投球回 + FIP 定数。FIP 定数は、リーグ全体の FIP がリーグ全体の防御率に等しくなるように決める。係数の出どころは設定で切り替えられる(今は標準値)。
- **基準値と混ぜ方**(D-126):各シーズンの打席ログから求める。シーズン序盤は、前シーズンの値(初年度は試運転の値。D-121)を出発点にし、今シーズンの累積打席数が増えるほど今シーズンの値の比重を上げる(D-091)。
  - 比重 = 累積打席数 ÷(累積打席数 + 定数)。定数の既定値は 20,000 打席(設定値)。シーズンの最後で約75%。
  - 使う値 = 比重 × 今シーズンの値 +(1 − 比重)× 出発点の値。重み・目盛り・リーグ平均・FIP 定数は、すべて同じ混ぜ方。球場補正の推定(②)にも同じ混ぜ方を使う。
  - 翌シーズンの出発点には、今シーズンの最終値を使う。
- **試運転**(D-121、D-122):新規開始のとき、見えない試運転のシーズン(リーグのシードから決めた別のシード)を1回回して、初年度の基準値を求める。実際のリーグの状態には触れない。試運転の成績・打席ログは画面に出さず保存しない。求めた基準値だけをセーブデータに保存する。「速い選択肢」では、設定ファイルの既定値を使う。基準値を持たない古いセーブデータも、既定値で読む。
- 計算はすべて分数で行う(D-127)。
- **指標を足す3つの段階**(D-128):A 定義データだけ / B 元の数を足す / C 打席ログに情報を足す(過去のデータでは「値なし」)。

#### 球場補正(D-064、D-135〜D-138)
- 第2弾②は、②a(球場の倍率を試合に入れる。試合の計算が変わる)と②b(球場補正の推定と指標への反映。試合の計算は変えない)に分ける(D-135)。②a の間、wRC+・OPS+ の球場補正は 1.0 のまま。
- 球場ごとに「本塁打」と「インプレーの安打(BABIP)」の2つの真の倍率を持ち、打席の計算(オッズ比法)の倍率として入れる。各リーグの6球場の平均をちょうど 1.0 に合わせる(D-136)。
- 倍率は、リーグのシードから SHA-256 で導いた別の乱数で、架空の球場に割り当てる(整数の千分率。範囲内で一様。D-137)。実在の球場の数値は使わない。既存の選手・球団の生成の乱数は変えない。
- 真の倍率は隠し情報(答え合わせモードの段階1で、球場のページに見せる)。公開用には、球場名・本拠地のチーム・本拠地での実際の結果(試合数・本塁打・得点)だけを出す。セーブデータに保存し(版 4)、版3以前は倍率なし(すべて 1.0)として読む(D-138)。
- **推定**(②b。D-140〜D-146):同じチームの本拠地の試合とアウェイの試合(両チーム合計)を比べ、「本拠地の率 ÷ アウェイの率」を生の比とする。複数シーズンを合算し、比重 = 本拠地の打席数 ÷(打席数 + 定数)で 1.0 に向けて縮め、各リーグの6球場の平均を 1.0 にそろえる。定数は、1シーズンのぶれと想定する球場差から決める(D-145)。
  - wRC+・OPS+ に使う球場補正は、得点ベースの1つの値。②c からは、縮めた後の本塁打と BABIP の推定値から「1打席あたりの得点の出やすさ」を換算して作る(真の値側と同じ式。各リーグの平均 1.0。D-147)。縮めるのは本塁打と BABIP だけ(D-148)。直接推定した得点(本拠地 ÷ アウェイの生の比)は球場のページの比較と開発者向けスクリプトに検証用として残す。BABIP 単独の推定は「参考値」と注記する(D-149)。
  - 選手ごとの球場補正は、球場ごとに立った打席数で重みづけした平均(D-142)。
  - 今シーズンには、前のシーズンまでの推定を使う。1シーズン目は 1.0(D-143)。FIP は球場補正をしない(D-144)。
  - 球場 × シーズンの集計は、シーズンの履歴としてセーブデータに保存する(版 5。D-146)。
- 指標に使う補正の値は、結果から推定する(複数年のデータで、平均の1.0に向けて回帰させる)。真の倍率は答え合わせ用に保持し、画面には出さない。
- 最初のシーズンは補正を1.0とし、そのことを注記する。

#### 第3弾:守備・走塁・WAR(D-070)
- **守備**:担当した打球ごとに、リーグ平均の野手との差(アウトにした数の差)を得点に換算する。捕手専用の守備評価は、盗塁・暴投・捕逸を足す段階で一緒に決める。
- **WAR の部品**:打撃(wOBA 由来、球場補正込み)、走塁(進塁の価値のみ)、守備(打球ごとの差)、ポジション補正(設定値)、控え水準(設定値。初期案は勝率 .290 前後)、1勝あたりの得点(リーグの得点環境から計算)。
- **投手の WAR**:FIP 版と失点版(守備と球場の影響を除いた実際の失点から)の両方を出す。どちらが真の力に近いかを、隠し情報を使って検証できるようにする。
- 第3弾は3つの依頼に分ける(D-155):①選手生成の変更(ポジション別の型の出現割合。4.1 節。D-157)、②打撃・走塁・守備の得点(計算は変えない)、③WAR(ポジション補正・控え水準・1勝あたりの得点・投手の WAR・画面)。
- 守備の得点は打球ごとの記録(担当野手の ID は記録済み)から、走塁の得点は進塁の価値から計算する。ポジション補正と控え水準(初期案は勝率 .290 前後)は設定値。投手の WAR は FIP 版と失点版の両方。1勝あたりの得点はリーグの得点環境から計算する(D-156)。
- **第3弾②:打撃・走塁・守備の得点**(D-160〜D-166。計算本体と開発者向けスクリプトまで。画面は③):
  - 得点期待値表は基準値の RE24(試運転で求め、シーズン中は混ぜる。D-161)。
  - 打撃の得点 =((wOBA − リーグ平均の wOBA)÷ 目盛り +(1 − 球場補正)× 1打席あたりの得点)× 打席数(D-162)。
  - 走塁の得点:打席ごとの得点期待値の変化から「同じ状況(結果の種類 × 打席の前の状況 × 外野への打球か)」の平均を引いた差を、選択の余地があった走者に等分して付ける。打者自身の進塁は入れない(D-163)。
  - 守備の得点 =(実際のアウト数 − 期待のアウト数)× アウト1つの得点の価値。期待はポジション × 打球の種類ごとのリーグ平均のアウト率。球場の倍率と打者の能力は反映しない(D-164)。
  - 集計:選手 × シーズンごとに 3つの得点、ポジションごとの守備の得点・機会・守備アウト数。記録の項目は足さず、保存形式も変えない(D-165)。指紋 (k) を足す(D-166)。
  - リーグ全体の合計は、走塁・守備はちょうど 0、打撃は球場補正なしならちょうど 0(球場補正ありはほぼ 0)。
- **第3弾③a:WAR の計算**(D-167〜D-173。計算本体と開発者向けスクリプトまで。画面は ③b):
  - 1勝あたりの得点 = 4 × 1チーム1試合あたりの得点 ÷ 指数(指数 2 なら 2 × 得点。ピタゴラス勝率。基準値の1打席あたりの得点 × 今シーズンの1試合あたりの打席数。D-170)。
  - ポジション補正(設定値。点/125試合):捕手 +9、遊撃 +6、二塁 +2、三塁 +2、中堅 +2、左翼 −6、右翼 −6、一塁 −10、指名打者 −14。守備アウト数(指名打者は打席数)で按分(D-168)。
  - 控え水準(設定値):野手は1打席あたり、先発・救援は9イニングあたり。リーグ全体の WAR の合計が「勝ち数の合計 − .290 × チーム試合数の合計」に合うよう調整(D-169)。
  - 打者の WAR =(打撃 + 走塁 + 守備 + ポジション補正 + 控え水準)÷ 1勝あたりの得点。投手は FIP 版(球場補正なし)と失点版(球場補正あり。チームの野手の守備の得点を投球回で按分して差し引く)(D-171)。
  - 集計は分数、保存形式は変えない。指紋 (l)(D-172)。
  - ポジション補正の値は多数の世界で測り直してから決める(D-174)。出場量の重みづけで合計 0。値を変えるときは控え水準も同時に調整(D-175)。控え水準・1勝あたりの得点・合計の目標は ③a の値で確定(D-176)。

**将来の目標**(D-025)

### 4.6 セーブ・ロード(保存と読み込み)
(D-004〜D-006、D-068、D-083、D-084、D-100〜D-104)
- セーブデータは**1つのファイル**(拡張子 `.sav`。中身は ZIP)にする(D-100)。
  - 中身:状態の JSON(リーグ・球団・選手・シーズンの状態・設定値など)と、シーズンごとの打席ログ。
  - 既定のファイル名は日付(例:`save-20261002.sav`)。球団名はファイル名に自動で入れない。利用者が名前を付けられる。
- 必ず含めるもの:
  - 形式のバージョン番号、保存日時、セーブデータの名前
  - 乱数の初期のシードと、現在の状態
  - そのセーブデータで使った設定値
  - リーグ(球団名・球場名)、選手(隠し情報の潜在能力・成長タイプ・生成時の型を含む。画面には出さない)
  - シーズンの現在の日付・勝敗・順位・ローテーションの位置・疲労、試合の結果、打席のログ、各試合の前の状態(1試合を再現するため)
- **保存のしかたは差し替えられる**(D-083、D-101):ローカルのフォルダ(既定は `~/.npb-pennant-simulator/`。設定で変更可)/1ファイルの書き出し・読み込み/ブラウザのファイル選択・ダウンロード。計算本体はファイルを直接読み書きしない。
  - ブラウザでは、利用者がファイルを書き出し(ダウンロード)、読み込むときにファイルを選ぶ。ブラウザ内の自動保存は既定でオフ(D-084)。
- **読み込み時の検証**(D-102):バージョン番号を確かめ、古い版は変換して読む。新しすぎる版・壊れたデータ・手で編集されたデータは、どこが・なぜを日本語で示して読まない。検証が済むまで、今の状態を上書きしない。
- **続きの再現**(D-103):保存して読み込んだ後の続きは、保存せずに続けた場合と同じ結果になる。別の端末・別の Python の版で保存したファイルでも同じ。
- **実名の扱い**(D-104):入力された球団名などは、セーブデータの状態の中にだけ入る。ログ・一時ファイル・既定のファイル名には書かない。暗号化はしないので、セーブデータは共有しない(README の注意)。
- **新規開始と球団名の入力**:球団名を入力してリーグを作る。空欄の球団は架空の初期名にする(D-008)。空白だけ・長すぎる(24文字を超える)・制御文字(画面に出ない特殊な文字)を含む・12球団の中で重複する名前は、理由を示して受け付けない。
- **画面に出す選手の情報**:隠し情報(潜在能力・成長タイプ・生成時の型)と、真の能力値(D-017)は含めない。

### 4.7 操作画面(ブラウザ)
(D-008、D-009、D-080、D-081、D-086、D-106〜D-108、D-111)
- **方式**:ブラウザの中で完結する(Python をブラウザ上で実行する)。サーバーは使わず、計算も画面もブラウザの中で動く。配る場所にはコードと架空のデータだけを置き、実名のデータはサーバーに送らない(D-081)。
- **段階2(最小のブラウザ画面)の操作範囲**は観戦と閲覧(D-080):
  - 新規開始(球団名の入力。空欄は架空の初期名)
  - 日数を指定して進める/シーズンの最後まで進める
  - 順位表/個人成績(並べ替え)/1試合の文章ログ
  - 保存と読み込み
- 操作の種類は計算本体の側で関数として用意し、画面はそれを呼ぶだけの薄い層にする。
- 不正な入力は、理由を表示して再入力を求める。
- 確認用の開発者向けスクリプト(`scripts/`)は残す(CLI の操作画面は作らない)。
- **画面の方針**(D-086):
  - 表を中心にする(グラフは第2弾・F2 でデータが増えてから)。
  - 画面:スタート(新規開始・セーブデータを開く)、自球団の選択、シーズンの進行、順位表、個人成績、選手のページ、試合のページ、保存・書き出し。
  - スマホは縦持ちが基本。表は、左端の選手名の列を固定して横スクロール。広い画面(PC・スマホの横持ち)でも使いやすくする(D-223):新しく作る表の部品は幅に応じて広がり、広い画面では横スクロールなしで全列を表示する(幅の境目は設定値。切り替えは自動)。既存の表(個人成績・チーム・順位)の広い画面への対応と、左右に分ける画面構成は、デザインの見直しで扱う。
  - 指標の名前をタップすると、初心者向けの解説が出る。
  - 隠し情報(潜在能力・成長タイプ・生成時の型)は画面に出さない。
- **画面の作り**(D-107):
  - スマホの縦持ちが基本。下に固定のタブ。明るい/暗いは端末の設定に従う。表示はすべて日本語(指標の略称には日本語名を併記)。
  - 計算は裏(Web Worker)で行い、画面は固まらない。進行(1日・1週間・最後まで)は途中で止められる。
  - 順位表では自球団の行を目立たせる。保存・読み込みは目立つ場所に置く。
  - 新規開始の画面に「実名を入れたデータは共有しない」注意を常に表示する。自動保存はしない。未保存の変更があるまま閉じようとしたら警告を出す。
  - 新規開始の「詳しい設定」で、リーグ(選手の生成)とシーズン(日程と試合)のシードを入れられる。空欄なら毎回ちがう値(D-113)。
  - 保存のファイル名は日付だけ(`save-YYYYMMDD.sav`。球団名は入れない)。読み込みに失敗したときは、理由を日本語で表示し、今のゲームはそのまま残す。
  - 2つの依頼で作る(D-106):①土台と進行(新規開始・自球団の選択・進行・順位表・保存と読み込み)、②成績の画面(個人成績・選手のページ・試合のページ・指標の切り替え・答え合わせモード)。
- **能力の見せ方**(D-108):観戦版では、選手の能力値・能力の見積もり・隠し情報を、画面にも通信にも出さない。②で「基本」「セイバー」「能力」の切り替えを置き、「能力」は答え合わせモード(既定オフ)でだけ見せる(1段階目:現在の能力 20〜80、5刻み。2段階目:潜在能力・成長タイプ・生成時の型)。F3 では、答え合わせモードを新規開始のときに決め、途中で変えられない。
- **成績の画面**(②。D-114〜D-118):
  - 下のタブは「進行」「順位表」「成績」「試合」。設定は、上の帯のメニューから開く。
  - 個人成績:打者/投手、「基本」「セイバー」「能力」の切り替え。列の見出しをタップして並べ替え(もう一度で逆順)。規定到達者の絞り込み(既定オン。規定打席 = 試合数 × 3.1、規定投球回 = 試合数 × 1.0)。リーグ・チームの絞り込み。指標名のタップで解説(指標の定義データの解説と同じ文章)。選手名のタップで選手のページへ。
  - 表の既定(D-116、D-130):打者の基本は打率の高い順(試合・打席・打数・安打・本塁打・打点・得点・打率・出塁率・長打率・OPS)、投手の基本は防御率の低い順(登板・先発・勝・敗・セーブ・ホールド・投球回・奪三振・防御率)、打者のセイバーは wRC+ の高い順(打席・wOBA・wRC+・OPS+・ISO・BABIP・K%・BB%)、投手のセイバーは防御率の低い順(投球回・FIP・K%・BB%)。OPS は「基本」の区分(D-130)。
  - 並び順と絞り込みの保持(D-131):打者(または投手)の中で、基本・セイバー・能力を切り替えても、並び順・絞り込み・表示件数を保つ。並び順の指標が表にないときは、名前の隣に固定の列として出す。打者と投手を切り替えたときは、その側の既定の並び順に戻す。状態は保存しない。
  - 「並び順」の選択欄(D-132):表の上に置き、基本・セイバーの全指標(答え合わせモードがオンのときは能力の項目も)から選べる。高い順/低い順の切り替えつき。見出しのタップでも並べ替えられる。
  - 選手のページ:基本情報(年齢・ポジション・投打・所属)、シーズン通算の成績、試合ごとの成績(新しい順)。
  - 試合のページ:日付を選んでその日のスコアの一覧 → 1試合の文章ログ(確認用スクリプトと同じ内容)と投手の成績(勝敗・セーブ・ホールド)。
  - チームのページ:チームの成績(試合・勝・敗・分・得点・失点)と選手の一覧。順位表のチーム名から開く。
  - 進行の画面に、直近の日の全試合のスコアを出し、タップで試合のページへ(D-117)。
  - 「止める」と処理の進み具合のバーは、処理が 0.6 秒を超えたときだけ出し、出したら最低 0.6 秒は表示を続ける。「1日」では出さない。処理中は、ほかの進行ボタンを押せない(D-118)。
  - **答え合わせモード**(D-108、D-114、D-115):既定はオフ。オンにするとき確認を出す。1段階目は現在の能力(20〜80、5刻み。範囲外は端に丸めて印)、2段階目は潜在能力・成長タイプ・生成時の型も見せる。「能力」は表で数値を並べ、並べ替えられる。オフのときは、能力値・潜在能力・成長タイプ・生成時の型を、画面にも通信にも出さない。設定は保存しない(開き直すとオフ)。
- **第2弾の指標の画面**(D-121、D-122、D-124):「成績」の「セイバー」に wOBA・wRC+・OPS+・FIP を出す(打者のセイバーの既定の並び順は wRC+ の高い順)。表の近くに、前のシーズン(初年度は試運転)の値を混ぜている旨と、今シーズンの比重を出す。新規開始で、基準値を求める進み具合(「リーグの基準値を求めています」)を出す。「詳しい設定」に「試運転で求める(既定)/既定値を使う(速い)」の切り替え。メニューに「指標の解説」ページ(すべての指標を区分別に、式・解説・見るときの注意つきで。指標の定義データから作る)。
- **球場のページ**(②a・②b。D-138、D-140):チームのページの「本拠地」から開く。球場名、本拠地のチーム、本拠地での実際の結果(試合数、本塁打、本塁打/試合、得点/試合。両チームの合計)。今シーズンの本拠地とアウェイを並べた表(本塁打/打席、BABIP、得点/打席。本拠地・アウェイ・比)。推定した球場補正(得点・本塁打・BABIP。得点は本塁打と BABIP の推定から組み立てた値。D-147)は2シーズン目から出し、1シーズン目は「まだ推定できません」と出す。BABIP 単独の推定には「参考値」と注記する(D-149)。答え合わせモード(段階1以上)がオンのときだけ、真の倍率(本塁打・BABIP)を出す。試合のページに球場名を出す。wRC+・OPS+ の注記は「1シーズン目は 1.0。2シーズン目から、推定した球場補正を含みます」。FIP は球場補正をしない旨を注記する。
- **WAR の画面**(第3弾③b。D-179):個人成績に「WAR」の切り替え(野手:打席・WAR・打撃・走塁・守備・ポジション補正・控え水準。投手:投球回・WAR(失点版)・WAR(FIP 版))。並び順の保持・固定列・「もっと見る」は既存と同じ。選手のページに「WAR」の切り替え(今シーズンの内訳)、チームのページにチームの WAR の合計(野手・投手別)。用語の説明は表の下。答え合わせモードに関係なく見える。シーズン途中は「○日目まで」の値。計算はブラウザの中で行い、試合数が変わるまで結果を覚えておく。
- **複数年の画面**(F2。D-182、D-185):シーズン終了後に「年度を確定」(終了前は押せない)→ 確認の画面(戻せないこと、保存への導線)→ 確定 → オフの結果(引退した選手、入団した新人。能力の増減は答え合わせモードがオンのときだけ)。成績のページでシーズン(今シーズン・過去の各シーズン・通算)を選べ、通算には WAR も含む。通算の指標は、元の数から計算できるもの(打率など)は元の数の合計から、基準値に依存するもの(wOBA・wRC+・OPS+・FIP など)は各シーズンの値を打席数(投手は投球回)で加重平均して出す(D-192)。選手のページに年度ごとの成績の推移。球場のページと wRC+・WAR の注記で、2シーズン目以降の球場補正を確認できる。
- **開発者向けの測定ページ**は、本番の画面とは別の場所(`/dev/`)に置く(D-111)。

### 4.8 球団経営

- 試合中の采配は自動。采配の操作は後から追加できる形にする。
- 他球団の判断ロジックは差し替え可能にする。

#### お金のルール(D-230、D-231。D-076 を置き換え)
- 4 段階(なし・ゆるい・標準・きびしい)。既定は「なし」。新規開始のときに選び、途中では変えられない。
  - なし:予算の機能なし。年俸と契約年数は存在して表示される。契約満了者は全員更改。
  - ゆるい:予算は目安。超えると警告が出るだけで、契約は結べる。全球団同額。
  - 標準:予算は上限。超える契約は結べない(あなたも AI も)。全球団同額。
  - きびしい:標準に加えて、球団ごとの予算の格差(大・中・小 = 1.2・1.0・0.85 倍。新規開始のシードから大 3・中 6・小 3 球団)。球団ごとの予算は公開情報。
- 予算は、支配下 70 人の総年俸(年俸の合計)の枠。予算の上限(標準・きびしい)と目安(ゆるい)は基準予算の 1.10 倍(設定値)。「収入と支出」は F4。

#### 契約と年俸(F3-2a。D-232〜D-236)
- 選手ごとに、年俸(架空の「万円」)と契約の満了シーズン、年俸の履歴を持つ。契約年数は 1〜5 年(設定値)で、年齢と見込みの WAR から決める。
- 年俸は見える情報だけで決める:見込みの WAR = 直近 3 シーズンの WAR の加重平均(新しいほど重い。出場の少ない年は重みを小さく。30 歳以上は年齢で割り引く)。年俸 = 最低年俸 + 単価 × 見込みの WAR(下限は最低年俸。丸めは設定値)。履歴がない選手(入団 1 年目の新人、事前運転後の初期選手)は、所属球団のスカウト評価(総合の推定値と天井)から見込みの WAR を求める(評価と WAR の関係はリーグの実測から求めた設定の表)。ドラフトの新人は巡ごとの年俸の表。真の能力・潜在能力・成長タイプ・型は使わない。
- 単価(1 WAR あたり)と予算の基準額は、リーグの環境から毎年自動で決める:単価 = (基準予算 × 球団数 − 最低年俸の合計)÷ リーグの見込みの WAR の合計(D-234)。
- オフの流れ:加齢・能力の更新・引退 → 契約満了の自動更改(全球団。新しい年俸は算定)→ 予算超過の解消(標準以上。AI は見込みの WAR あたりの年俸が高い選手から、最低人数を守って自由契約。あなたの球団は自由契約の画面で自分で選び、超過のままでは「次の手続きへ」が押せない。「おまかせ」は AI と同じ)→ 自由契約 → ドラフト(巡ごとの年俸で契約。標準以上で予算が足りない球団はパス)→ 市場(算定した年俸で契約。予算が足りなければ結べない)→ 自動補充(最低年俸の契約。予算に関わらず結べる)。ゆるいは警告のみ。
- 手放した選手の残りの契約は消える(違約金なし。D-236)。
- 画面:新規開始の「詳しい設定」にお金のルール。選手のページに契約(年俸・契約年数・残り年数・年俸の履歴。他球団の選手も公開情報)。チームのページに総年俸・予算・使用率(「なし」は総年俸だけ)と年俸の高い順の表。自由契約の画面と市場の表に年俸・残り年数の列、自由契約の画面の上に総年俸 / 予算と警告。オフの手続きの最初に契約更改の結果(更改した選手、年俸の変化、予算超過で自由契約になった選手)。
- 保存形式は版 10(契約、ルールの段階、予算の格差、契約の履歴、単価の推移)。旧版は契約を算定で補って読む(ルールは「なし」、残り年数は別の乱数系列で 1〜3 年)。
- 交渉(志望)と FA は F3-2b(D-238):志望の軸は年俸重視・出場機会重視・勝利重視の 3 つ(設定ファイル。隠し情報。契約の判定にだけ使う。別の乱数系列。AI 球団も同じルール。お金のルールなしでも出場機会と勝利の 2 軸で働く)。

#### FA(D-077)
- 選手が特定の球団に集まりすぎないためのブレーキは、支配下70人の枠と、選手の志望(出場機会・勝てるか・年俸などの好み)。
- 志望の細かい形は、F3-2 の前に決める。

#### オフの手続き(F3-1。D-198〜D-207)
- 操作する球団は 1 つ(新規開始で選ぶ「自球団」)。選ばない場合は観戦のみで、オフの手続きはすべて自動で進む(D-198)。
- 年度の確定の後、加齢・能力の更新・引退(自動)→ **自由契約**(球団が手放す)→ **ドラフト** → **自由契約市場からの獲得** → **足りない分の自動補充**(F2 の自動入団を穴埋めとして残す)の順に進む(D-201)。手続きは保存できる状態として持ち、途中で保存・再開できる。「おまかせ」で残りを自動で進められる(D-207)。
- **自由契約**:操作する球団は選手を選んで手放せる(確認の画面つき。最低人数を割る場合は警告)。AI 球団は、自球団のスカウト評価が低い選手を上限(設定値。仮置き 3 人)まで手放す。手放された選手は市場へ。
  - 自由契約の画面(D-222):自球団の選手を野手・投手に分けて、名前(固定列)・ポジション・年齢・打席(投手は投球回)と、選んだ成績(基本・セイバー・WAR。2 シーズン目以降は今シーズン・通算を選べる。答え合わせモードがオンのときは真の能力も)の列を出す。全部の列で並べ替えでき(初期は WAR の低い順)、並び順の保持と並べ替えた指標の固定表示は個人成績と同じ。ポジション別の絞り込み(先発・救援 / 捕手・内野手・外野手)。手放す印を付けるたびに、ポジション別の残り人数と最低人数を出す。市場の画面にも同じ表示を足す(手放された選手は成績も出る。指名されなかった候補は成績なし「—」)。並べ替え・絞り込み・切り替えの状態は、手続きの画面を行き来しても保つ。
- **ドラフト**(D-202、D-203):ウェーバー方式。前年の成績(勝率)が低い球団から順に指名し、巡ごとに順番を逆にする(往復)。巡数は設定値(既定 6 巡)。候補は指名数の 1.5 倍ほど(設定値)を、既存の新人の生成で作る(校正の定数を足す。ポジションの構成は人数の目安の比率、年齢は新人の分布)。指名できるのは空き枠(上限 70 人)の分まで。空き枠がない球団はパス。ポジション別は、一軍を組むのに必要な最低人数(先発 6・救援 8・捕手 2・その他の各ポジション 1・野手 15)だけ守る。指名した時点で入団する(契約金・年俸・入団拒否なし)。
- **自由契約市場**(D-204):手放された選手と、指名されなかった候補が並ぶ。獲得はドラフトと同じ順番で数巡(設定値。既定 3 巡)。お金のルールは入れない。市場に残った選手は、そのオフの終わりにリーグを去る。
- **自動補充**:オフの終わりに、70 人に満たない球団を既存の補充(同じ生成)で埋める(最低人数を満たすポジションから)。
- AI 球団はプレイヤーと同じスカウト評価の仕組み(球団ごとのずれ)で判断する(D-205)。判断の方針は差し替え可能。
- 範囲外(D-208):育成選手、外国人、契約年数・年俸・お金のルール、トレード、FA。

#### スカウトの評価(D-199、D-200、D-206、D-212〜D-215。D-079 を置き換え)
- 評価は、各能力の**推定値**(20〜80)+ **ふれ幅** + **天井**(S〜D の 5 段階)。同じ候補は何度見ても同じ値(シードから導く)。球団ごとに違う値。
- 推定値 = 真の現在の能力 + **共通の見誤り**(選手 × 球団ごとに 1 つ。全項目に同じ値)+ **項目ごとの見誤り**(項目ごとに独立)の 2 層(D-212)。2 つの大きさ(標準偏差)は設定で、ずれの段階(小・中・大。既定は中)ごとに持つ。仮置き:共通 2・4・6、項目ごと 約 2.2・3.0・5.3(項目の誤差の合計は 3・5・8、総合の誤差は約 2・4・6)。球団ごとの値で持てる形(既定は全球団同じ。将来の球団職員につなぐ。D-200)。
- 総合の推定値は項目の推定値の平均。ふれ幅は、項目も総合も、その推定値の実際の誤差の標準偏差の 1.28 倍(真の値が入る確率が約 80%。D-213)。
- 天井は、潜在能力の総合値に総合の誤差と同じ大きさの見誤り(現在の能力の見誤りとは別の乱数。D-214)を足した値を、そのオフの候補全体の上位 5%(S)・次の 15%(A)・次の 30%(B)・次の 30%(C)・下位 20%(D)で段階にしたもの(相対評価。D-218)。
- 隠し情報(潜在能力・成長タイプ・生成時の型)はそのまま隠す。年齢・出身・左右・ポジションは正確に見える。
- 入団した選手には、入団時の評価(評価方式の版つき。D-215)を保存し、選手のページに残す。旧方式(版 1)の評価はそのまま表示する。答え合わせモードがオンのときだけ、評価と真の能力を並べて見られる。オフのときは、入団後の能力は表示されない。

#### ドラフトの振り返り(当たり外れの一覧。D-216)
- 「ドラフトの振り返り」の画面で、入団した年度と球団を選ぶ(初期値は、自球団の最新の年度。観戦のみなら球団を選ぶ)。1 人 1 行(固定列は名前)で、入団の経路(ドラフトの巡・市場・自動補充)、ポジション、入団時の総合の推定値とふれ幅、入団時の天井、今の所属(自球団・他球団・引退)、今までの成績(出場と WAR の累計)を出す。
- 答え合わせモードがオンのときだけ、今の真の総合、入団時の推定値との差(+ は期待以上、− は期待以下)、実際の天井の段階(潜在能力を入団時の分位点で判定)を足し、球団ごとの差の平均と標準偏差(その球団の「見る目」の目安)と、リーグ全体の値を出す。
- 事前運転中の入団(年を持たない)は出さない。観戦のみでも見られる。スマホの縦持ちで読めること(固定列 + 横スクロール。表を上、説明を下)。広い画面では横スクロールなしで全列を出す(D-223)。表の下に、入団直後は「差」がマイナスに偏りやすいこと(勝者の呪い)の説明を一行入れる(D-226)。

### 4.9 オフシーズン(F2:複数年。D-071、D-180〜D-189)
(契約・ドラフトなどは F3 で決める)
- **年度の確定**:シーズン終了後に、画面の「年度を確定」で行う。戻せないので、確認の画面で「戻せないこと」と「直前の状態を別名で保存できること」を示す(D-185)。処理はこの順:
  1. 今シーズンの集計を履歴に残す(順位表、選手 × シーズンの成績・WAR・内訳。全シーズン保存)。球場 × シーズンの集計を球場補正の履歴に足し、指標の基準値の出発点を今シーズンの最終値にする(D-121、D-146)。
  2. 加齢(年齢を 1 上げる)。
  3. 能力の更新(年1回。D-186):能力の揺れを足し、年齢カーブで現在の能力を出し直す。好調・不調は引き直す。潜在能力・成長タイプ・型は変えない。20〜80 の目盛りを保つ。
  4. 引退:年齢と能力から確率で決める(設定値。実在の統計は写さない。D-187)。
  5. オフの手続き(F3-1。D-201):自由契約 → ドラフト → 自由契約市場 → 自動補充(4.8「オフの手続き」)。F2 の簡易な補充(D-184)は、最後の自動補充として残す。
  6. 次のシーズンの準備:一軍(29人)・打順・先発の編成は既存の自動の規則で組み直す。疲労はリセット。日程は次のシーズンのシード(今のシーズンのシードから導く)で作る。
- 乱数は年度ごとのシードから導き、同じシードなら同じ結果(D-186)。
- 怪我は F2 では入れない。契約・自由契約・FA・トレードは F3 で扱う。
- 30年回しても、一軍相当の能力の平均とリーグの成績に上がる・下がる傾向がないこと(受け入れ条件。D-188)。
- 打席ログは直近の `log_seasons` シーズン(設定値。既定 1)だけ残し、それ以前は集計だけ残す(D-189)。
- 球場補正の換算の基準値は固定のまま(D-189)。
- 初期選手は、ゲーム開始前に試合なしで数十年分回した状態から始める(D-034 の完成形。D-190。4.2「初期選手の作り方」)。
- 引退の設定は、30 年回した後に 38 歳以上が全体の 2〜4% 程度残る値にする(D-191)。41 歳で必ず引退。

## 5. 非機能要件(機能そのものではなく、守るべき条件)

- **実名の扱い**:実名の球団名は、ユーザーが入力するセーブデータの中にのみ存在し、公開リポジトリには含まれないこと。
- **セーブデータの保存場所**:セーブデータは各自の端末(PC・スマホ)に保存され、リポジトリの外に置かれること。サーバーには送らないこと(D-081)。
- **画面の差し替えへの備え**:画面を作り直しても、計算本体を作り直さずに済むこと。
- **再現性**(D-088):同じシードなら、端末(スマホのブラウザ・PC)や Python の版が違っても、同じ結果になること。決まったシードの結果の指紋をテストに固定して確かめる(D-089)。
- **ブラウザで動くこと**:計算本体は Python 標準のライブラリだけで作り、ブラウザ上の Python でもそのまま動くこと(D-083)。
- **速度の目安**(D-082):スマホと PC のブラウザで、1日分が約1秒以内、1シーズンが数分以内(進み具合を表示)、メモリ不足で止まらないこと。
