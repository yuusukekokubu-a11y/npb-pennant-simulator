## 3. 用語集
<!-- このプロジェクトで使う言葉の意味をそろえるための一覧 -->

開発で使う言葉の一覧です。**指標(打率・wOBA など)とゲームのルールの用語は、ゲームの用語集のデータ `src/pennant/data/glossary.json` が正本**です(画面の「用語集」のページと、表の見出しの解説は、そこから作ります。D-311)。ここには指標の文を重ねて書きません。

| 用語 | 意味 |
| --- | --- |
| ペナントレース | シーズン全体を通した順位争い |
| セーブデータ | ユーザーが入力した内容や進行状況を保存したファイル。リポジトリの外に置く |
| シード(乱数のシード) | 乱数の出方を決める初期値。同じシードなら同じ結果を再現できる |
| セイバーメトリクス | 統計(データの集計・分析)を使って、選手の本当の貢献度を測ろうとする考え方。打率や勝利数のような昔ながらの数字より、得点や勝利への影響を重視する |
| 見せる能力 | 選手の能力(野手:弾道・ミート・パワー・走力・肩力・守備力・捕球、投手:球速・コントロール・スタミナ・変化球)。プロの選手はいつでも画面で見える。成績は、この能力をもとに乱数で決まるため、同じ能力でも年によって成績が上下する(作り直し①。D-335) |
| WAR | Wins Above Replacement の略。「控え水準の選手(簡単に代わりが見つかる選手)と比べて、何勝分チームに上積みしたか」を表す指標。打撃・守備・走塁・投球をまとめて1つの数字にする |
| ドラフト | 新人選手を各球団が順番に指名して獲得する制度 |
| 自由契約 | 球団が選手との契約を打ち切り、その選手がどの球団とも契約できる状態になること |
| FA | Free Agent(フリーエージェント)の略。一定の年数プレーした選手が、自分の意思で他球団と契約できる権利、またはその権利を使った選手 |
| 契約更改 | シーズン後に、球団と選手が翌年の年俸などの契約内容を話し合って決め直すこと |
| GM | General Manager(ゼネラルマネージャー)の略。選手の獲得・放出・契約など、チーム編成を決める責任者。このシミュレーターでのプレイヤーの立場 |
| 標準偏差 | データのばらつきの大きさを表す数値。平均から「だいたいどのくらい離れているか」の目安。このプロジェクトの能力値では、10点が標準偏差1つ分(D-024) |
| 正規分布 | 平均付近の値が最も多く、平均から離れた極端な値ほど少なくなる、釣り鐘型のばらつき方。身長などが代表例。平均 ± 標準偏差1つ分の範囲に全体の約68%、± 2つ分に約95%が入る |
| 伸びやすさ | 若いうちに能力がどれだけ伸びるかの個人差。隠し情報で画面には出ない(D-350。潜在能力は持たない) |
| 成長タイプ | 選手ごとの伸び方の違い。早熟(若くしてピーク)・標準・晩成(遅れてピーク)の3つ。隠し情報で、スカウト評価にも出ない |
| 生き残りバイアス | 生き残ったものだけを見ると偏って見える現象。プロ野球では、能力の低い選手は若いうちに引退・解雇されるため、高齢まで残っている選手は平均より能力が高くなる |
| インプレー | 打球がグラウンド内(フェアゾーン)に飛び、守備が処理する打席結果。三振・四球・死球・本塁打以外の打席がこれにあたる |
| オッズ比法 | 打者と投手の能力を組み合わせて結果の起きやすさを決める計算方法。「リーグ平均と比べて何倍起きやすいか」を打者側と投手側で掛け算する。例:三振しやすさが平均の1.5倍の打者と、三振を奪う力が平均の1.5倍の投手なら、およそ2.25倍になる |
| 左右の相性 | 投手と打者の利き腕・打席の組み合わせによる有利・不利。一般に、同じ側どうし(右投手×右打者など)は投手が有利、逆側どうしは打者が有利とされる |
| 担当ポジション | インプレーの打球を処理する野手の守備位置(例:三遊間のゴロなら遊撃手)。その野手の守備能力が、アウトになるかヒットになるかに影響する |
| 年齢カーブ | 年齢によって能力がどう上がり下がりするかを表す形。若いうちは伸び、ピークを過ぎると衰える。能力の種類ごとに形が違う(例:走力は早く衰え、技術は長持ちする) |
| RE24 | 走者の有無(8通り)× アウト数(3通り)= 24通りの状況ごとに、「その状況から、イニングの終わりまでに平均で何点入るか」(得点期待値)をまとめた表。例:無死満塁なら2点強、二死走者なしなら0.1点ほど。打席の前後で期待値がどれだけ増えたかで、その打席の得点への貢献を測れる |
| 線形加重 | 四球・単打・二塁打・本塁打などの結果ごとに、「平均で何点分の価値があるか」を RE24 から求めた値。結果の数にこの値を掛けて足し合わせると、得点への貢献をおおまかに表せる。wOBA の重みの元になる |
| パークファクター(球場補正) | 球場ごとの打ちやすさ・打ちにくさを表す倍率。1.0 が平均で、1.1 なら平均より1割ほど打ちやすい。打ちやすい球場を本拠地にする選手の成績を割り引いて、公平に比べるために使う |
| 回帰(平均への回帰) | 少ないデータから出した値は偶然の影響で極端になりやすいため、平均の方向へ引き戻して見積もること。例:1年だけの結果で 1.2 倍に見える球場も、真の倍率はもっと 1.0 に近いと考えて補正する |
| FIP 定数 | FIP を防御率と同じ目盛りにそろえるために足す数。リーグ全体の防御率と、リーグ全体の本塁打・四死球・三振から、毎シーズン計算する |
| 規定打席 | 打率などのランキング(タイトル)の対象になるために必要な打席数。チームの試合数 × 3.1 で決まる(例:125試合なら 387.5 → 388打席) |
| 規定投球回 | 防御率などのランキングの対象になるために必要な投球回。チームの試合数 × 1.0 で決まる(例:125試合なら 125回) |
| ゲーム差 | 順位表で、上のチームとどれだけ離れているかを表す数。上のチームとの「勝ちの差」と「負けの差」を足して2で割る。1ゲーム差は、直接対決1試合で追いつける差 |
| ラウンド制 | 日程の作り方の1つ。毎日、同じリーグの全チームが1試合ずつ行い、決まった日数で全チームとの対戦が一巡する。これを繰り返してシーズンの日程を作る |
| Pyodide(パイオダイド) | ブラウザの中で Python を動かす仕組み。インストールなしで、Web ページを開くだけで Python のプログラムが動く |
| GitHub Pages | GitHub のリポジトリの内容を、Web ページとして公開する機能 |
| キャッシュ | ブラウザが、一度読み込んだページやファイルを、次回すばやく表示するために一時的に保存しておくもの |
| ハードキャップ | 球団が選手に払う年俸の総額の上限のうち、絶対に超えられないもの |
| ソフトキャップ | 年俸の総額の上限のうち、超えることはできるが、超えると負担(罰金のような支払いなど)がかかるもの |
| 逆順位(ドラフト) | 前の年の順位が低い球団から順に指名する方式。弱い球団ほど良い新人を取りやすくし、戦力の差を縮める |
| スカウトの見立て | ドラフト・外国人の候補の能力の見積もり。能力の数字と特殊能力を見立てで見せ、入団すると本当の数字になる。本当の能力とはずれがあり、ずれは球団ごとに違う(D-212、D-418、D-419)。プロの選手の能力は見える(D-335) |
| 自責点 | 投手の責任による失点。失策(エラー)がなければ防げた失点は含めない。防御率の元になる |

## 4. 機能要件(何ができるか)

### 4.1 リーグ・球団
(D-021)
- 12球団・2リーグ制(各リーグ6球団)。
- 日程は「対戦相手ごとの試合数」を設定値として持つ(コードを変えずに変更できる)。
- 最初は同一リーグ内の対戦のみ:各相手25試合 × 5球団 = 計125試合。
- その後、交流戦(別リーグの6球団と3試合ずつ = 18試合)を加えて計143試合にする。
- クライマックスシリーズ(シーズン後の上位チームによるプレーオフ)は後から追加する。

### 4.2 選手
(D-017、D-022〜D-024、D-027〜D-031、D-033、D-034、D-039、D-041)

#### 人数(D-029)
- 1球団の選手は支配下70人を上限とし、70人で始める。
- 内訳の目安(設定値):投手 約32、捕手 約9、内野手 約18、外野手 約11。
- 育成選手は最初は持たない(F3 で検討)。
- 支配下の上限70人・一軍登録枠29人は確認済み(D-029 補足)。

#### 能力(作り直し①。D-335〜D-338、D-347〜D-351)
- 選手の正本は**見せる能力**で、プロの選手(自球団・他球団)の能力はいつでも画面で見える。ドラフト候補の能力は見せない(③ までは今のスカウト評価の形。D-352)。
- 目盛りは **1〜100** の整数とランク(S 90〜・A 80〜・B 70〜・C 60〜・D 50〜・E 40〜・F 20〜・G 〜19)。一軍の平均がおよそ 60(C の入口)。
  - 内部では、今までと同じ目盛り(50 が一軍の平均、10 点が標準偏差 1 つ分)の小数で持ち、画面では 60 + 1.5 ×(値 − 50)に直す。
- 能力(固定的な力)と、状態(疲労・好調不調など)は分けて持つ。

**野手の能力(7項目)**

| 項目 | 見せ方 | 主な効き目(試合の計算の内部の能力) |
| --- | --- | --- |
| 弾道 | 1〜4 | 打球の上がりやすさ(ゴロ/フライ傾向)。パワーと、隠し情報の「弾道の傾き」で決まる |
| ミート | 1〜100・ランク | 三振の少なさ(コンタクト)と打球の鋭さ(打球の質) |
| パワー | 1〜100・ランク | 長打力(本塁打・二塁打) |
| 走力 | 1〜100・ランク | 走力・走塁判断(内野安打・三塁打・進塁) |
| 肩力 | 1〜100・ランク | 肩(走者の進塁・併殺) |
| 守備力 | 1〜100・ランク | 守備範囲(安打を防ぐ) |
| 捕球 | 1〜100・ランク | 捕球(失策の少なさ) |

**投手の能力(4項目と球種)**

| 項目 | 見せ方 | 主な効き目 |
| --- | --- | --- |
| 球速 | km/h(145 が平均の目安) | 球威(本塁打の打たれにくさ)と奪三振力 |
| コントロール | 1〜100・ランク | 制球力(四球の少なさ) |
| スタミナ | 1〜100・ランク | 先発で投げられる長さ |
| 変化球 | 球種ごとの変化量 1〜7(2〜4 球種) | 奪三振力(合計の強さ。球種ごとの効き目は後から足せる) |

- 試合の計算は今までの式のまま、見せる能力を内部の能力に換算して使う(換算表は設定ファイル。D-349)。
- 新しい項目にない内部の能力(選球眼・走塁判断・回復力・走者抑制・打球抑制・投手のゴロ/フライ傾向)は全員平均にそろえ、差をなくす。後で特殊能力として戻せる形にする(D-348)。
- 特殊能力(チャンスに強い など)は今は持たない。後から足せる形にする(D-336)。

#### 特殊能力(D-374)
- 良いもの(◯)と悪いもの(×)の対。1 人の選手が同じ対の両方を持つことはない。
  - 野手:チャンス◯/×(得点圏でミート・パワー ±8)・対左投手◯/×(左投手が相手のときミート・選球眼・パワー ±8)・走塁◯/×(走塁の判断 ±15)・パワーヒッター(パワー +5)・アベレージヒッター(ミート +5)。
  - 投手:ピンチ◯/×(得点圏で奪三振・打球を抑える力・本塁打を抑える力 ±8)・対左打者◯/×(左打者が相手のとき同じ 3 つ ±8)・奪三振◯/×(奪三振 ±6)・重い球(本塁打を抑える力 +6)/一発気味(−6)。
  - 値は内部の能力の目盛り(10 点が標準偏差 1 つ分)。見せる能力の数値は変えない。仮置き。
- 付き方:選手を作るときに別の乱数で確率で付く(◯ 約 10%・× 約 8%。パワーヒッター・アベレージヒッターはパワー・ミートの高い選手だけ)。毎年のオフに、選手ごとに 4% の確率で 1 つ付き、4% の確率で 1 つ消える。
- 見せ方:選手のページ・成績の「能力」・スタメンと打順の画面。ドラフト候補の特殊能力は見えない(入団後に見える)。種類は `data/skills.json` で足せる。
- 保存形式は版 18。版 17 以前のセーブデータの選手は特殊能力なしで始まる。

#### 属性(能力値以外の情報)
- 打席の左右(打者のみ。右・左・両打ち)
- 投球の左右(投手のみ。野手の投げ手は持たない。D-048)
- 打席の左右と投球の左右の間に、関係は持たせない(D-048)
- 年齢
- ポジション:第1弾は1人1つの主ポジションで固定。守備適性・兼任は F3 で扱う(D-049)
- 先発 / 救援の適性(投手)
- 投手は打席に立たないので、打撃の能力・打席の左右を持たない(D-046)

#### 成長(作り直し①。D-030、D-031、D-033、D-337、D-350)
- 潜在能力(ピーク時の能力・天井)は持たない。能力は毎年のオフに次の増減だけ変わる。
  - 年齢による増減(若いうちは伸び、ピークを過ぎると衰える)× 伸びやすさ(伸びる年だけ)+ 小さな揺れ
- 伸びやすさ・成長タイプ(ピークの年齢の早い・遅い)・弾道の傾きは隠し情報で、画面には出さない。
- 年齢カーブは、能力をグループに分けて持つ(数値は仮置き)。

| グループ | 項目 | カーブの特徴 |
| --- | --- | --- |
| 身体系 | 走力、守備力、スタミナ | ピークが早く、衰退が速い |
| パワー系 | パワー、球速、肩力 | ピークは中間で、衰退はやや緩やか |
| 技術系 | ミート、捕球、コントロール、変化球 | ピークが遅く、衰退が緩やか |

- 一軍の平均が 50(画面では 60)になるよう、新規開始の校正の定数で合わせる(D-197)。30 年回しても平均が動かないことを確かめる(D-071)。
- 調子(シーズン中に変わる 5 段階。D-424)は「状態」として持つ。

#### 自動生成(D-027、D-028、D-030、D-350)
見せる能力は次の順で作る(生成のときだけ「ピーク時の水準」を一度引き、そこから年齢による差を引いて今の能力にする。ピーク時の水準は保存しない)。
1. 型を選ぶ
2. 型ごとの補正を基準値に足す
3. 正規分布の乱数を足す

- 型の補正値・出現割合、正規分布の平均・標準偏差は設定値とする。
- 補正は、型の割合を掛けて合計するとリーグ平均がほぼ変わらないよう調整する。
- **ポジション別の出現割合**(第3弾①。D-157):打者の型の割合は、ポジションごとに「足す量」(合計 0)を全体の割合に足して決める。捕手・遊撃・二塁は守備型と俊足型が多め、一塁・三塁・左翼・右翼は長距離砲が多め、中堅は俊足型と守備型が多め。「足す量」は球団の人数で重みづけした合計が型ごとに 0 で、全体の割合(各 20%)と全体の平均は変わらない。指名打者は独立したポジションではない。投手には適用しない。
- 型の補正を足す前の基準分布は全員共通。ドラフトで入る新人は、年齢にかかわらず全員同じ基準分布から作る。
- 生成時の型は、隠し情報として選手データに記録する。年齢では変わらず、計算には使わない(D-043)。
- **初期選手の作り方**(D-034、D-190、D-197):ゲーム開始時の初期選手は、年齢が高いほど能力を高めにずらして作り(生き残りバイアス)、その後、試合をせずに年度の確定の処理(加齢・能力の更新・引退・補充)だけを数十年分回す(事前運転。年数は設定値)。事前運転の間は成績・WAR・球場補正の履歴を作らない。最後に、一軍相当の総合(見せる能力の平均)が 50 になるよう、見せる能力に役割ごとの定数を足す(校正。定数は設定値で、その後に入る新人にも同じ定数を足す)。乱数はシードから導き、同じシードなら同じ結果。
- 偏りを持たせる調整は、後から行えるようにする。

**打者の型(5型)**:長距離砲、巧打者、俊足型、守備型、万能型

**投手の型**:役割 × 球質 の組み合わせ

| 役割 | 球質 |
| --- | --- |
| 先発型 / 救援型 | 本格派 / 技巧派 / ゴロ打たせ型 / 変則派 / 標準型 |

- 変則派は、変化球↑・コントロール↓ の方向で補正する(初期案)。
- 「控え型」は置かない(水準の差は年齢と能力で表す)。
- 投手は 2〜4 個の球種(スライダー・カーブ・フォーク・チェンジアップ・カットボール・シュート・シンカー)を持つ(D-351)。

#### 年齢(D-039)
- 初期選手の年齢は正規分布で近似する(平均27歳前後、標準偏差5歳前後で試行中。18〜42歳に収める。D-051 で D-039 の初期案を更新)。
- 新人の入団年齢:高卒18歳、大卒22歳、社会人・独立リーグ出身23歳前後。割合は 4:4:2。
- いずれも設定値の仮置き。実在の統計は写さない。

#### 名前(D-041)
- 選手の名前は、一般的な姓と名の部品を組み合わせてプログラムが作る。部品リストに実在選手の名簿は使わない。
- 同じ球団・同じリーグの中では、名前が重複しないようにする。
- 外国人選手の名前は、カタカナの「名」と「姓」の部品を組み合わせて作る(実在の名簿は使わない)。画面では姓だけを出し、同じ球団の中では姓が重ならないようにする(D-376)。
- 球団名・球場名の初期名も、一般的な地名や言葉の組み合わせで作り、実在の名前と一致しない形にする。

### 4.3 試合のシミュレーション
(D-015、D-017、D-035〜D-038、D-045〜D-047)
- **指名打者制**:両リーグとも指名打者制で、投手は打席に立たない。指名打者は守備につかない打者の枠で、担当ポジションの対象に入らない。起用は監督の自動采配が決める(D-046)。
- **再現するプレー**:打席の結果・走者の進塁・併殺・犠牲フライ・盗塁・暴投・捕逸(D-427)。犠打・ボーク・牽制は、後から追加できる設計にする(D-045)。
- ゴロ/フライ傾向は、数値が高いほどゴロが多い(D-047)。
- 試合は**打席単位**(打者1人が打席に立つごと)で計算する。
- 打席結果は、選手の「真の能力」をもとに乱数で決める。
- 打席結果は**2段階**で決める(D-035)。
  1. **第1段階**:守備が関係しない結果か、打球が飛んだかを決める。結果は「三振・四球・死球・本塁打・インプレー」のどれか。
  2. **第2段階**:インプレーの場合、打球の種類(ゴロ・ライナー・フライ)と方向を決め、守備側の能力で「アウト・安打・失策」を決める。
  - BABIP は第2段階の結果だけで決まる。
  - 第2段階では、打球の種類に加えて**担当ポジション**(どの野手が処理するか)まで決める(D-038)。
    - 担当野手の守備範囲・肩・捕球と、打者の打球の質・走力で、アウト・安打・失策を決める。
    - 野手が処理できない打球(長打など)は、別の割合で扱う。
    - 安打の内訳(単打・二塁打・三塁打)は、担当ポジションで決める(D-072)。投手・捕手・二塁手・遊撃手は単打だけ。一塁手・三塁手は単打が中心で、線を抜ける二塁打を少し認める(三塁打なし)。外野手は単打・二塁打・三塁打。野手が処理できない打球の内野手担当分も同じ。
    - 第1弾では守備の効果を単純に実装し、第3弾(WAR)で精密にする。
    - 打球の落下地点や速度を座標で再現することは行わない。
- 打者と投手の能力は**オッズ比法**で合成する(D-036)。
  - リーグ平均の率(三振率、四球率など)は、実在の成績表を写さず、一般的な水準の架空値(設定値)とする。
  - 能力値から倍率への変換は「10点あたりの倍率」を設定値とし、シーズンを繰り返し回して校正する。
- **左右の相性**はリーグ共通の補正で扱う(D-037)。
  - 同じ側どうし(右投手×右打者、左投手×左打者)は投手有利、逆側どうしは打者有利の補正を、オッズ比法の倍率として掛ける。
  - 両打ちの打者は、投手の左右の逆で打つ(常に有利な側)。
  - 補正の大きさは設定値(ゼロにもできる)。一般的な傾向を参考にした仮置き値で、実在の統計は写さない。
  - 選手ごとの左右差(個人差)は、後から追加できるようにする。
- **球場の倍率**(D-064、D-136、D-137。第2弾②a):球場ごとの本塁打と BABIP(インプレーの安打)の倍率を、その試合の球場(ホームチームの本拠地)について、オッズ比法の倍率として両チームの打者に掛ける。本塁打の倍率は第1段階の本塁打に、BABIP の倍率は第2段階の「野手が処理できる打球が安打になる」確率に掛ける(処理できない打球の割合と失策率には掛けない)。ホームの有利とは別に掛ける。倍率は整数の千分率で持ち、各リーグの6球場の平均がちょうど 1.0。範囲の初期値は本塁打 0.85〜1.15、BABIP 0.97〜1.03(設定値)。
- 打席結果は種類ごとに区別して記録する。少なくとも次を区別する:
  - 単打、二塁打、三塁打、本塁打
  - 四球、死球
  - 三振
  - ゴロアウト、ライナーアウト、フライアウト
  - 失策(打者が失策で出塁)
  - (その他、指標の計算に必要な種類は必要に応じて追加する)
- 打席ごとの記録(打席ログ)には、打席結果の種類に加えて、走者・アウト状況(24通り)を必ず記録する(D-026)。
- 打席結果を計算する部分は、差し替え可能な部品とする(計算方法を後から改良できるように)。
- 試合中の采配(選手起用や作戦)は自動とする(D-019)。

#### 1試合の進行(D-059〜D-062)
- **試合の形式**(D-062):9回まで。9回裏はホームがリードしていれば行わない。サヨナラはその場で試合終了。延長は上限(初期値12回)まで、同点なら引き分け(設定で変更可)。
- **走者の進塁**(D-059):
  - 四球・死球は押し出し。本塁打・三塁打は全員生還。
  - 単打・二塁打での進塁、ゴロでの併殺と進塁、フライでの犠牲フライ、失策での進塁は、確率表を能力(走者の走力・走塁判断、打者の走力、担当野手の捕球・肩)で補正して決める(オッズ比法)。
  - 併殺は走者1塁・2アウト未満のゴロのときだけ。犠牲フライは3塁走者・2アウト未満のフライのときだけ。
  - 走塁死は第1弾では入れない。
  - 打席ログに、各走者の進塁(どの塁からどの塁へ、アウトか)、その走者を出塁させた投手、失策による出塁・進塁かどうか、打順、イニング、点差を記録する。
- **盗塁・暴投・捕逸**(D-427〜D-429):
  - 次の打者の打席の前、塁に走者がいるときに起きる。まず暴投か捕逸かを決め、起きれば全走者が 1 つ進む(3 塁の走者は生還)。暴投は投手のコントロールが低いほど、捕逸は捕手の捕球が低いほど起きやすい。
  - 次に盗塁を走るかを決める。1 塁 → 2 塁(2 塁が空き)と 2 塁 → 3 塁(1 塁と 3 塁が空き)だけ。本盗・重盗はなし。走るかは、走者の走力・相手の捕手の肩力・投手のクイック(内部の能力)と点差(4 点以上負け・5 点以上勝ちなら走らない)で決め、成功の見込みが低い走者は走らない。成功は 走力・走塁判断・肩力・クイックで決める(オッズ比法)。失敗(盗塁死)はアウトで、3 アウトになれば打席の打者は次の回の先頭。
  - 9 回以降の裏に暴投・捕逸で勝ち越せば、サヨナラで終了。
  - 多さの目安(仮置き):1 球団 1 シーズンで盗塁 60 前後・成功率 7 割・足の速い選手は 30 前後・暴投 25・捕逸 5。値は `game.json` の steal・battery。
  - 特殊能力:盗塁◯/×(盗塁のときだけ走力 ±15。◯は走力 60 以上)、キャッチャー◯/×(捕手だけ。捕手として出ている間、肩力・捕球 ±10、組む投手の全能力 ±2)。
  - 自球団は、スタメンと打順の画面で盗塁の作戦(積極的・普通・慎重)を選べる。AI 球団は普通。
- **投手の起用**(D-060):
  - 先発は、対戦打者数の上限(スタミナと疲労から決まる)か失点の上限で降板する。降板はイニングの終わりが原則で、失点の上限に達したときだけ途中で降板する(引き継いだ走者の責任は前の投手)。
  - 救援は1イニング単位。
  - 疲労は投げた打者数から計算し、回復力で日ごとに回復する。疲労が大きい投手は登板できない。球数は使わない。
- **一軍・スタメン・休養**(D-061):
  - 一軍登録は29人(投手14・野手15)。
  - スタメンは各ポジションで最も強い野手+指名打者。主力は一定確率で休み、控えが同じ打順・ポジションに入る。
  - 試合中の交代(代打・代走・守備固め)・敬遠・犠打は入れない。
  - 一軍の選抜・スタメン・打順・継投・休養は、差し替え可能な簡易ルールとする。
- **スタメンと打順の操作**(D-373):
  - あなたの球団(自球団)は、スタメン 9 人(捕手・一塁手・二塁手・三塁手・遊撃手・左翼手・中堅手・右翼手・指名打者)と打順を自分で決められる。選べるのは一軍の野手 15 人。同じ選手を 2 つの枠に入れることはできない。本来と違う守備位置に入れた選手は、守備の能力が下がる(近いポジションは −5、遠いポジションは −10。控えを入れるときと同じ)。
  - 打順の型:**二番強打者**(打撃の総合がいちばん高い打者を 2 番、1 番は出塁、3〜5 番は長打)・**二番つなぎ役**(2 番にミートと走力の高い打者)・**機動力重視**(1・2 番に足の速い打者)・**長打重視**(1・2 番は出塁、3〜5 番に長打の高い 3 人。今までの組み方で既定)。どの型も 6〜9 番は打撃の総合の順。スタメンは各ポジションで最も強い野手 + 指名打者(今までどおり)。
  - 型を選ぶと、AI がその型でスタメンと打順を組む(毎試合)。自分で組んだスタメンと打順は、次の見直し(7 日ごと。設定値)まで毎試合使い、見直しの日に AI が型で組み直す(画面に知らせを出す)。一軍の選手でなくなった選手が入っていれば、その場で AI が組み直す。
  - 主力の休養(一定の確率で控えが同じ打順・ポジションに入る)は、自分で組んだ打順にも働く。
  - AI 球団は長打重視のまま。一軍の顔ぶれ・先発の順番・継投は AI のまま(怪我・試合中の采配は入れない。D-372)。
  - 試合のページで、その試合を同じ打順で再現できるよう、自分で組んだ打順は試合ごとに記録する。保存形式は版 17(版 16 は変換して読む)。

### 4.4 シーズン(日程・順位)
(D-021、D-066、D-087、D-435〜D-437)
- **日程**(D-435):1 シーズン 143 試合。同じリーグの 5 球団と 25 試合ずつ(リーグ戦 125 試合)と、交流戦 18 試合(もう片方のリーグの 6 球団と 3 試合ずつ)。
  - 試合は同じ相手との連戦(シリーズ)で組む。試合のある日は、全 12 球団が 1 試合ずつ行う(1 日 6 試合)。
  - リーグ戦は総当たりの巡(5 シリーズで一巡)を 9 回くり返し、シリーズの長さは巡ごとに 2・3・2・3・3・3・3・3・3 試合(合計 25)。2 リーグは同じ日に並行して試合をする。
  - ホームとアウェイは、同じ相手とのシリーズごとに交互に入れ替える。
  - 交流戦は、リーグ戦の 45 試合目のあと(シリーズの区切り)にまとめて置く。3 連戦 × 6。ホームはどの球団も 3 カード(9 試合)で、奇数年と偶数年で入れ替える。
  - 試合が 6 日続いたら、シリーズの区切りで全球団が休む日を 1 日入れる(シーズンは約 170 日)。休みの日も 1 日として数え、投手の疲労の回復・調子(5 日ごと)・一軍の見直し(7 日ごと)・外した選手の 10 日は日で進む。
  - 進行の「1日」は、次の公式戦の日まで進む(休みとオールスターの日を飛ばす)。試合のタブの「前の日・次の日」も休みの日を飛ばす。トレードの期限は今までどおりシーズンの日数の割合。規定打席・規定投球回は試合数 × 3.1・× 1.0。
  - 値は設定(`data/season.json` の schedule)。版 26 のセーブデータの続きのシーズンは、今までの日程(25 回の総当たり、毎日 1 試合、交流戦・休みなし)のまま。次のシーズンから 143 試合(D-438)。
- **オールスター**(D-436):リーグ戦(交流戦を含む)の 86 試合目のあとに 4 日の休み(オールスターの休み)を入れ、その 2 日目と 3 日目に、両リーグの選抜チームどうしで 2 試合行う(1 試合目は第一リーグ、2 試合目は第二リーグの球団の球場。球場はそのリーグの球団から乱数で選ぶ)。
  - 選手は、そのリーグの全球団の支配下の選手から、一軍の選び方と同じ決まり(29 人・ポジション・外国人の上限)で、基準を「総合 + 今シーズンの成績の点」にして自動で選ぶ。成績の点は −5〜+5(内部の能力の目盛り。仮置き):打者は OPS、投手は防御率から、規定(救援は 1 試合 1 アウト)に足りない分だけ小さくする。
  - 成績・疲労・調子・WAR には入れない。結果(得点・勝ったリーグ・出た選手・MVP)を残し、進行の画面と記録室に出す。MVP は勝ったリーグの、塁打 + 打点が最も多い打者(同じなら打順の早い方。引き分けは両リーグから 1 人ずつ)。
  - 乱数は `derive_seed(シーズンのシード, "allstar:<回>")`。
- **交流戦の順位**(D-437):順位表の画面に「交流戦」の表(12 球団の交流戦だけの勝敗・勝率・ゲーム差)。交流戦の優勝は交流戦の勝率が最も高い球団(同率なら勝利数、それでも同じならシーズンのシードの抽選)。記録室の「順位と優勝」に、その年の交流戦の優勝とオールスターの結果を出す。
- **勝率**:勝利数 ÷(勝利数 + 敗戦数)。引き分けは分母に入れない。
- **順位**:勝率の高い順。同率のときは、勝利数、直接対決の成績、の順で決める。それでも同じなら、シーズンのシードで決めた抽選の順。同順位を許す設定では、勝率が同じチームを同じ順位にする。
- **ゲーム差**:首位との差と、1つ上の順位のチームとの差の両方を出す(ゲーム差 =(上のチームの勝利数 − 勝利数 + 敗戦数 − 上のチームの敗戦数)÷ 2)。
- **疲労と先発**:先発は疲労が回復してから登板する。回復力の低い先発は、ときどき飛ばされる(1シーズンで先発の機会の約4%)。
- **先発**:6人ローテーション。疲労が大きい投手は飛ばす。
- **再現**:試合ごとの乱数のシードはシーズンのシードから決め、1試合だけを取り出して再現できる。
- **範囲外**:怪我・成長はシーズンの中では起こらない(F2・F3 で扱う)。
- **ホームとアウェイの割り振り**(D-087):各ペアの25試合のうち13試合のホーム権を持つ側を、各チームが2〜3組で持つように割り振る(各チームのリーグ戦のホームは62試合か63試合。交流戦を足して 71 か 72 試合)。割り振りはシーズンのシードで決める。
- **試合数**:設定値(既定は 25試合 × 5チーム + 交流戦 3試合 × 6チーム = 143試合)。
- **1日の流れ**:スタメンと先発を決める → 試合 → 疲労を加える → 1日を進めて回復させる。
- **シーズンの結果**:最終順位表、全試合の結果、全打席のログ。優勝は各リーグの最高勝率のチーム。
- **ポストシーズン**(D-439〜D-441):レギュラーシーズンの後に行う。
  - CS 1st ステージ:各リーグの 2 位 vs 3 位、3 試合(先に 2 勝)。すべて 2 位の球場。
  - CS ファイナルステージ:1 位 vs 1st の勝者、6 試合(1 位に 1 勝のアドバンテージを足して、先に 4 勝)。すべて 1 位の球場。
  - 日本シリーズ:両リーグの CS の勝者、7 試合(先に 4 勝)。球場は 2・3・2 で交代(1・2・6・7 試合目は、奇数年は第一リーグ、偶数年は第二リーグの球団)。8 戦目以降は同じ並びの続き。
  - 引き分けは数えない。CS で試合を使い切って決着がつかなければ、レギュラーシーズンの順位が上の球団が勝ち抜け。日本シリーズは決着がつくまで続ける。
  - 日程:シーズン後に休み 1 日 → CS 1st(2 リーグ並行)→ 休み 1 日 → CS ファイナル → 休み 2 日 → 日本シリーズ(2 試合目と 5 試合目の後に休み 1 日)。決着がついたら残りの試合は行わない。日はシーズンの日に続けて数える(画面では「ポストシーズン N日目」)。
  - 一軍・調子・疲労・先発の順番・打順の計画はシーズンの続き。自球団はスタメン・一軍登録の画面を使える(トレードは期限後なのでできない)。
  - 試合の乱数は `derive_seed(シーズンのシード, "post:<通し番号>")`。1 試合だけを再現できる。
  - 成績はレギュラーシーズンの成績・タイトル・WAR・順位には入れない。シリーズごとの MVP(勝った球団の、打者は塁打 + 打点、投手は 投球回 − 自責点 × 2 + 勝利 × 3 + セーブ × 2 が最も大きい選手)。
  - 日本シリーズが終わってから年度の確定ができる。結果は記録室に残す(お金などへの影響はない)。値は設定(`data/season.json` の postseason)。
- **サヨナラの打ち切り**:サヨナラで得点が打ち切られた打席には、そのことを打席のログに残す(公式記録の数え直しは実装⑤で決める)。
- **ホームの有利**(D-073):ホームチームの打者に小さな倍率(設定値。なしにもできる)を掛ける。ホームの勝率がおおむね52〜54%になる大きさにする。
- **一軍**(D-074、D-425):一軍は 29 人。疲労は登板の可否と先発の打者数の上限にだけ使い、成績には効かせない。
  - **調子**(D-424):絶好調(+2)・好調(+1)・普通(0)・不調(−1)・絶不調(−2)の 5 段階。シーズンの初めに決まり(5 段階の割合は 10・20・40・20・10%。仮置き)、5 日ごと(設定値)に確率で 1 段階上下する(上がる確率 25% − 8% × 段階、下がる確率 25% + 8% × 段階。仮置き)。段階 × 3 点(内部の能力の目盛り。設定値)を全能力に足す。乱数は `derive_seed(シーズンのシード, "cond:<選手>:<回>")`(回は 0 が初め、1 から 5 日ごと)。画面では矢印の印(↑・↗・→・↘・↓)で出す。
  - **入れ替え**(D-425):自球団は「一軍登録」の画面で、一軍と二軍の選手を 1 人ずつ入れ替える(投手は投手と、野手は野手と)。一軍の最低人数(捕手 2 人・各ポジション 1 人以上など、一軍の選び方の決まり)と外国人の上限(4 人)は守る。一軍から外した選手は、外した日から 10 日(設定値)たつまで一軍に戻せない。
  - **AI の見直し**:AI 球団と、「AI に任せる」(既定オン)の自球団は、7 日ごと(打順の見直しと同じ日。その日の試合の前)に一軍を選び直す。選び方はシーズンの初めと同じ決まりで、基準を「総合 + 調子 × 3 点」にし、今の一軍の選手に 4 点(設定値)を足す(入れ替えすぎない)。10 日の決まりで戻せない選手は選ばない(最低人数に足りないときだけ例外)。トレードの後の選び直しも同じ。
  - 二軍の試合は行わない(成績は付かない)。投手の疲労は、一軍・二軍に関わらず毎日回復する。けがは入れない。

### 4.5 成績・記録の表示
(D-016、D-018、D-025、D-026)
個人成績と、セイバーメトリクス系の指標を最優先の機能とする。指標は3弾に分けて実装するが、設計は最初から WAR まで見据える。

指標の弾への振り分けは、次の原則に従う(D-026)。

| 弾 | 振り分けの原則 | 目標とする指標の例 |
| --- | --- | --- |
| 第1弾 | 選手個人の記録だけで計算できる指標 | 打率、出塁率、長打率、OPS、ISO、BABIP、K%、BB%、防御率 など |
| 第2弾 | リーグ全体の集計(基準値)が必要な指標 | wOBA、wRC+、OPS+、FIP、球場補正 |
| 第3弾 | 守備・走塁・ポジション補正が必要な指標 | 守備指標、走塁指標、WAR |

指標の簡単な意味:
- 第1弾の指標(打率・出塁率・長打率・OPS・ISO・BABIP・K%・BB%・防御率)の意味は「3. 用語集」を参照。用語集の文章は、指標の定義データ(`src/pennant/data/metrics.json`)の解説と同じにする(テストで照合する。D-097)。
- **wRC+**:wOBA をもとに、リーグ平均を100として打者の得点貢献を表す指標(球場補正込み)。
- **OPS+**:OPS をリーグ平均と比べ、リーグ平均を100として表す指標(球場補正込み)。
- wOBA・FIP・WAR は「3. 用語集」を参照。

- 指標の基準値(リーグ平均など)は、実在の成績表を使わず、一般的な水準の架空値か、シミュレーション自身の結果から作る(D-003 補足)。
- wOBA と FIP は、リーグ全体の結果から決める値(wOBA の重み、FIP 定数)を使う指標のため、第2弾とする(D-018 補足、D-026)。
- 第2弾以降の指標を過去のシーズンについても計算できるよう、第1弾の時点から打席ログに必要な情報を残す(D-026)。

#### 第1弾の集計の範囲(D-067、D-094〜D-098)
- **元の数**(すべて整数で持つ。打席ログと登板の記録から、その都度計算する):
  - 打者:試合、打席、打数、安打、単打、二塁打、三塁打、本塁打、塁打、四球、死球、三振、犠牲フライ、併殺打、打点、得点、盗塁、盗塁死(D-430)
  - 投手:登板、先発、投球回(アウトの数で持つ)、対戦打者、被安打、被本塁打、与四球、与死球、奪三振、失点、自責点、勝利、敗戦、セーブ、ホールド、完投、暴投(D-430)
  - 守備(ポジションごと。D-431):スタメンの試合、守備イニング(チームが守ったアウトの数 ÷ 3)、失策。捕手は盗塁企図(走られた数)・盗塁阻止・捕逸。守備の得点は WAR の計算から。
  - 盗塁成功率 = 盗塁 ÷(盗塁 + 盗塁死)、盗塁阻止率 = 盗塁阻止 ÷ 盗塁企図。暴投の点は自責点、捕逸の点と捕逸で進んだ走者の点は自責点にしない。
  - チーム:得点、失点、勝敗(順位表と一致する)
- **集計の単位**(D-096):第1弾はシーズン通算と試合ごと。月別・期間別、左右別・走者の状況別は後から、ホーム・ビジター別は第2弾で足す。
- **指標の式**(定義データ `metrics.json` の計算式):
  - 打数 = 打席 − 四球 − 死球 − 犠牲フライ(犠打・打撃妨害はない)
  - 打率 = 安打 ÷ 打数、出塁率 =(安打 + 四球 + 死球)÷(打数 + 四球 + 死球 + 犠牲フライ)
  - 長打率 = 塁打 ÷ 打数、OPS = 出塁率 + 長打率、ISO = 長打率 − 打率
  - BABIP =(安打 − 本塁打)÷(打数 − 三振 − 本塁打 + 犠牲フライ)
  - K% = 三振 ÷ 打席(投手は 奪三振 ÷ 対戦打者)、BB% = 四球 ÷ 打席(投手は 与四球 ÷ 対戦打者)
  - 防御率 = 自責点 × 9 ÷ 投球回
  - 分母が 0 のときは、エラーにせず「値なし」とする。
- **規定打席・規定投球回**(D-096):規定打席 = チーム試合数 × 3.1(端数は四捨五入)、規定投球回 = チーム試合数 × 1.0。チーム試合数は、そのチームの消化試合数。
- **自責点**(簡易版。D-095):得点した走者の出塁・進塁に失策が関わっていれば、自責点にしない。関わっていなければ、その走者を出塁させた投手の自責点。
- **打点**(D-095):その打席で生還した走者(本塁打なら打者自身も)の数。併殺打と、失策によって生還した得点は打点にしない。押し出しの四球・死球は打点にする。
- **勝利・敗戦・セーブ・ホールド**(簡易版。D-094):
  - 勝利投手:勝ち越しの得点が入った時点でそのチームの投手として試合にいて、リードが最後まで保たれた投手。先発は5回以上を投げていること。先発が5回に満たない場合は、リードを最後まで保った最初の救援投手。
  - 敗戦投手:決勝点を許した投手。
  - セーブ:勝ったチームの、勝利投手でない最後の投手が、①3点以内のリードで登板し1イニング以上、②同点・勝ち越し点の走者が塁上または打席にいる状況で登板、③3イニング以上(リードを保って終える)、のどれかを満たすとき。
  - ホールド:勝った試合で、勝利投手でもセーブ投手でもない救援投手が、リードがある場面で登板し、リードを保ったまま試合終了前に降板したとき。
  - 公式記録の簡易版で、ごく一部の試合で公式と違いが出る。
- **公式記録のサヨナラ安打の数え直し**は、第1弾では再現しない(D-098)。長打率・OPS・ISO の解説に注記する。
- ランキング(タイトル)は後から作る。

#### 第2弾:wOBA・wRC+・OPS+・FIP(D-063、D-120〜D-128)
- 第2弾は、①指標(試合の計算を変えない)と②球場補正(試合の計算が変わる)の2つに分ける。①の間、球場補正は 1.0(D-120)。
- **RE24**(D-123):打席の前の走者・アウトの状況(24通り)ごとに、その打席からイニングの終わりまでの得点を平均する。サヨナラで打ち切られた半イニングは外す。
- **線形加重**(D-123):結果の種類(四球・死球・単打・二塁打・三塁打・本塁打・アウト)ごとに「打席の後の期待値 − 打席の前の期待値 + その打席の得点」を平均する。失策による出塁は、重みを付けない(アウトと同じ 0)。
- **wOBA**:(重み × 四球・死球・単打・二塁打・三塁打・本塁打の数の合計)÷(打数 + 四球 + 死球 + 犠牲フライ)。重みは「各結果の得点価値 − アウトの得点価値」に、目盛りの倍率を掛けたもの。目盛りは、リーグ全体の wOBA がリーグ全体の出塁率に等しくなるように合わせる。
- **wRC+・OPS+**(D-124):リーグ平均(12球団の合算)を100にする。球場補正は、1シーズン目は 1.0、2シーズン目から前のシーズンまでの結果で推定した値(4.7 節。D-142、D-143。画面の解説に「1シーズン目は 1.0。2シーズン目から、推定した球場補正を含みます」と書く)。
  - wRC+ = ((wOBA − リーグの wOBA)÷ 目盛り + リーグの1打席あたりの得点 +(リーグの1打席あたりの得点 − 球場補正 × リーグの1打席あたりの得点))÷ リーグの1打席あたりの得点 × 100
  - OPS+ = 100 ×(出塁率 ÷ リーグの出塁率 + 長打率 ÷ リーグの長打率 − 1)÷ 球場補正
- **FIP**(D-125):(13 × 本塁打 + 3 ×(四球 + 死球)− 2 × 三振)÷ 投球回 + FIP 定数。FIP 定数は、リーグ全体の FIP がリーグ全体の防御率に等しくなるように決める。係数の出どころは設定で切り替えられる(今は標準値)。
- **基準値と混ぜ方**(D-126):各シーズンの打席ログから求める。シーズン序盤は、前シーズンの値(初年度は試運転の値。D-121)を出発点にし、今シーズンの累積打席数が増えるほど今シーズンの値の比重を上げる(D-091)。
  - 比重 = 累積打席数 ÷(累積打席数 + 定数)。定数の既定値は 20,000 打席(設定値)。シーズンの最後で約75%(143 試合の日程では約 77%。D-435)。
  - 使う値 = 比重 × 今シーズンの値 +(1 − 比重)× 出発点の値。重み・目盛り・リーグ平均・FIP 定数は、すべて同じ混ぜ方。球場補正の推定(②)にも同じ混ぜ方を使う。
  - 翌シーズンの出発点には、今シーズンの最終値を使う。
- **試運転**(D-121、D-122):新規開始のとき、見えない試運転のシーズン(リーグのシードから決めた別のシード)を1回回して、初年度の基準値を求める。実際のリーグの状態には触れない。試運転の成績・打席ログは画面に出さず保存しない。求めた基準値だけをセーブデータに保存する。「速い選択肢」では、設定ファイルの既定値を使う。基準値を持たない古いセーブデータも、既定値で読む。
- 計算はすべて分数で行う(D-127)。
- **指標を足す3つの段階**(D-128):A 定義データだけ / B 元の数を足す / C 打席ログに情報を足す(過去のデータでは「値なし」)。

#### 球場補正(D-064、D-135〜D-138)
- 第2弾②は、②a(球場の倍率を試合に入れる。試合の計算が変わる)と②b(球場補正の推定と指標への反映。試合の計算は変えない)に分ける(D-135)。②a の間、wRC+・OPS+ の球場補正は 1.0 のまま。
- 球場ごとに「本塁打」と「インプレーの安打(BABIP)」の2つの真の倍率を持ち、打席の計算(オッズ比法)の倍率として入れる。各リーグの6球場の平均をちょうど 1.0 に合わせる(D-136)。
- 倍率は、リーグのシードから SHA-256 で導いた別の乱数で、架空の球場に割り当てる(整数の千分率。範囲内で一様。D-137)。実在の球場の数値は使わない。既存の選手・球団の生成の乱数は変えない。
- 真の倍率は隠し情報で、画面には出さない(答え合わせモードはなくした。D-338)。公開用には、球場名・本拠地のチーム・本拠地での実際の結果(試合数・本塁打・得点)だけを出す。セーブデータに保存する(D-138)。
- **推定**(②b。D-140〜D-146):同じチームの本拠地の試合とアウェイの試合(両チーム合計)を比べ、「本拠地の率 ÷ アウェイの率」を生の比とする。複数シーズンを合算し、比重 = 本拠地の打席数 ÷(打席数 + 定数)で 1.0 に向けて縮め、各リーグの6球場の平均を 1.0 にそろえる。定数は、1シーズンのぶれと想定する球場差から決める(D-145)。
  - wRC+・OPS+ に使う球場補正は、得点ベースの1つの値。②c からは、縮めた後の本塁打と BABIP の推定値から「1打席あたりの得点の出やすさ」を換算して作る(真の値側と同じ式。各リーグの平均 1.0。D-147)。縮めるのは本塁打と BABIP だけ(D-148)。直接推定した得点(本拠地 ÷ アウェイの生の比)は球場のページの比較と開発者向けスクリプトに検証用として残す。BABIP 単独の推定は「参考値」と注記する(D-149)。
  - 選手ごとの球場補正は、球場ごとに立った打席数で重みづけした平均(D-142)。
  - 今シーズンには、前のシーズンまでの推定を使う。1シーズン目は 1.0(D-143)。FIP は球場補正をしない(D-144)。
  - 球場 × シーズンの集計は、シーズンの履歴としてセーブデータに保存する(版 5。D-146)。
- 指標に使う補正の値は、結果から推定する(複数年のデータで、平均の1.0に向けて回帰させる)。真の倍率はテスト・確認用に保持し、画面には出さない。
- 最初のシーズンは補正を1.0とし、そのことを注記する。

#### 第3弾:守備・走塁・WAR(D-070)
- **守備**:担当した打球ごとに、リーグ平均の野手との差(アウトにした数の差)を得点に換算する。捕手は、盗塁・盗塁死の得点の逆(リーグ平均との差)と捕逸の得点(リーグ平均との差)も守備に入れる(D-430)。
- **盗塁の走塁**:盗塁・盗塁死の得点期待値の変化からリーグ平均(1 回あたり)を引いた差を、走者の走塁に入れる(D-430)。
- **WAR の部品**:打撃(wOBA 由来、球場補正込み)、走塁(進塁の価値のみ)、守備(打球ごとの差)、ポジション補正(設定値)、控え水準(設定値。初期案は勝率 .290 前後)、1勝あたりの得点(リーグの得点環境から計算)。
- **投手の WAR**:FIP 版と失点版(守備と球場の影響を除いた実際の失点から)の両方を出す。どちらが真の力に近いかを、隠し情報を使って検証できるようにする。
- 第3弾は3つの依頼に分ける(D-155):①選手生成の変更(ポジション別の型の出現割合。4.1 節。D-157)、②打撃・走塁・守備の得点(計算は変えない)、③WAR(ポジション補正・控え水準・1勝あたりの得点・投手の WAR・画面)。
- 守備の得点は打球ごとの記録(担当野手の ID は記録済み)から、走塁の得点は進塁の価値から計算する。ポジション補正と控え水準(初期案は勝率 .290 前後)は設定値。投手の WAR は FIP 版と失点版の両方。1勝あたりの得点はリーグの得点環境から計算する(D-156)。
- **第3弾②:打撃・走塁・守備の得点**(D-160〜D-166。計算本体と開発者向けスクリプトまで。画面は③):
  - 得点期待値表は基準値の RE24(試運転で求め、シーズン中は混ぜる。D-161)。
  - 打撃の得点 =((wOBA − リーグ平均の wOBA)÷ 目盛り +(1 − 球場補正)× 1打席あたりの得点)× 打席数(D-162)。
  - 走塁の得点:打席ごとの得点期待値の変化から「同じ状況(結果の種類 × 打席の前の状況 × 外野への打球か)」の平均を引いた差を、選択の余地があった走者に等分して付ける。打者自身の進塁は入れない(D-163)。
  - 守備の得点 =(実際のアウト数 − 期待のアウト数)× アウト1つの得点の価値。期待はポジション × 打球の種類ごとのリーグ平均のアウト率。球場の倍率と打者の能力は反映しない(D-164)。
  - 集計:選手 × シーズンごとに 3つの得点、ポジションごとの守備の得点・機会・守備アウト数。記録の項目は足さず、保存形式も変えない(D-165)。指紋 (k) を足す(D-166)。
  - リーグ全体の合計は、走塁・守備はちょうど 0、打撃は球場補正なしならちょうど 0(球場補正ありはほぼ 0)。
- **第3弾③a:WAR の計算**(D-167〜D-173。計算本体と開発者向けスクリプトまで。画面は ③b):
  - 1勝あたりの得点 = 4 × 1チーム1試合あたりの得点 ÷ 指数(指数 2 なら 2 × 得点。ピタゴラス勝率。基準値の1打席あたりの得点 × 今シーズンの1試合あたりの打席数。D-170)。
  - ポジション補正(設定値。点/125試合):捕手 +9、遊撃 +6、二塁 +2、三塁 +2、中堅 +2、左翼 −6、右翼 −6、一塁 −10、指名打者 −14。守備アウト数(指名打者は打席数)で按分(D-168)。
  - 控え水準(設定値):野手は1打席あたり、先発・救援は9イニングあたり。リーグ全体の WAR の合計が「勝ち数の合計 − .290 × チーム試合数の合計」に合うよう調整(D-169)。
  - 打者の WAR =(打撃 + 走塁 + 守備 + ポジション補正 + 控え水準)÷ 1勝あたりの得点。投手は FIP 版(球場補正なし)と失点版(球場補正あり。チームの野手の守備の得点を投球回で按分して差し引く)(D-171)。
  - 集計は分数、保存形式は変えない。指紋 (l)(D-172)。
  - ポジション補正の値は多数の世界で測り直してから決める(D-174)。出場量の重みづけで合計 0。値を変えるときは控え水準も同時に調整(D-175)。控え水準・1勝あたりの得点・合計の目標は ③a の値で確定(D-176)。

**将来の目標**(D-025)
- 球種別の深掘り分析(例:この選手のこの球種は被本塁打率が低い)。
- 実装は第3弾(WAR)の後とする。

### 4.6 セーブ・ロード(保存と読み込み)
(D-004〜D-006、D-068、D-083、D-084、D-100〜D-104)
- セーブデータは**1つのファイル**(拡張子 `.sav`。中身は ZIP)にする(D-100)。
  - 中身:状態の JSON(リーグ・球団・選手・シーズンの状態・設定値など)と、シーズンごとの打席ログ。
  - 既定のファイル名は日付(例:`save-20261002.sav`)。球団名はファイル名に自動で入れない。利用者が名前を付けられる。
- 必ず含めるもの:
  - 形式のバージョン番号、保存日時、セーブデータの名前
  - 乱数の初期のシードと、現在の状態
  - そのセーブデータで使った設定値
  - リーグ(球団名・球場名)、選手(見せる能力・球種と、隠し情報の成長タイプ・伸びやすさ・弾道の傾き・生成時の型。隠し情報は画面には出さない)
  - シーズンの現在の日付・勝敗・順位・ローテーションの位置・疲労、試合の結果、打席のログ、各試合の前の状態(1試合を再現するため)
- **保存のしかたは差し替えられる**(D-083、D-101):ローカルのフォルダ(既定は `~/.npb-pennant-simulator/`。設定で変更可)/1ファイルの書き出し・読み込み/ブラウザのファイル選択・ダウンロード。計算本体はファイルを直接読み書きしない。
  - ブラウザでは、利用者がファイルを書き出し(ダウンロード)、読み込むときにファイルを選ぶ。ブラウザ内の自動保存は既定でオフ(D-084)。
- **読み込み時の検証**(D-102):バージョン番号を確かめ、古い版は変換して読む。新しすぎる版・壊れたデータ・手で編集されたデータは、どこが・なぜを日本語で示して読まない。検証が済むまで、今の状態を上書きしない。
- **続きの再現**(D-103):保存して読み込んだ後の続きは、保存せずに続けた場合と同じ結果になる。別の端末・別の Python の版で保存したファイルでも同じ。
- **実名の扱い**(D-104):入力された球団名などは、セーブデータの状態の中にだけ入る。ログ・一時ファイル・既定のファイル名には書かない。暗号化はしないので、セーブデータは共有しない(README の注意)。
- **新規開始と球団名の入力**:球団名を入力してリーグを作る。空欄の球団は架空の初期名にする(D-008)。空白だけ・長すぎる(24文字を超える)・制御文字(画面に出ない特殊な文字)を含む・12球団の中で重複する名前は、理由を示して受け付けない。
- **画面に出す選手の情報**:見せる能力は出す(作り直し①)。隠し情報(成長タイプ・伸びやすさ・弾道の傾き・生成時の型)と、試合の計算の内部の能力は含めない。

### 4.7 操作画面(ブラウザ)
(D-008、D-009、D-080、D-081、D-086、D-106〜D-108、D-111)
- **方式**:ブラウザの中で完結する(Python をブラウザ上で実行する)。サーバーは使わず、計算も画面もブラウザの中で動く。配る場所にはコードと架空のデータだけを置き、実名のデータはサーバーに送らない(D-081)。
- **段階2(最小のブラウザ画面)の操作範囲**は観戦と閲覧(D-080):
  - 新規開始(球団名の入力。空欄は架空の初期名)
  - 日数を指定して進める/シーズンの最後まで進める
  - 順位表/個人成績(並べ替え)/1試合の文章ログ
  - 保存と読み込み
- 操作の種類は計算本体の側で関数として用意し、画面はそれを呼ぶだけの薄い層にする。
- 不正な入力は、理由を表示して再入力を求める。
- 確認用の開発者向けスクリプト(`scripts/`)は残す(CLI の操作画面は作らない)。
- **画面の方針**(D-086):
  - 表を中心にする(グラフは第2弾・F2 でデータが増えてから)。
  - 画面:スタート(新規開始・セーブデータを開く)、自球団の選択、シーズンの進行、順位表、個人成績、選手のページ、試合のページ、保存・書き出し。
  - スマホは縦持ちが基本。表は、左端の選手名の列を固定して横スクロール。広い画面(PC・スマホの横持ち)でも使いやすくする(D-223):新しく作る表の部品は幅に応じて広がり、広い画面では横スクロールなしで全列を表示する(幅の境目は設定値。切り替えは自動)。広い画面では、タブを左の縦の列にし、選手・チーム・試合・球場のページを元の画面の右に並べる(左右 2 列。作り直し④。D-402)。
  - 指標の名前をタップすると、初心者向けの解説が出る。
  - 隠し情報(成長タイプ・伸びやすさ・弾道の傾き・生成時の型)は画面に出さない。
- **画面の作り**(D-107):
  - スマホの縦持ちが基本。下に固定のタブ。画面の色は「ナイター」の 1 つ(作り直し④。D-399)。表示はすべて日本語(指標の略称には日本語名を併記)。
  - 計算は裏(Web Worker)で行い、画面は固まらない。進行(1日・1週間・最後まで)は途中で止められる。
  - 順位表では自球団の行を目立たせる。保存・読み込みは目立つ場所に置く。
  - 新規開始の画面に「実名を入れたデータは共有しない」注意を常に表示する。自動保存はしない。未保存の変更があるまま閉じようとしたら警告を出す。
  - 新規開始の「詳しい設定」で、リーグ(選手の生成)とシーズン(日程と試合)のシードを入れられる。空欄なら毎回ちがう値(D-113)。
  - 新規開始の「詳しい設定」で、リーグ名・球場名(球団の順)を入れられる。空欄は架空の初期名。点検は球団名と同じで、リーグ名の重複はできない(D-409)。
  - 新規開始の「詳しい設定」で、自球団の資金力を 自動・小・中・大・超大量 から選べる(既定は自動。観戦のみでは使わない)。選んだときは、ほかの 11 球団で 大 3・中 6・小 3 を合わせる(超大量は大として数える)。超大量は基準額の 120 倍。単価を求める資金の合計では超大量を大の上限として数え、ほかの球団の年俸に響かないようにする(D-410)。
  - 保存のファイル名は日付だけ(`save-YYYYMMDD.sav`。球団名は入れない)。読み込みに失敗したときは、理由を日本語で表示し、今のゲームはそのまま残す。
  - 2つの依頼で作る(D-106):①土台と進行(新規開始・自球団の選択・進行・順位表・保存と読み込み)、②成績の画面(個人成績・選手のページ・試合のページ・指標の切り替え・答え合わせモード。答え合わせモードは作り直し①でなくした)。
- **画面の仕上げ**(作り直し④。D-399〜D-404):
  - 色:夜の球場のような濃い紺の背景に、金色(強調・自球団)と水色(選んでいるもの・リンク)。暗い色の 1 つだけで、端末の明るい/暗いの設定には従わない。色・文字の大きさ・余白・角丸は CSS の変数で指定する。
  - 上の帯:題(日付)と、保存・メニューの 2 つのアイコン。未保存の変更があるときは保存のアイコンに点。「開く」はメニューの中。
  - 下のタブ:進行・順位・成績・試合・自球団(小さな絵つき)。自球団のタブは自球団のチームのページ(観戦のみのときは出さない)。
  - 球団のマーク:丸の中に球団名の頭文字。色は球団の番号ごとの 12 色(画面だけの飾り)。
  - 進行の画面:上に「自球団 VS 次の相手」の得点板(両球団の勝敗、シーズンの進み具合の棒。シーズンが終わったら最後の試合の相手)。その下に大きな「1日すすめる」、「1週間」「最後まで」。自球団の順位・勝率・ゲーム差(首位なら 2 位との差)を大きな数字で出し、2 以上の連勝・連敗と直近 10 試合の勝敗を添える。直近の日の試合は 2 列のカード。観戦のみのときは得点板の代わりに日付と進み具合。
  - 順位表と個人成績:1〜3 位の順位の数字を金・銀・銅のメダルにする。個人成績の表の上に、並べている指標の 1 位の選手のカード。
  - 個人成績の絞り込み(シーズン・リーグ・チーム・規定到達者だけ)は「絞り込み」の 1 つにまとめて、押すと開く。閉じているときは今の絞り込みを 1 行で出す。並び順の行は出しておく。
  - 選手のページ:上に選手のカード(マーク・名前・ポジション・年齢・投打・所属。背景にポジションの 1 文字)。能力はランクの札と数字(ゲージなし)、右側に特殊能力をまとめる。
  - 表:数字は等幅で右にそろえる。縦線なし、行は薄い横線。並べ替えた列は見出しを水色にし、▲▼ は見出しの文字の左。数値は太字で、ほかの列と同じ右の余白。
  - 広い画面:タブを左の縦の列にする。順位表・成績・試合・自球団から開いた選手・チーム・試合・球場のページは、元の画面の右に出す。何も開いていないときは右に案内。
  - ほかの画面も同じ色・ボタン・表にそろえ、画面の並びと操作は変えない。見た目の変更で指紋は変えない。
- **ロード画面**(D-405〜D-408):
  - 長い待ち(最初の起動の読み込み・新規開始の事前運転と試運転)は全画面のロード画面。上に題(今の作業)・進み具合の棒と割合、真ん中に絵、下にヒントの札(用語集のゲームのルールと指標から数秒ごとに入れ替え)。
  - 真ん中の絵は「球場」(ダイヤモンドの上を走者が塁を回る)か「歴史」(事前運転の年ごとの出来事:目玉の新人・引退した名選手・戦力 1 位の球団)。メニューの「ロード画面」で選ぶ。最初の起動はいつも「球場」。
  - 選択は端末(ブラウザの保存領域)に「stadium」か「history」の 1 つの値だけ覚える。ほかは何も残さない。
  - 短い待ち(画面の切り替え)は、0.3 秒を超えたら前の画面を暗くして、小さなボールと「読み込み中…」を出す。
  - 日を進める・年度の確定・おまかせの待ちは今の形(D-118)のまま。
  - スクロールの棒の場所を常に空けておき、画面によってボタンの位置が変わらないようにする。
  - 「新しく始める」「この内容で始める」は、押した瞬間にボタンの文字の前に小さなボールを回し、押せなくする(押せたことが分かるように。D-411)。
- **能力の見せ方**(作り直し①。D-335、D-338):プロの選手の能力は、選手のページ(上に能力の欄)・成績の「能力」・チームのページの選手一覧で、いつでも見せる。答え合わせモードはなくした。隠し情報は画面にも通信にも出さない。
- **成績の画面**(②。D-114〜D-118):
  - 下のタブは「進行」「順位」「成績」「試合」「自球団」(作り直し④。D-401)。設定は、上の帯のメニューから開く。
  - 個人成績:打撃/守備/投球(D-431)、「基本」「セイバー」「能力」の切り替え(打撃・投球)。守備はポジション(すべて・捕手〜右翼手)を選んで、試合・守備イニング・失策・守備の得点(捕手は盗塁企図・盗塁阻止・阻止率・捕逸も)。守備の規定は、そのポジションでチームの試合数の半分以上スタメン。表は並べた上位 30 人で、続きは「もっと見る」。リーグはいつも 1 つ(両リーグをまとめた表はない。最初は自球団のリーグ)。列の見出しをタップして並べ替え(もう一度で逆順)。規定到達者の絞り込み(既定オン。規定打席 = 試合数 × 3.1、規定投球回 = 試合数 × 1.0)。リーグ・チームの絞り込み。指標名のタップで解説(指標の定義データの解説と同じ文章)。選手名のタップで選手のページへ。
  - 表の既定(D-116、D-130):打者の基本は打率の高い順(試合・打席・打数・安打・本塁打・打点・得点・打率・出塁率・長打率・OPS)、投手の基本は防御率の低い順(登板・先発・勝・敗・セーブ・ホールド・投球回・奪三振・防御率)、打者のセイバーは wRC+ の高い順(打席・wOBA・wRC+・OPS+・ISO・BABIP・K%・BB%)、投手のセイバーは防御率の低い順(投球回・FIP・K%・BB%)。OPS は「基本」の区分(D-130)。
  - 並び順と絞り込みの保持(D-131):打者(または投手)の中で、基本・セイバー・能力を切り替えても、並び順・絞り込み・表示件数を保つ。並び順の指標が表にないときは、名前の隣に固定の列として出す。打者と投手を切り替えたときは、その側の既定の並び順に戻す。状態は保存しない。
  - 「並び順」の選択欄(D-132):表の上に置き、基本・セイバーの全指標と能力の項目から選べる。高い順/低い順の切り替えつき。見出しのタップでも並べ替えられる。
  - 選手のページ:基本情報(年齢・ポジション・投打・所属)、シーズン通算の成績、試合ごとの成績(新しい順)。
  - 試合のページ:日付を選んでその日のスコアの一覧 → 1試合の文章ログ(確認用スクリプトと同じ内容)と投手の成績(勝敗・セーブ・ホールド)。
  - チームのページ:チームの成績(試合・勝・敗・分・得点・失点)と選手の一覧。順位表のチーム名から開く。
  - 進行の画面に、直近の日の全試合のスコアを出し、タップで試合のページへ(D-117)。
  - 「止める」と処理の進み具合のバーは、処理が 0.6 秒を超えたときだけ出し、出したら最低 0.6 秒は表示を続ける。「1日」では出さない。処理中は、ほかの進行ボタンを押せない(D-118)。
  - **能力の表**(作り直し①。D-347):野手は弾道・ミート・パワー・走力・肩力・守備力・捕球、投手は球速・コントロール・スタミナ・変化球。1〜100 の項目はランクつき(例「C 63」)、球速は km/h、変化球は球種ごとの変化量。並べ替えは丸める前の値で行う。
- **第2弾の指標の画面**(D-121、D-122、D-124):「成績」の「セイバー」に wOBA・wRC+・OPS+・FIP を出す(打者のセイバーの既定の並び順は wRC+ の高い順)。表の近くに、前のシーズン(初年度は試運転)の値を混ぜている旨と、今シーズンの比重を出す。新規開始で、基準値を求める進み具合(「リーグの基準値を求めています」)を出す。「詳しい設定」に「試運転で求める(既定)/既定値を使う(速い)」の切り替え。メニューに「指標の解説」ページ(すべての指標を区分別に、式・解説・見るときの注意つきで。指標の定義データから作る)。
- **球場のページ**(②a・②b。D-138、D-140):チームのページの「本拠地」から開く。球場名、本拠地のチーム、本拠地での実際の結果(試合数、本塁打、本塁打/試合、得点/試合。両チームの合計)。今シーズンの本拠地とアウェイを並べた表(本塁打/打席、BABIP、得点/打席。本拠地・アウェイ・比)。推定した球場補正(得点・本塁打・BABIP。得点は本塁打と BABIP の推定から組み立てた値。D-147)は2シーズン目から出し、1シーズン目は「まだ推定できません」と出す。BABIP 単独の推定には「参考値」と注記する(D-149)。(答え合わせモードは作り直し①でなくした)がオンのときだけ、真の倍率(本塁打・BABIP)を出す。試合のページに球場名を出す。wRC+・OPS+ の注記は「1シーズン目は 1.0。2シーズン目から、推定した球場補正を含みます」。FIP は球場補正をしない旨を注記する。
- **WAR の画面**(第3弾③b。D-179):個人成績に「WAR」の切り替え(野手:打席・WAR・打撃・走塁・守備・ポジション補正・控え水準。投手:投球回・WAR(失点版)・WAR(FIP 版))。並び順の保持・固定列・「もっと見る」は既存と同じ。選手のページに「WAR」の切り替え(今シーズンの内訳)、チームのページにチームの WAR の合計(野手・投手別)。用語の説明は表の下。いつでも見える。シーズン途中は「○日目まで」の値。計算はブラウザの中で行い、試合数が変わるまで結果を覚えておく。
- **複数年の画面**(F2。D-182、D-185):シーズン終了後に「年度を確定」(終了前は押せない)→ 確認の画面(戻せないこと、保存への導線)→ 確定 → オフの結果(引退した選手、入団した新人。能力の増減も見せる。作り直し①)。成績のページでシーズン(今シーズン・過去の各シーズン・通算)を選べ、通算には WAR も含む。通算の指標は、元の数から計算できるもの(打率など)は元の数の合計から、基準値に依存するもの(wOBA・wRC+・OPS+・FIP など)は各シーズンの値を打席数(投手は投球回)で加重平均して出す(D-192)。選手のページに年度ごとの成績の推移(1 年ごとの行と、最後に通算の行。1 シーズン目から出し、1 シーズン目の通算は今シーズンと同じ値。事前運転の年の成績は作らない。D-417)。球場のページと wRC+・WAR の注記で、2シーズン目以降の球場補正を確認できる。
- **説明と用語集**(UI の整理②。D-306〜D-313。D-274 を置き換え):
  - 画面には説明ブロックを置かない。残すのは、読み違いを防ぐ 1 行の注意書きだけ(例:「シーズン途中の値(ここまで)」「参考値」「入団直後は、差がマイナスに偏りやすい」)。詳しい理由は用語集に書く。
  - 用語集はメニューの下の方から開くページ。分類(指標:打撃・投球・守備と走塁・WAR、契約とお金、ドラフトとスカウト、試合と球場、画面の見方)と検索ボックス(名前・略語・正式名・意味の文字で探す。略語「wRC」でも日本語「年俸」でも見つかる)。項目の一覧を主役にする。
  - 1 項目は、名前・略語の正式名(あるものだけ)・意味 1〜2 行・式(あるものだけ)・良い向き(あるものだけ)。ゲームのルール(資金、査定、FA 権、ドラフトと市場の方式、天井とふれ幅など)も項目にする。
  - 説明の文は用語集のデータ(`src/pennant/data/glossary.json`)1 か所に持つ。表の見出しの title(指やマウスを重ねると出る説明)、選手のページなどで見出しを押すと出る解説、新規開始の説明バーは、同じデータから引く。指標の式は、計算に使う指標の定義データ(`metrics.json`)から作る。
  - 表の列の名前は、すべて用語集に載せる(テストで確かめる)。指標や用語を足すときは、用語集にも 1 項目足す。
  - **新規開始の説明バー**(D-313):新規開始の設定には常に出る説明を置かない。設定の項目(球団名・自球団・シード・基準値の求め方・スカウト評価のずれなど)を選んでいる間だけ、画面の下のバーに、その項目(選んだ選択肢)の説明を 1〜2 行で出す。選び直すと中身が入れ替わり、別の設定に移るとその設定の説明に切り替わる。バーは下のタブや「始める」のボタンを隠さない。設定の画面から離れると消える。ほかの画面にはまだ使わない(広げるかはデザインの見直しで決める)。
- **開発者向けの測定ページ**は、本番の画面とは別の場所(`/dev/`)に置く(D-111)。

### 4.8 球団経営
(D-019、D-075〜D-079)
- 対象:ドラフト、自由契約、FA、契約更改、トレード。
- プレイヤーは GM の視点。獲得・放出・契約はプレイヤーが自分で決める。
- 試合中の采配は自動。スタメンと打順だけは自球団が決められる(D-373)。
- 他球団の判断ロジックは差し替え可能にする。

#### 段階(D-075)
| 段階 | 内容 |
| --- | --- |
| F3-1 | ドラフトと自由契約(契約・年俸なし) |
| F3-2a | 契約の土台:年俸・契約年数・お金のルール 4 段階・予算(D-229) |
| F3-2b | 契約更改と志望の判定(単年が基本・複数年・志望。D-242〜D-253) |

#### 資金(作り直し②。D-339、D-353〜D-355。お金のルールの 4 段階を置き換え)
- お金のルールの選択はない。球団ごとに「資金」(支配下 70 人の総年俸に使える上限)を持つ。球団の規模は 大 3・中 6・小 3 球団(新規開始のシードで割り当て)。規模の基準額は 大 48 億・中 40 億・小 32 億円(基準 40 億円 × 1.2・1.0・0.8。設定値)。球団ごとの規模と資金は公開情報。
- 資金は毎年のオフの最初に、前のシーズンのリーグ内の順位で増減する:1 位 +5%・2 位 +3%・3 位 +1%・4 位 −1%・5 位 −3%・6 位 −5%(設定値)。規模の基準額の 0.85〜1.15 倍に収める(D-354)。
- 総年俸が資金を超える契約は結べない(FA・市場の提示。あなたも AI も)。ドラフトの指名(D-396)と、年俸が最低年俸の契約(最低人数の補充・市場の最低年俸の選手)は資金に関わらず結べる(D-391、D-394)。「収入と支出」は後の球団経営の段階。

#### 契約と年俸(F3-2a。D-232、D-233、D-236。作り直し②で見直し)
- 選手ごとに、年俸(架空の「万円」)と契約の満了シーズン、年俸の履歴を持つ。契約年数は 1〜5 年。
- 見込みの WAR(D-356):成績の分 = 直近 3 シーズンの WAR の加重平均(新しいほど重い。出場の少ない年は重みを小さく)、能力の分 = 見せる能力の平均から求めた WAR の目安(関係はリーグの実測から求めた設定の表)。2 つを、成績の重み(出場の量)と能力の重み(満の出場 0.5 シーズン分。設定値)で混ぜる。出場が多いほど成績で、少ないほど能力で決まる。30 歳以上は年齢で割り引く。伸びやすさ・成長タイプ・型などの隠し情報は使わない。
- 年俸 = 最低年俸 + 単価 × 見込みの WAR(下限は最低年俸。丸めは設定値)。ドラフトの新人は巡ごとの年俸の表。
- 単価(1 WAR あたり)は毎年のオフに求め直す:単価 = (資金の合計 ÷ 1.1 − 最低年俸の合計)÷ リーグの見込みの WAR の合計(D-355)。総年俸の平均は資金の 9 割ほど。
- 複数年契約(D-360):FA の契約(提示の年数)と、主力級(見込みの WAR 2.0 以上・32 歳以下。設定値)の更改(2.0 以上で 2 年、3.0 以上で 3 年)だけ。ほかの更改・ドラフトの新人・市場・最低人数の補充は 1 年。複数年のあいだは査定を飛ばす(年俸は固定)。
- 手放した選手の残りの契約は消える(違約金なし。D-236)。
- 画面:選手のページに契約(年俸・契約年数・残り年数・年俸の履歴。他球団の選手も公開情報)。チームのページに総年俸・資金・使用率と年俸の高い順の表。

#### 契約更改(作り直し②。D-340、D-357〜D-361)
- 毎年のオフ、契約が満了した全員が更改の対象。複数年契約の途中の選手は対象外。延長契約・年俸調停はない。
- 査定:全球団とも、満了した選手の来季の年俸を見込みの WAR から自動で決め、選手は受ける(断る・再提示はない)。1 年で下がるのは前の年俸の 25% まで(前の年俸の 75% を下回らない。D-357)。上がる幅に上限はない。
- FA 権保持者(D-359。③ までのつなぎ):契約が満了した FA 権保持者は、確率で宣言する(見込みの WAR が高いほど高い。設定値)。宣言しなければ査定どおりに更改する。目標は宣言がリーグ全体で年 15〜35 人、移籍の成立が年 8〜12 人(D-384、D-388)。
- 資金の超過(D-361):更改の後に総年俸が資金を超える球団は、契約の段階で超過を解消する。AI は年俸のうち最低年俸を超える分が見込みの WAR に比べて大きい選手から外し、最低人数を守ったままでは解消できないときは最低人数を割っても外す(不足は完了のときに市場の売れ残りから最低年俸で取る。D-391)。あなたの球団は自分で選び、超過のままでは「次の手続きへ」が押せない(「この段階をおまかせ」は AI と同じ方針)。
- 事前運転(新規開始の 25 年)でも同じ査定で更改する(宣言と FA は行わない。D-254)。
- 保存形式は版 15(球団の規模と資金。お金のルールはなくした)。版 14 以前は読み込まない(D-362)。
- 作り直し③で保存形式は版 16(志望をなくし、ドラフトの入札の状態と評価の形)。版 15 以前は読み込まない(D-371)。

#### FA で選手が選ぶ方法(作り直し③。D-365〜D-367)
- 選手は受けた提示ごとに点数を付け、最も高い提示を選ぶ(全選手に共通の式。選手ごとの志望はない。値は設定値・仮置き):
  - 点数 = 年俸 ×(元の球団の提示なら 1.1。愛着)÷(算定年俸 × 期待の倍率)− 1 + 年数の加点 + 0.10 × 出場機会 + 0.05 × 勝てるチーム + 小さな乱数(標準偏差 0.03)
  - 年数の加点:2 年目から 1 年ごとに 0.03(27 歳を超えると 1 歳ごとに 0.005 ずつ大きく)。出場機会:提示した球団の同じポジションで自分より評価の高い選手の数から(−1〜1)。勝てるチーム:提示した球団の前年のリーグ内の順位(1 位 +1 〜 最下位 −1)。
  - 最も高い点数が −0.15 未満なら選ばず、次のラウンドを待つ。同じ提示には同じ答え(乱数は手続きのシードから)。
- FA のブレーキは、支配下 70 人の枠と、出場機会の項(D-365。D-077 を置き換え)。
- 宣言は、見込みの WAR が高いほど確率が上がる(年齢・チームの状況は使わない。D-366)。補償はなし(D-367)。

#### FA(F3-2c。D-257〜D-264)
- FA 権:一軍に登録されたシーズン(シーズンの最初に選ばれる一軍 29 人に入ったシーズン)の通算が 7(設定値)で取得。宣言したら、移籍・残留にかかわらず 0 から数え直す。新規開始の初期選手と旧版の選手は、年齢と履歴から補う(D-264)。
- 宣言:契約が満了した FA 権保持者は、確率で自動で宣言する(あなたは止められない。上の「契約更改」。D-359)。
- オフの順番:加齢・能力の更新・引退 → 資金の増減 → 契約更改 → 資金の超過の解消 → 自由契約 → **FA** → ドラフト → 市場(年俸は自動、順番に獲得。D-370)→ 最低人数の補充(D-391)。
- FA 市場:提示ラウンド制で 3 ラウンド(設定値)。各ラウンドで全球団(あなたと AI)が年数(1〜5)と年俸を提示する。選手は受けた提示から点数(上の「FA で選手が選ぶ方法」)が最も高いものを選ぶ。決まらなければ次のラウンド、3 ラウンドで決まらなければ自由契約市場へ。元の球団も同じ条件で提示する(愛着の分だけ有利)。補償はなし(差し替え口は残す)。1 球団 70 人、総年俸は資金まで。
- AI:一軍に入る見込みがあり、見込みの WAR が設定値(仮置き 0.3)以上の選手を、1 ラウンド 3 人まで(設定値。自動 FA のときは候補が多いので 8 人まで。D-388)。年俸は算定 × ラウンドの倍率(1.0・1.1・1.2)。「おまかせ」は AI と同じ方針。
- 画面:「FA」の段階(表:名前・ポジション・年齢・前の所属・成績・算定年俸・状態。並べ替え・絞り込み)、提示のパネル(年数・年俸・「+5%」「+10%」「−5%」)、「ラウンド 1/3」の表示、結果の一覧。選手のページに一軍登録のシーズン数と FA 権。
- 保存形式は版 12。FA の途中でも保存・再開できる。版 11 以前も読める(D-263)。
- **主力級の期待**(D-322〜D-325):FA 権を持つ選手は、見込みの WAR が高いほど「自分の価値は算定より高い」と考える。FA 市場の点数で、年俸の基準を 算定年俸 × 期待の倍率 にする(倍率は見込みの WAR が高いほど大きく、上限あり。設定値)。FA 市場の AI は、主力級に期待の倍率を考えた年俸で提示する(資金の範囲で)。期待の倍率は画面に出さない。(更改での引き留めは作り直し②でなくした。D-359)

#### オフの手続きの枠と契約の画面(UI の整理①a。D-270〜D-273)
- 判断の画面の原則(D-270):表が最初の画面の 6 割以上、操作は最大 2 行、判断に使う列を左から、説明ブロックを置かない、同じ意味の操作を重ねない。
- 段階のタブは 5 つ:**契約**(契約更改と自由契約をまとめたもの)・FA・ドラフト・市場・完了。折り返さない。今の段階の名前を大きく出す。
- 状態バー(1 つ):段階ごとの要約(契約:人数と状態の内訳。FA:ラウンド・宣言・契約・空き枠。ドラフト:巡と順番・候補の人数・人数。市場:提示・契約・空き枠)、資金(総年俸と使用率)、主ボタン。FA・ドラフト・市場では、段階の操作(「ラウンドを締める」「次の自分の番まで進める」「パス」「市場を締める」)も状態バーに置く。
- ボタン(D-271):主ボタン「この段階をおまかせ」は、今の段階だけを AI の方針で自球団の分も代行して進め、自球団の分として何をしたかの一覧を出し、次の段階の入口で止まる(市場では完了まで進めて結果を出す)。「次の手続きへ」は自分の操作を終えて進む(AI の代行はしない。FA では自球団は追加の提示をしない。ドラフト・市場の自分の残りの番はパス)。「全部おまかせ」は上のメニューの中(確認つき。やり直せない。未保存の変更があれば保存を案内)。
- 契約の画面(D-272、D-358):自球団の全選手を 1 つの表に出す。列は左から 名前(固定)・選んだ指標(既定は WAR)・状態・新しい年俸・増減(前の年俸との差)・ポジション・年齢・今の契約(年俸と残り年数)。絞り込みはポジション(全員・投手・捕手・内野手・外野手)と状態(全部・更改済・FA 宣言・自由契約・契約中)。「全員」では共通の列(WAR・年齢・ポジション・年俸・出場量)だけ、投手・捕手・内野手・外野手では種類の指標(基本・セイバー・WAR)を選べる。並べ替えは列見出しのタップ(初期は WAR の低い順)。更改は段階の始めに自動で済んでいる。選手をタップすると、その選手の契約のパネル(前の年俸・新しい年俸・年数・「自由契約にする」。資金と総年俸)。複数年契約中の選手も自由契約にできる(残りの契約は消える)。資金を超えていなければ「次の手続きへ」が押せる。AI 球団の資金の超過の解消と自由契約は、契約の段階の終わりに行う(内部の順序は 更改 → 資金の超過の解消 → 自由契約)。
- 旧版で「自由契約」の段階にいるセーブは、「契約」の段階として再開する。保存形式は版 12 のまま。

#### FA・ドラフト・市場の画面(UI の整理①b。D-295〜D-301)
- 3 つの画面に判断の画面の原則(D-270)を当てはめる(D-296)。操作は最大 2 行(状態バーと絞り込み)。説明ブロックは置かない。列は判断に使う順に左から並べ、名前と並べ替えた列は固定する(広い画面では固定しない)。並べ替えは列見出しのタップ(もう一度で逆順)。
- 絞り込みは 1 本:全員・投手・捕手・内野手・外野手(野手/投手の切り替えはない)。「全員」では共通の列だけ、投手・捕手・内野手・外野手を選ぶと、その種類の指標(基本・セイバー・WAR)を選べる。2 シーズン目以降は今季・通算も選べる。
- 加入後の序列(D-297):自球団の同じポジションで何番手になるか(自球団の評価で、自分より評価の高い選手の数 + 1。FA の点数の出場機会と同じ計算)。一軍の枠の目安に入る序列は印を付ける。
- 自球団の状況のパネル(D-298):状態バーを押すと開く。ポジション別の人数(と人数の目安・手薄の印)、主な選手と WAR・年齢、空き枠、予算。FA・ドラフト・市場で開ける。
- FA:列は 名前(固定)・選んだ指標(既定は WAR)・年齢・ポジション・加入後の序列・算定年俸・出場量・前の所属・状態。ラウンドの表示と「ラウンドを締める」は状態バー。名前を押すと提示のパネル。
- ドラフト(D-299、D-368、D-369、D-418):列は 名前(固定)・見立ての総合(投手・捕手・内野手・外野手を選んだときは見立ての能力の各項目と特殊能力)・年齢・出身・ポジション・加入後の序列。名前を押すと、見立ての能力の一覧も出す。手薄なポジションに印。「おすすめ」の印は付けない。絞り込みの既定は「未指名だけ」。1 巡目は名前を押すと「入札する」のボタン、入札の後に抽選の結果を出す。2 巡目からは「次の自分の番まで進める」「パス」は状態バー、名前を押すと「指名」のボタン。
- 市場(D-370):列は 名前(固定)・選んだ指標・能力(総合)・年齢・ポジション・加入後の序列・年俸(自動)・出場量・前の所属・状態。名前を押すと、能力と「獲得を希望する」のボタン(希望の順が優先の順)。「市場を締める」(状態バー)で、前年の順位が低い球団から順に 1 人ずつ獲得する。
- 契約の画面の列は、名前(固定)・選んだ指標・状態・今回の提示・ポジション・年齢・今の契約・出場(D-284)。
- 「この段階をおまかせ」は、ドラフトと FA の段階だけ確認を出す(D-284)。
- 選手の志望はなくした(D-365)。
- 保存形式は版 13(市場の提示の状態)。版 12 以前も読める。旧版で市場の段階(指名の途中)にいるセーブは、新しい提示の方式で再開する(それまでに獲得した選手はそのまま)。

#### オフの手続き(F3-1。D-198〜D-207)
- 操作する球団は 1 つ(新規開始で選ぶ「自球団」)。選ばない場合は観戦のみで、オフの手続きはすべて自動で進む(D-198)。
- 年度の確定の後、加齢・能力の更新・引退(自動)→ **自由契約**(球団が手放す)→ **ドラフト** → **自由契約市場からの獲得** → **最低人数の補充**(市場の売れ残りから。D-391)の順に進む(D-201)。手続きは保存できる状態として持ち、途中で保存・再開できる。「おまかせ」で残りを自動で進められる(D-207)。
- **自由契約**:操作する球団は選手を選んで手放せる(確認の画面つき。最低人数を割る場合は警告)。AI 球団は、自球団のスカウト評価が低い選手を上限(設定値。仮置き 3 人)まで手放す。手放された選手は市場へ。
  - 自由契約の画面(D-222):自球団の選手を野手・投手に分けて、名前(固定列)・ポジション・年齢・打席(投手は投球回)と、選んだ成績(基本・セイバー・WAR。2 シーズン目以降は今シーズン・通算を選べる。)の列を出す。全部の列で並べ替えでき(初期は WAR の低い順)、並び順の保持と並べ替えた指標の固定表示は個人成績と同じ。ポジション別の絞り込み(先発・救援 / 捕手・内野手・外野手)。手放す印を付けるたびに、ポジション別の残り人数と最低人数を出す。市場の画面にも同じ表示を足す(手放された選手は成績も出る)。並べ替え・絞り込み・切り替えの状態は、手続きの画面を行き来しても保つ。
- **ドラフト**(D-202、D-203、D-369):1 巡目は全球団が同時に 1 人ずつ入札し、同じ候補に入札が重なったら抽選で 1 球団に決める。外れた球団は残りの候補から入札し直す(全球団が決まるまで)。2 巡目からは前年の成績(勝率)が低い球団から順に指名し、巡ごとに順番を逆にする(往復)。巡数は 1 球団 10 巡まで(設定値)。何人取るかは球団が決め、一度パスしたら、その年の指名は終わり(選択終了。1 巡目の入札をしなかったときも同じ。D-397)。AI 球団は、支配下が人数の目安(65 人くらい)に届くまで指名し、届いていても最低 4 人は指名する。候補は 120 人(10 巡 × 12 球団 × 1.0。設定値)を、既存の新人の生成で作る(校正の定数を足す。ポジションの構成は人数の目安の比率、年齢は新人の分布)。指名できるのは空き枠(上限 70 人)の分まで。空き枠がない球団はパス(資金に関わらず指名できる。D-396)。ポジション別は、一軍を組むのに必要な最低人数(先発 6・救援 8・捕手 2・その他の各ポジション 1・野手 15)だけ守る。指名した時点で入団する(入団拒否なし。年俸は巡ごとの表)。
- **自由契約市場**(D-204、D-343、D-370):手放された選手と、FA で決まらなかった選手が並ぶ(指名されなかった候補は市場に出さず、リーグを去る。D-398)。年俸は算定の年俸 × 市場の割合(仮置き 0.3。手放された選手は安く結べる。最低年俸を下回らない。D-386)の 1 年で自動、選手は断らない。各球団(あなたと AI)が獲得の希望を出し(あなたは入れた順が優先の順。AI は空き枠の分まで最大 10 人、一軍か控えに入る見込みの選手を、見込みの WAR の高い順に。D-386)、市場を締めると、ドラフトの 2 巡目以降と同じ順(前年の勝率が低い球団から。周ごとに往復)で、各球団が希望のうち残っている最初の選手を 1 人ずつ獲得する。空き枠・資金が足りない選手は飛ばす(最低年俸の選手は、自動補充と同じく資金に関わらず獲得できる。D-386)。1 周目で誰も獲得しなくなったら、売れ残った選手を最低年俸で AI 球団が獲得する 2 周目を行う(空き枠の分まで。選び方は 1 周目と同じ。あなたの球団は加わらない。D-389)。決まらなかった選手は、そのオフの終わりにリーグを去る。新規開始の事前運転も同じ方式。
- **支配下の人数**(D-391):70 人は上限で、下回ってもよい。新しく作った選手で 70 人まで埋める「自動補充」はしない。
  - AI 球団は 65 人くらいを目安に取る(市場の 2 周目で、65 人に届くまでは、見込みの WAR の高い選手から最低年俸で取る。65 人を超える分は FA と同じ基準の選手だけ。D-395)。
  - **最低人数の補充**:オフの終わりに、一軍に必要な最低人数(ポジションごと)を割る球団は、育成選手に同じポジションの選手がいれば先に支配下に上げ、足りなければ市場の売れ残りから最低年俸(1 年)で取る(あなたの球団も自動。資金に関わらず。前年の順位が低い球団から)。同じポジションの選手がいなければ、同じ投手・野手のほかのポジションの選手で代用する。投手・野手が市場に 1 人もいないときだけ、試合が組めなくなるのを防ぐために新人を作る(起きない想定)。
  - 70 人のまま最低人数が足りない球団は、評価の低い選手を外して枠を空ける。
- AI 球団はプレイヤーと同じスカウト評価の仕組み(球団ごとのずれ)で判断する(D-205)。判断の方針は差し替え可能。

#### トレード(D-378)
- **形**:支配下の選手どうしの交換(1〜3 人 対 1〜3 人)。お金は付けない。育成選手は対象外。
- **時期**:シーズン中は全日程の 3 分の 2(設定値)の日まで。オフはオフの手続きの「トレード」の段階(市場の後・完了の前)。
- **出せない選手**:そのオフに入った選手(FA・外国人市場・ドラフト・育成から支配下・市場・トレード)は、次のシーズンの開幕まで出せない。
- **成り立つ条件**:交換の後も両球団が 70 人以内・最低人数(ポジション)を守り、総年俸が資金を超えない。
- **あなたから持ちかける**:相手の球団と、出す選手・欲しい選手(各 1〜3 人)を選んで「提案する」。相手(AI)はその場で受けるか断るかを答え、理由を一言出す(例:「釣り合わない」「そのポジションは足りている」)。
- **AI の判断**:選手の価値 = 見込みの WAR − 年俸 ÷ 単価(年俸の分)、若い選手(28 歳以下)は少し上乗せ。受け取る価値の合計 + 手薄なポジションが埋まる加点 が、出す価値の合計 + 余裕(設定値)以上なら受ける。
- **外国人の人数**:AI は、外国人が 3 人(設定値)より少なくなる交換は受けない(偏りを防ぐ。D-387)。
- **AI どうし**:シーズン中は決まった日(期限までに数回)、オフはトレードの段階で、年に数件ほど成立する。
- **AI からの提案**:シーズン中に 2〜3 件、オフに 1〜2 件ほど、AI 球団からあなたへ「この選手とこの選手を交換しませんか」と提案が来る。トレードの画面と進行の画面のお知らせに出し、受けるか断るかを選ぶ(次の提案の日・期限・段階の終わりで消える)。
- **シーズン中のトレード**:成立したら、両球団の一軍を選び直す。成績は選手ごとに通算し、所属は今の球団で表示する。試合のページの再現のため、トレードした球団の試合ごとの一軍の顔ぶれを記録する。打順で自分が組んだスタメンに出た選手が入っていれば、AI が組み直す。
- **記録**:トレードの履歴(年・日・球団・選手)を残し、入退団の記録とトレードの画面で見られる。
- 保存形式は版 20(D-379)。版 19 のセーブデータは、トレードなしとして読む。

#### 現役ドラフト(D-380)
- **時期**:オフの手続きの「現役ドラフト」の段階(トレードの後・完了の前)。新規開始の設定で「なし」にできる(D-381)。
- **形**:全球団が 2 人ずつ候補を出す。前年の順位が低い球団から順に 1 人ずつ指名する。どの球団も 1 人出て 1 人入る(指名できるのは、まだ選手を取られていない、ほかの球団の候補だけ。最後の球団が自分の候補しか選べない形にならないようにする)。
- **出せる選手**:そのシーズンの最後の一軍に入っていなかった支配下の選手。ただし、外国人・育成選手・このオフに入った選手・年俸が最低年俸の 3 倍(仮置き)を超える選手は出せない。出すとポジションの最低人数を割る選手も出せない。
- **あなたの球団**:出す 2 人を表から選ぶ(AI のおすすめが最初から入っている)。候補を決めると、順番に指名が進み、あなたの番では候補の表から 1 人選ぶ(AI のおすすめつき)。「次の手続きへ」「この段階をおまかせ」は、残りを AI の方針で決める。
- **AI 球団**:出せる選手のうち価値の低い 2 人を出す。指名は、手薄なポジションを少し重んじて、価値の高い選手を取る(トレードの価値。D-378)。
- **契約**:年俸と年数はそのまま引き継ぐ。1 人出て 1 人入るので、資金の決まりは当てない。
- 記録は入退団の記録(現役ドラフト)と、段階の結果の一覧に出す。事前運転でも行う。

#### 仕組みの選択肢(D-381)
- 新規開始の「詳しい設定」で、次の 4 つを選べる。始めた後は変えられない(セーブデータに残る)。
  - **自動 FA**(既定:なし。D-390):FA 権を取ったオフに、契約が残っていても必ず FA になる(契約は終わる。宣言の確率は使わない)。その後は、契約が満了するたびに FA。FA 権を一度も取っていない選手は今までどおり更改する。外国人選手も同じ。FA 市場の 1 ラウンド目に、元の球団が残留の提示をする(AI 球団は資金の中で全員に。ドラフトの上位の巡と外国人の分は資金に残す。D-395。あなたの球団は、査定の年俸と年数の提示が最初から入っていて、取り消せる)。ほかの球団の提示と選手の選び方は今までどおり。決まらなかった選手は自由契約市場へ。新規開始の事前運転は FA を行わないので、今までどおり更改する。
  - **現役ドラフト**(既定:あり)。
  - **トレード**(既定:あり):なしにすると、シーズン中もオフもトレード・提案がない(トレードの段階も飛ばす)。
  - **外国人・育成**(既定:あり):なしにすると、新しいリーグに外国人選手と育成選手がいない。外国人市場と育成ドラフトもない。
- 保存形式は版 21(D-382)。版 20 のセーブデータは、既定の選択肢(自動 FA なし、ほかはあり)として読む。

#### 設備(D-383)
- 球団ごとに 3 つの設備を持つ。段階は 1〜5(段階 3 が標準)。
  - **練習設備**:毎年のオフの能力の伸び(年齢による増える分)を、段階 1 で 30% 小さく、5 で 30% 大きくする(1 段階ごとに 15%)。
  - **トレーナー・医療**:年齢による能力の下がり方を、段階 5 で 30% 小さく、1 で 30% 大きくする。
  - **育成施設**:育成選手の伸びを、段階 1 で 50% 小さく、5 で 50% 大きくする(1 段階ごとに 25%)。
  - 揺れ(毎年の偶然の増減)は設備で変わらない。
- **維持費**:1 つの設備あたり毎年 段階 1:0・2:5,000 万・3:1 億 5,000 万・4:3 億 5,000 万・5:7 億円(仮置き)。3 つの合計の分だけ、その年の資金のうち年俸に使える額が減る(総年俸の上限 = 資金 − 維持費)。
- **変え方**:オフの契約の段階の「設備」の欄で、何段でも上げ下げできる。変えると、年俸に使える額がすぐ変わる(超えたら、自由契約で減らすまで次の手続きへ進めない)。効きは、次のオフの能力の更新から。
- **新規開始**:球団の規模に応じて 大 3・中 2・小 2。
- **AI 球団**:契約の段階の始めに、資金に応じて段階を決める(資金が多いほど高い。基準は設定値)。事前運転でも同じ。
- 設備の段階は、チームの画面と契約の段階で見られる(全球団)。
- 保存形式は版 22(D-385)。版 21 のセーブデータは、規模に応じた初めの段階として読む。
- 保存形式は版 23(D-393)。選手ごとに「FA 権を取ったことがある」印を持つ(自動 FA で使う)。版 22 のセーブデータは、印なしとして読む。

#### 育成選手(D-375)
- 支配下(70 人。試合に出られる)とは別の枠で、1 球団 20 人まで(設定値)。試合には出ない(一軍・二軍のどちらにも入らない)。能力は毎年のオフに支配下と同じく伸び縮みする。能力は見える。
- **育成ドラフト**:ドラフトが終わった後、指名されなかった候補から指名する(育成ドラフトでも指名されなかった候補はリーグを去る。D-398)。順番はドラフトの 2 巡目以降と同じ(前年の順位が低い球団から、巡ごとに往復)。巡数は設定値(仮置き 4 巡)。育成の空きがない球団は飛ばす。あなたはパスもできる。AI 球団は育成が目安(仮置き 10 人)より少なければ、評価の高い若い候補(22 歳以下)を指名する。
- 年俸は育成の年俸(固定。仮置き 300 万円)。総年俸に入るが、低い額なので資金を超えていても結べる。契約更改はしない(毎年同じ年俸)。
- **支配下に上げる**:あなたは市場の段階で、70 人の空きの分だけ、育成選手を選んで支配下に上げられる(年俸は最低年俸、契約 1 年。資金の中だけ。AI も同じ。最低人数の補充で上げるときは資金に関わらず上げる)。AI 球団は市場を締めるときに、空きがあれば、育成で 1 シーズン以上過ごした選手のうち、支配下の最も低い選手より評価が高い選手を上げる。オフの終わりの最低人数の補充は、育成選手のうち総合の高い選手を先に上げ、足りない分は市場の売れ残りから取る(D-391)。
- 育成で 3 シーズン(設定値)過ごしても上がらなければ、年度の確定で自由契約になり、リーグを去る(引退と同じく一覧に出す)。
- 球団の選手一覧・選手のページで「育成」と分かるようにする。

#### 外国人選手(D-376)
- 選手は「外国人」の区分を持つ。新規開始のとき、各球団に 5〜6 人(70 人の内数)。
- 一軍に登録できる外国人は 4 人まで(投手・野手の組み合わせは自由)。抱える人数に上限はない。
- **外国人市場**:オフの手続きの「外国人」の段階(FA の後・ドラフトの前)。毎年のオフに候補(設定値。仮置き 24 人)を作る。年齢は 25〜33 歳、能力は一軍の主力〜控えくらいで、ふれが大きい。
  - 見せ方はドラフト候補と同じ:能力の数字と特殊能力を見立てで見せる(D-418)。年齢・左右・ポジションは正確に見える。
  - 年俸は内部の評価の段階ごとの表(仮置き A 2 億・B 1 億 2000 万・C 7000 万・D 4000 万・E 2500 万円)、契約は 1 年。資金を超える獲得はできない。ただし外国人が 3 人(設定値)より少ない球団は、年俸 4000 万円(設定値)以下の候補なら、3 人になるまで資金に関わらず獲得できる(D-387)。
  - 獲得は自由契約市場と同じ方式:各球団が獲得の希望を出し(あなたは入れた順が優先)、締めると前年の順位が低い球団から 1 人ずつ、希望のうち残っている最初の選手を獲得する。選手は断らない。AI 球団は外国人が目安(仮置き 7 人)より少なければ、評価の高い候補を 3 人まで希望する。獲得の順は、外国人が少ない球団が先(目安以上は同じ扱い。その中は今までの順。D-387)。決まらなかった候補はリーグを去る。
  - 入団した後は本当の能力が見え、契約更改・FA は他の選手と同じ。
- オフの手続きの順:契約 → FA → 外国人 → ドラフト(育成ドラフトを含む)→ 市場 → 完了。事前運転でも外国人市場と育成ドラフトを行う。
- 保存形式は版 19(D-377)。版 18 のセーブデータは、全員を支配下・日本人として読む。

#### スカウトの見立て(作り直し③。D-200、D-212、D-368。見せ方は D-418〜D-420)
- ドラフト・育成ドラフト・外国人の候補は、能力の数字(野手:弾道・ミート・パワー・走力・肩力・守備力・捕球、投手:球速・コントロール・スタミナ・変化球)と特殊能力を、自球団のスカウトの**見立て**で見せる。見立ては下の内部の推定値で、ふれ幅は見せない。同じ候補は何度見ても同じ(シードから導く)。球団ごとに違う。入団すると本当の数字になる。評価(A〜E)とスカウトの一言は画面に出さない(内部で使う)。
- 特殊能力の見立て(D-419):持っている特殊能力を確率で見落とし、持っていないもの(持っているものと別の対)を確率で 1 つ「ある」と見る。確率は項目の誤差(√(共通² + 項目ごと²))1 点あたり 見落とし 5%・ないものを見る 4%(上限 60%。仮置き。`data/draft.json` の `scouting.skills`)。乱数はほかと別の系列。
- 内部の推定値 = 真の現在の能力 + **共通の見誤り**(選手 × 球団ごとに 1 つ。全項目に同じ値)+ **項目ごとの見誤り**(項目ごとに独立)の 2 層(D-212)。2 つの大きさ(標準偏差)は設定で、ずれの段階(小・中・大。既定は中)ごとに持つ。仮置き:共通 2・4・6、項目ごと 約 2.2・3.0・5.3。球団ごとの値で持てる形(既定は全球団同じ。D-200)。AI 球団も同じ推定値で判断する(D-205)。
- 評価(内部。AI の判断と外国人の年俸の段階に使う):ピークまでの伸びを見込んだ総合(今の能力 + 年齢カーブと伸びやすさから見込んだ伸び)に、総合の誤差と同じ大きさの見誤り(現在の能力の見誤りとは別の乱数)を足した値を、そのオフの候補全体の上位 10%(A)・次の 20%(B)・次の 30%(C)・次の 25%(D)・下位 15%(E)で段階にしたもの(相対評価。仮置き。D-218)。少し外れることがある。
- スカウトの一言(内部に残すだけで、画面には出さない):項目ごとの推定値のうち、同じ役割(野手・投手)の候補の平均より目立って高い項目を 1〜2 個選び、短い言葉にする(例:「速球が武器」「守備範囲が広い」)。2 つ目は 1 つ目と同じくらい目立つときだけ。目立つ項目がなければ「目立つ長所はまだない」。言葉は `data/draft.json` に置く。
- 隠し情報(成長タイプ・伸びやすさ・生成時の型)はそのまま隠す。年齢・出身・左右・ポジションは正確に見える。
- 入団した選手には、入団時の評価(項目ごとの推定値と、特殊能力の見立て)を保存する。入団した後は本当の能力が見える(D-335)。ドラフト・育成ドラフト・外国人で入った選手は、選手のページに「入団時の見立て」を今の数字と並べて出す(D-420)。特殊能力の見立ては D-419 の後に入団した選手から(前からの選手は「記録なし」)。保存形式は変えない(版 24 のまま)。

#### 記録室(D-422、D-423)
- 下のタブの「記録」(6 つ目)。中は 歴代の順位と優勝・年ごとのタイトル・通算記録・補強の記録 の 4 つを切り替える。観戦のみでも見られる。計算本体は読むだけ(保存形式・指紋は変えない)。
- **歴代の順位と優勝**:終わったシーズン(年度を確定したシーズン)を選び、リーグごとの順位表(順位・勝敗・勝率・ゲーム差。優勝に印)。その下に球団ごとの優勝回数と優勝した年。まだ終わったシーズンがなければ、その旨を出す。
- **年ごとのタイトル**:終わったシーズンを選び、リーグごとに 打者 首位打者(打率)・最高出塁率・本塁打王・打点王・最多安打、投手 最多勝・最優秀防御率・最多奪三振・最多セーブ・最多ホールド。打率・出塁率・防御率は規定打席・規定投球回に届いた選手だけ。同じ値は全員。値が 0 なら「該当なし」。所属はそのシーズンの最後の球団、リーグはその球団のリーグ。盗塁王(盗塁の数)も出す(D-432)。
- **通算記録**:今シーズンまで(進行中を含む)の通算の上位 20 人。打者 安打・本塁打・打点・盗塁(D-432)・試合・WAR、投手 勝利・セーブ・奪三振・ホールド・WAR を選ぶ。引退した選手も含み、今の所属(引退なら「引退」)とシーズン数を出す。同じ値は同じ順位。
- **補強の記録**(当たり外れの一覧。D-216、D-368、D-420。旧「ドラフトの振り返り」):
  - 「ドラフト」(ドラフト・育成ドラフト)と「外国人」に分け、入団した年度と球団を選ぶ(初期値は、自球団の最新の年度。観戦のみなら最初の球団)。1 人 1 行(固定列は名前)で、入団の経路(ドラフトの巡・育成ドラフトの巡・外国人市場)、ポジション、年齢、入団時の見立ての総合と今の総合、今の所属(自球団・他球団・引退)、今までの成績(出場と WAR の累計)を出す。事前運転中の入団(年を持たない)は出さない。
  - 「出入り」:オフの年(N シーズン目のオフ)と球団(すべて・各球団)を選び、FA(移籍・残留)・トレード(シーズン中を含む)・自由契約市場・現役ドラフト・自由契約・支配下登録・引退を 1 人 1 行(種類・前の所属・新しい所属)で出す。
- 進行の画面の「ドラフト」とチームのページのボタンは、記録室の補強の記録を開く(チームのページからはその球団を選んだ状態)。
- **表彰**(D-442、D-443):記録室の中の 5 つ目「表彰」。終わったシーズンを選び、リーグごとの賞と両リーグの賞を出す(受賞者・所属・理由の数字)。版 28 までのシーズンは「記録なし」。
  - 年度の確定のときに、そのシーズンの成績から自動で決める(記録だけ。年俸などに影響しない)。同じ値なら WAR の大きい方、それでも同じなら選手の番号の順。
  - リーグごと:MVP(WAR 最大)、新人王(新人で WAR 最大)、ベストナイン(投手・捕手・一塁・二塁・三塁・遊撃・外野 3・指名打者。WAR 最大)、ベストバッター賞(投手を除くポジションごとに、打撃 + 走塁の得点が最大)、ベストディフェンス賞(捕手・一塁・二塁・三塁・遊撃・外野 3。守備の得点が最大)、最優秀中継ぎ投手賞(ホールド + 救援の勝利が最多)、最優秀救援投手賞(セーブが最多)。
  - 両リーグで 1 人:最優秀先発投手賞(規定投球回に届いた先発投手で WAR が最大)。
  - 対象:ポジションはそのシーズンに最も多くスタメンで守った位置(指名打者はスタメンの試合からポジションの試合を引いた数。外野はまとめる)。ベストナイン・ベストバッター賞は規定打席の半分以上、投手のベストナインは規定投球回の半分以上。ベストディフェンス賞は、そのポジションでチームの守備アウトの 3 分の 1 以上。中継ぎ・救援は先発の登板が登板の半分未満の投手。
  - 新人王の対象(近似):外国人でない、入団 5 年目まで(年齢 − 入団の年齢。高卒 18・大卒 22・社会人 24)、前のシーズンまでの記録が 60 打席・30 投球回以下、前のシーズンまでの一軍登録が 1 シーズン以下。
  - 結果は、オフの結果の画面、記録室の「表彰」、選手のページの受賞歴に出す。保存形式は版 29。

### 4.9 オフシーズン(F2:複数年。D-071、D-180〜D-189)
(契約・ドラフトなどは F3 で決める)
- **年度の確定**:シーズン終了後に、画面の「年度を確定」で行う。戻せないので、確認の画面で「戻せないこと」と「直前の状態を別名で保存できること」を示す(D-185)。処理はこの順:
  1. 今シーズンの集計を履歴に残す(順位表、選手 × シーズンの成績・WAR・内訳。全シーズン保存)。球場 × シーズンの集計を球場補正の履歴に足し、指標の基準値の出発点を今シーズンの最終値にする(D-121、D-146)。
  2. 加齢(年齢を 1 上げる)。
  3. 能力の更新(年1回。D-186、D-350):見せる能力に「年齢による増減 × 伸びやすさ + 揺れ」を足し、内部の能力を作り直す。好調・不調は引き直す。成長タイプ・伸びやすさ・型は変えない。
  4. 引退:年齢と能力から確率で決める(設定値。実在の統計は写さない。D-187)。
  5. オフの手続き(F3-1。D-201):自由契約 → ドラフト → 自由契約市場 → 最低人数の補充(4.8「オフの手続き」)。F2 の簡易な補充(D-184)はなくした(D-391)。
  6. 次のシーズンの準備:一軍(29人)・打順・先発の編成は既存の自動の規則で組み直す。疲労はリセット。日程は次のシーズンのシード(今のシーズンのシードから導く)で作る。
- 乱数は年度ごとのシードから導き、同じシードなら同じ結果(D-186)。
- 怪我は F2 では入れない。契約・自由契約・FA・トレードは F3 で扱う。
- 30年回しても、一軍相当の能力の平均とリーグの成績に上がる・下がる傾向がないこと(受け入れ条件。D-188)。
- 打席ログは直近の `log_seasons` シーズン(設定値。既定 1)だけ残し、それ以前は集計だけ残す(D-189)。
- 球場補正の換算の基準値は固定のまま(D-189)。
- 初期選手は、ゲーム開始前に試合なしで数十年分回した状態から始める(D-034 の完成形。D-190。4.2「初期選手の作り方」)。
- 引退の設定は、30 年回した後に 38 歳以上が全体の 2〜4% 程度残る値にする(D-191)。41 歳で必ず引退。

## 5. 非機能要件(機能そのものではなく、守るべき条件)

- **実名の扱い**:実名の球団名は、ユーザーが入力するセーブデータの中にのみ存在し、公開リポジトリには含まれないこと。
- **セーブデータの保存場所**:セーブデータは各自の端末(PC・スマホ)に保存され、リポジトリの外に置かれること。サーバーには送らないこと(D-081)。
- **画面の差し替えへの備え**:画面を作り直しても、計算本体を作り直さずに済むこと。
- **再現性**(D-088):同じシードなら、端末(スマホのブラウザ・PC)や Python の版が違っても、同じ結果になること。決まったシードの結果の指紋をテストに固定して確かめる(D-089)。
- **ブラウザで動くこと**:計算本体は Python 標準のライブラリだけで作り、ブラウザ上の Python でもそのまま動くこと(D-083)。
- **速度の目安**(D-082):スマホと PC のブラウザで、1日分が約1秒以内、1シーズンが数分以内(進み具合を表示)、メモリ不足で止まらないこと。
- **実名データの扱いの注意**:README に書く(D-085)。
