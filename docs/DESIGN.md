## 1. 全体構成
<!-- プログラムをどんな部品に分けるか -->

基本方針として、**画面(入出力)** と **シミュレーション本体** を分離する。

```
[画面:ブラウザ]  ←→  [シミュレーション本体]  ←→  [保存の差し替え口]
                                                 ├ ローカルのフォルダ
                                                 ├ 1ファイルの書き出し/読み込み
                                                 └ ブラウザ用の保存
```

- シミュレーション本体は画面に依存せず、単体でテストできるようにする。
- 画面はブラウザの中で動かす(Python をブラウザ上で実行する。D-080、D-081)。サーバーは使わない。
- 計算本体は Python 標準のライブラリだけで作り、ファイルの読み書きを直接書かない。保存は差し替え口を通す(D-083)。
  - 初期データ(`src/pennant/data/*.json`)は、パッケージの中のデータとして読む(`importlib.resources`)。ブラウザでもそのまま読める。

## 3. データ設計

### 3.1 初期データ(テンプレート)
- 架空の球団・選手のみを使う。
- コードに直書きせず、外部ファイルから読み込む。
- ファイル形式・置き場所(D-050 で決定):
  - 形式は JSON(セーブデータと同じ形式にそろえる)。先頭に `format_version`(形式のバージョン番号)を持つ。
  - 既定のファイルは `src/pennant/data/` に置き、プログラムと一緒に配る。別のファイルの場所を渡して差し替えることもできる。
  - 読み込むときに検証し、値の欠け・範囲外・割合の合計の不一致・型の補正の釣り合いの崩れなどを、場所と理由つきでまとめて知らせる。

### 3.2 セーブデータ(D-004〜D-006、D-068、D-100〜D-104)
- **1つのファイル**:拡張子 `.sav`、中身は ZIP(`zipfile` と `BytesIO` でメモリ上で作る。一時ファイルは作らない)。
  | ZIP の中のファイル | 中身 |
  | --- | --- |
  | `manifest.json` | 形式の名前・バージョン番号・保存日時・セーブデータの名前・中のファイルの一覧 |
  | `state.json` | シード、設定値(生成・名前の部品・打席・試合・シーズン)、リーグ(球団・選手。隠し情報と状態を含む)、シーズンの状態(現在の日・ローテーションの位置)、各試合の前の状態・先発を飛ばしたか、遊ぶ人の選択(`user.my_team_id`:自球団。形式の版 2 から) |
  | `logs/season-1.jsonl` | 1行に1試合(試合の結果と打席ログ)。ZIP の圧縮だけで、二重には圧縮しない |
- **乱数**:シーズンは、試合ごとのシードをシーズンのシードから作る(D-088)ので、持ち越す乱数の状態はない。保存するのは初期のシードだけで足りる(日程も、シードと設定値から作り直し、保存した試合と一致するかを確かめる)。
- **保存日時**は manifest にだけ入れ、指紋の元には入れない。ZIP の中の日時は固定する(同じ状態なら、保存日時のほかは同じ中身になる)。
- **保存の差し替え口**(D-101。`storage.py`):`Storage` の形(`write(name, data)`・`read(name)`・`list()`)。
  - `LocalFolderStorage`:PC のフォルダ(既定 `~/.npb-pennant-simulator/`)。
  - `MemoryStorage`:メモリ(テストとブラウザ)。
  - ブラウザのファイル選択・ダウンロード:テスト用ページ(`web/`)が `MemoryStorage` とファイルを受け渡す。
  - 計算本体でファイルを読み書きするのは `storage.py` だけ(設定ファイルの場所を指定して読む機能と、パッケージに同梱した初期データの読み込みも、ここに集めた。D-092)。テストで確かめる。
- **検証**(D-102):読み込みでは、ZIP → manifest → バージョン(古い版は変換)→ 状態の JSON → 設定値(各設定の検証をそのまま使う)→ リーグと選手 → シーズン → 打席ログ、の順に点検し、問題をすべて集めて、場所と理由を日本語で示す。点検が済んでから、新しい状態を作って返す(今の状態には触れない)。
- **旧版の変換**:`MIGRATIONS`(版 n の状態を、版 n+1 の形に直す関数の表)を順に当てる。
- データが大きくなったら、形式のバージョン番号で見分けて、データベース(SQLite:1つのファイルで動く小さなデータベース)へ移行できるようにする。

## 4. シミュレーションの仕組み
<!-- 試合結果の決め方、乱数の使い方など -->

### 4.1 1回の打席の計算(`plate_appearance.py`。D-035〜D-038、D-046)
- 入力:打者、投手、守備側の野手8人(ポジション → 選手。投手と指名打者は含まない)、走者・アウト状況(24通り)、乱数。
- 打者は野手でなければならない(投手は打席に立たない。指名打者制。D-046)。
- **オッズ比法**:リーグ平均の率 p を「オッズ」p/(1−p) に直し、打者側・投手側・左右の相性の倍率を掛け、確率に戻す。
  結果が複数あるので、最後に合計が 1 になるよう割り算で調整(正規化)する。
- **能力から倍率**:倍率 = (10点あたりの倍率) ^ ((能力値 − 50) / 10)。能力 50 で 1 倍。能力ごと・結果ごとに設定できる。
- 使う能力値は「現在の能力 + 好調・不調 × 影響の大きさ」。型・成長タイプ・潜在能力・年齢・名前は使わない(D-043)。
- **第1段階**:三振・四球・死球・本塁打・インプレー。インプレーはリーグ平均の残りで、倍率は掛けない。
- **第2段階**(インプレー):
  1. 打球の種類(ゴロ・ライナー・フライ):打者・投手のゴロ/フライ傾向、打者の打球の質(ライナー)。
  2. 担当ポジション:打球の種類ごとの割合表で決める(打者の左右では変えない)。投手が担当のときは、守備の能力を固定値で使う。
  3. 結果:まず「野手が処理できない打球」(打球の種類ごとの割合。必ず安打)かを決め、処理できる打球は、安打・失策・アウトをオッズ比法で決める。
     - 安打:打者の打球の質・走力(ゴロのみ)、投手の打球抑制(効果は小さい)、担当野手の守備範囲・肩(ゴロのみ)、左右の相性
     - 失策:担当野手の捕球
  4. 安打の内訳(単打・二塁打・三塁打):打球の種類ごとの割合に、打者の長打力(二塁打)・走力(三塁打)の倍率を掛ける。
     - 担当ポジションごとの内訳(`in_play.<打球の種類>.extra_base_by_fielder`)があれば、そちらを使う(D-072)。内野手(投手・捕手・一塁・二塁・三塁・遊撃)はここに書く。投手・捕手・二塁手・遊撃手は単打だけ、一塁手・三塁手は単打と少しの二塁打(長打力で起きやすさが変わる)。
     - 書かれていないポジション(外野手)は、打球の種類ごとの内訳(`extra_base`)を使う。
     - 野手が処理できない打球にも、同じ内訳を使う。
- 記録(`PlateAppearance`):結果、打球の種類、担当ポジション、野手が処理できない打球だったか、打者・投手の ID、実際に立った打席の左右、走者・アウト状況、決着球の球種(予約欄。今は空欄)。
- 計算方法は、`probabilities`(確率)と `resolve`(乱数で決める)を持つクラスなら差し替えられる(`PlateAppearanceModel`)。
  試合の計算からも使うため、`rating`(好調・不調を含む能力値)と `fielding`(担当ポジションの守備の能力)も持つ。

### 4.2 1試合の進行(`game.py` ほか。D-059〜D-062)
- 入力:2チームの編成(`TeamSetup`:一軍29人、スタメンと打順、先発投手)、乱数、打席の計算、設定、監督(采配のルール)。
  疲労は選手の「状態」(`Player.state.fatigue`)から読む。試合は入力の選手を書き換えない(疲労は試合後に `apply_game_fatigue` で足す)。
- 出力(`GameResult`):両チームの得点、イニングごとの得点(行わなかった裏は空)、延長・引き分け・サヨナラの有無、打席ログ全体、投手ごとの登板記録、スタメン。
- **イニングの進め方**:3アウトで攻守交代。9回表のあとホームがリードしていれば終了。9回以降の裏に勝ち越したら、その打席で終了(本塁打以外は、勝ち越しに必要な分だけ得点を数える)。延長は上限まで。
- **サヨナラの得点の打ち切り**:本塁打以外は勝ち越しに必要な分だけ得点を数え、取り消した走者は3塁で止まったものとする。後ろの走者は、前の走者を追い越さない塁で止める(同じ塁に2人いないように)。
- **打席ログ**(`GamePlateAppearance`):イニング・表裏・攻撃チーム・打順・打者・投手・点差・走者とアウト・打席の記録に加え、各走者の動き(`RunnerMove`:どの塁からどの塁へ、アウトか、出塁させた投手、失策で出塁したか、失策が関係した動きか)、得点、併殺・犠牲フライ・サヨナラ。
- **走者の進塁**(`baserunning.py`):固定ルール(押し出し、本塁打・三塁打で全員生還、三振・ライナーアウトは進塁なし)と、確率表 × 能力の倍率(オッズ比法)の組み合わせ。
  - 単打:3塁走者は生還。2塁走者は外野への単打なら生還を判定、内野安打なら3塁まで。1塁走者は外野への単打で3塁が空いていれば3塁を判定。
  - 二塁打:2・3塁走者は生還。1塁走者は生還を判定(しなければ3塁)。
  - ゴロ:2アウト未満で1塁に走者がいれば併殺を判定。併殺でなければ打者アウト、詰まっている走者は進み、詰まっていない2・3塁走者は進塁・生還を判定。
  - フライ:2アウト未満で外野フライなら、3塁走者の生還(犠牲フライ)と2塁走者の3塁進塁を判定。内野フライは進塁なし。
  - 失策:打者は1塁へ、走者は1つ進み、さらに1つ進めるかを判定。
  - 走塁死は入れない(D-059)。
- **投手の起用**(`manager.py`・`fatigue.py`):
  - 先発の打者数の上限 = 基準 + (スタミナ − 50) / 10 × 係数 − 疲労 × 係数(下限あり)。イニングの終わりに上限以上なら降板。失点(出塁させた走者の生還)が上限に達したら、その場で降板。
  - 救援は1イニング単位。役割(抑え・中継ぎ(勝ち)・中継ぎ・敗戦処理)を総合値の順で割り当て、場面(イニングと点差)で使う役割を決め、疲労の少ない投手から選ぶ。
  - 救援が使い切られた・疲れているときは、疲労の少ない先発を救援に回す。それでもいなければ、今の投手が続投する(記録 `forced_extra_innings` が残る)。
  - 疲労は投げた打者数 × 係数で増え、1日ごとに 回復量 × 回復力の倍率 だけ減る(`advance_day`)。疲労が上限を超えた投手は登板できない。
- **一軍・スタメン・休養**(`manager.py`):
  - 一軍:先発型6・救援型8、捕手2+捕手以外の7ポジションに1人ずつ+総合値の高い野手6人(計29人)。
  - スタメン:各ポジションで総合値が最も高い野手+指名打者(残りで打撃の高い打者)。
  - 打順:3〜5番は長打の高い3人(4番が最も高い)、1・2番は出塁の高い2人(足の速いほうが1番)、6〜9番は打撃の総合の順。
  - 休養:主力は一定の確率で休み、控えが同じ打順・ポジションに入る。同じポジションの控えがいなければ近いポジションの控え(守備の能力を少し下げる)、それもいなければ誰か(大きく下げる)。捕手の控えがいなければ休ませない。守備適性そのものは F3 で扱う。
- **差し替え**:采配は `Manager` の形(一軍の選抜・スタメン・先発・降板の上限・救援の選び方)を持つクラスなら入れ替えられる。既定は `SimpleManager`。

### 4.3 シーズン(実装④。D-066、D-087)
- **日程**:ラウンド制。各リーグ6球団を、総当たり1巡(5日)ずつの組み合わせで並べ、25巡して125試合(試合数は設定値)。2つのリーグは同じ日に並行して行う。
- **ホームとアウェイ**(D-087):同じ相手との対戦ごとに交互。各ペアの25試合のうち13試合のホーム権を持つ側を、各チームが2〜3組で持つよう、シーズンのシードで割り振る(ホームは各チーム62か63試合)。
- 日程を作る部分は差し替えられる形にする(休養日・3連戦・交流戦は、別の日程の作り方を足して入れる)。
- **1日の流れ**(D-087):スタメンと先発を決める → 試合 → 疲労を加える(`apply_game_fatigue`)→ 結果を順位表に反映 → 1日を進めて回復させる(`advance_day`)。先発は6人ローテーションで、疲労が大きい投手は飛ばす。
- **シーズンの結果**:最終順位表、全試合の結果、全打席のログ。優勝は各リーグの最高勝率。ポストシーズンは後から足せる形にする。
- **サヨナラの打ち切りの記録**:得点を打ち切った打席に印を付ける(`GamePlateAppearance` に項目を足す)。
- **順位**:勝率(引き分けは分母に入れない)→ 勝利数 → 直接対決の成績。同順位を許す設定も持つ。
- **乱数**:試合ごとのシードを、シーズンのシードと試合の通し番号から、SHA-256(`hashlib`)で決める(`derive_seed`。組み込みの `hash()` は使わない。D-088)。日程の割り振りも、シーズンのシードから同じ方法で作った乱数で決める。
- **1試合の再現**:各試合の前の状態(両チームのローテーションの位置と、一軍の投手の疲労)を `GameContext` として残し、`Season.replay_game(番号)` で、その試合だけをもう一度計算できる(シーズンの状態は変えない)。
- **進め方の関数**(画面から呼ぶ):`play_day()`(1日)、`play_days(n, progress)`(n日)、`play_to_end(progress)`(最後まで)。`progress` には、1日ごとに(終わった日数, 全日数, 終わった試合数, 全試合数)を知らせる。
- **日程の差し替え**:日程は `ScheduleMaker` の形(`make(league, rng) → Schedule`)を持つクラスなら入れ替えられる。既定は `RoundRobinSchedule`(円の方式で1巡5日を作り、巡ごとに日の並びを入れ替えて25巡)。休養日・3連戦・交流戦は、別の作り方として足す。
- **ホームの多い組の割り振り**:チームを乱数で円に並べ、円の上で1つ先・2つ先の相手に対しては自分が13試合のホームを持ち、ちょうど半周先の相手とは円の前半のチームが持つ(6チームなら各チーム2組か3組)。
- **順位の決め方**:勝率 → 勝利数 → 直接対決の勝率(同じ成績どうしの対戦だけで計算)→ 抽選(シーズンのシードから決まる順)。同順位を許す設定(`standings.allow_shared_rank`)では、勝率が同じチームを同じ順位にする(表の並びは上の順)。ゲーム差は、首位との差と、1つ上の順位との差の両方を持つ。
- **ポストシーズン**:`SeasonResult`(最終順位表・優勝・全試合)を受け取る別の処理として、後から足す。
- 怪我・成長は入れない(F2・F3)。一軍29人は固定(D-074)。
- **ホームの有利**(D-073):ホームチームの打者の打席で、打席の計算にオッズ比法の倍率を足す。
  - 実装④で校正した値:四球・本塁打・インプレーの安打に 1.06 倍、三振に 0.94 倍(1.0 にすれば有利なし。9章)。最初の案(1.03 倍・0.97 倍)では、ホームの勝率が約51.6%で目標に届かなかった。
  - 結果:20シーズンの平均で、ホームの勝率は約52.8%(目標 52〜54%)。
  - 入れ方:`OddsRatioModel` の第1段階(三振・四球・本塁打)とインプレーの安打の倍率に、ホームの打者のときだけ掛ける。`game.py` が、裏の攻撃(ホームの打者)のときに `home=True` を渡す。
  - 全球団に同じだけ効くので、球場補正の推定(リーグ平均を1.0に合わせる)では打ち消されるはず。球場補正を作る第2弾のテストで確かめる(D-093)。

### 4.4 指標の集計(実装⑤。D-067、D-094〜D-098)
- **ログから計算する**(D-096):成績は、試合の結果(`GameResult` の打席ログと投手の登板記録)から、その都度計算する。成績を別に数え上げて持たない。集計の単位(月別・左右別など)は、ログを作り直さずに後から足せる。
- **部品**:
  - `records.py`:元の数(すべて整数)。1試合ごとの成績(`game_records`)を作り、シーズン通算はその合計(`season_records`)。打者・投手・チームの3種類。
  - `decisions.py`:1試合の勝利・敗戦・セーブ・ホールドの判定(D-094)。
  - `metrics.py`:指標の定義データ(`data/metrics.json`)の読み込み・検証と、計算式による指標の計算・表示の形。
  - `stats_report.py`:確認用の集計(規定到達者の上位、整合チェック、真の能力と成績の関係)。
- **自責点**(簡易版。D-095):半イニングごとに走者を追いかけ、出塁が失策によるもの(`reached_on_error`)か、それまでの進塁に失策が関わった(`advanced_on_error`)走者が生還したら、自責点にしない。それ以外は、その走者を出塁させた投手(`responsible_pitcher_id`)の自責点にする。
- **打点**(D-095):その打席で生還した走者の数。併殺打の打席は0。失策が関係した動き(`advanced_on_error`)で生還した走者は数えない。
- **勝利・敗戦・セーブ・ホールド**(D-094):打席ログで点差を追いかけて判定する。
  - 「勝ち越しの得点」は、勝ったチームが最後にリードを奪った打席の得点。その打席で、勝ち越しに必要な分の生還(走者の動きの並びで前から数える)の走者を、決勝点の走者とする。
  - 勝利投手:その時点で勝ったチームの投手として試合にいた投手(先発は試合の初めから、救援は最初に対戦した打席から試合にいるとみなす)。それが先発で、投球回が5回(15アウト)に満たなければ、勝ったチームの最初の救援投手。
  - 敗戦投手:決勝点の走者を出塁させた投手(`responsible_pitcher_id`)。
  - セーブ・ホールド:登板した最初の打席の前の点差・走者・アウトで、登板時の状況を判定する。
- **指標**(D-097):定義データの計算式(例:`(H + BB + HBP) / (AB + BB + HBP + SF)`)を、標準ライブラリの `ast` で読み、分数(`fractions.Fraction`)で計算する(小数の誤差を出さない)。分母が 0 なら「値なし」(`None`)。式の中で、ほかの指標(例:`obp + slg`)も使える。
- **規定**(D-096):規定打席 =(チーム試合数 × 31 + 5)÷ 10 の整数部分(× 3.1 の四捨五入)。規定投球回 = チーム試合数 × 3 アウト。
- **担当した野手の選手 ID**:打席ログ(`GamePlateAppearance.fielder_id`)に残す(第3弾の守備の計算用)。

### 4.5 セーブ・ロード(実装⑥。D-100〜D-104)
- `savegame.py`:`save_game(season, name, saved_at) → bytes`(.sav の中身)、`load_game(data) → Season`(検証してから作る)、`default_file_name(日付)`。
- `newgame.py`:`new_league(seed, 球団名の一覧)`(空欄は架空の初期名)、`validate_team_names`(空白だけ・24文字を超える・制御文字・重複を、理由つきで拒否)、`public_player`(画面用の選手情報。隠し情報と真の能力値を含めない)。
- 球団名は `Team.display_name` に入る(空なら、地名 + 愛称の架空の初期名)。指紋の元には、架空の地名・愛称だけを使う。
- 保存は計算本体の関数として用意し、画面からはそれを呼ぶだけにする。

### 4.6 第2弾・第3弾の指標(D-063、D-064、D-070)
- **基準値**(`baselines.py`。D-121〜D-127):打席ログから、整数の集計(状況ごとの得点と回数、結果ごとの状況の移り変わりの回数と得点)を試合ごとに作って足していき、そこから分数で RE24・線形加重・wOBA の重みと目盛り・リーグ平均・FIP 定数を求める。試合ごとに足せるので、シーズン中も、進めた試合の分だけ計算すればよい。
  - 試運転(`trial_baselines`):リーグを複製し、リーグのシードから決めた試運転のシードで1シーズン回して基準値を求める。進み具合を呼び出し側に知らせられる。
  - 既定値と設定:`data/baselines.json`(混ぜ方の定数、FIP の係数の出どころ、既定の基準値)。
  - セーブデータ(形式の版 3):出発点の基準値(出どころ・RE24・線形加重・値)を保存する。版 2 以前は、既定値で読む。
  - 指標の式(`metrics.json`)は、元の数・前に定義した指標に加えて、基準値の名前(`baseline_names` に書いたもの)を使える。基準値がないときは「値なし」。
- **RE24**:打席ログの走者・アウト状況ごとに、イニング終了までの得点を平均して作る。サヨナラで打ち切られた半イニングは、RE24 と線形加重の集計から外す(D-123)。
- **線形加重**:結果の種類ごとに「打席後の得点期待値 − 打席前の得点期待値 + その打席の得点」を平均する。wOBA の重みは、アウトの価値との差を取り、目盛りをリーグの出塁率に合わせる倍率を掛けて作る。
- **FIP**:係数は標準値(本塁打13・四死球3・三振2)。係数を得点価値から導く方式へ切り替えられるよう、係数を設定値として持つ。
- **ホームの有利との関係**(D-093):球場補正の推定で、ホームの有利が打ち消されることをテストで確かめる。
- **重みの混ぜ方**(D-091、D-126):使う値 = 比重 × 今シーズンの値 +(1 − 比重)× 出発点の値。比重 = 累積打席数 ÷(累積打席数 + 定数)、定数の既定は 20,000 打席(設定値)。出発点は前シーズンの最終値(初年度は試運転の値。D-121)。wOBA の重み・目盛り・リーグ平均・FIP 定数・球場補正の推定に共通で使う。
- **指標を足す3つの段階**(D-128):A 定義データだけ(元の数・基準値の組み合わせ)/ B 元の数を足す(`records.py`)/ C 打席ログに情報を足す(指紋が変わる。過去のデータでは「値なし」と表示)。
- **球場の倍率**(②a。D-136〜D-138。`parks.py`、`models.ParkFactors`):真の倍率(本塁打・BABIP。整数の千分率)は球団(`Team.park`)に持つ。リーグのシードから SHA-256 で導いたシードの `random.Random` で、リーグごとに6つを範囲内で一様に引き、合計が 6000 になるよう差を均等に配る。範囲に収まらなければ引き直す(同じシードなら同じ倍率)。打席の計算(`OddsRatioModel`)は `park` を引数で受け取る(省略時は 1.0)。`simulate_game`・`Season._play`・`play_games` が、ホームチームの本拠地の倍率を渡す。
  - 公開用(`Game.stadium`):球場名、本拠地のチーム、本拠地での実際の結果。答え合わせ用(`answers.stadium_answers`):真の倍率。
  - セーブデータ(版 4):`league.teams[].park` に保存。版3以前は 1000/1000(= 1.0)として読む。版 5 で `park_history`(球場 × シーズンの集計)を足した。版4以前は履歴なし(球場補正 1.0)として読む。
  - 指紋:(a) は変わらない(倍率の乱数は別)。(b)〜(h) は倍率を試合に入れたので変わる。(i) 球場の倍率を足す。倍率をすべて 1.0 にしたときの (b)〜(h) を、以前の値(`tests/data/fingerprints-parks-off.json`)と比べるテストで、回帰を確かめる。
- **球場補正の推定**(②b・②c。D-140〜D-150。`parkfactors.py`):球場 × シーズンの整数の集計(`ParkTally`:本拠地とアウェイの PA・HR・BIP・HIT・R)を試合ごとに足していく。推定(`estimate_parks`)は、履歴を合算 → 生の比 → 本塁打と BABIP を縮める(比重 = 本拠地の打席数 ÷(打席数 + 定数))→ リーグの平均で割ってそろえる → 得点の補正を本塁打と BABIP の推定から換算(`parks.run_factor`:推定値を千分率の `ParkFactors` にして打席の結果の確率を求め、wOBA の重みで「1打席あたりの得点の出やすさ」に直す。真の値側 `expected_run_factors` と同じ関数)→ 千分率に丸め、リーグの平均で割ってそろえる(D-147)。縮める計算は分数、換算は小数(打席モデルが小数のため)で、結果を千分率の整数に丸めてから分数に戻す(指紋 (j) のため)。設定は `data/park_factors.json`(本塁打と BABIP の想定する球場差と定数。D-148)。
  - 今シーズンに使う球場補正は、`GameState.park_history`(前のシーズンまでの集計)から求め、シーズン中は変えない。1シーズン目は 1.0。選手ごとの値は、`_StatsCache.player_park_pa`(選手 × 球場の打席数)で重みづけした平均を、指標の式の `pf` に入れる。
  - `run_seasons`:同じリーグを複数シーズン繰り返して回す確認用(F2 の最小の形。加齢などは含めない)。指紋 (j) は、固定のシードで3シーズン回した推定値。
  - 真の倍率は答え合わせ用に残す。
- **守備(第3弾)**:担当ポジションごとに、打球の種類ごとのリーグ平均のアウト率と比べ、アウトにした数の差を得点に換算する。
- **打撃・走塁・守備の得点**(第3弾②。D-160〜D-166。`runvalues.py`):試合の結果(打席ログ)と基準値(`Baselines`:RE24・線形加重・wOBA の重み)から、選手 × シーズンの `PlayerRuns`(打撃・走塁・守備の得点、ポジションごとの守備の得点・機会・守備アウト数)を分数で求める。手順:①今シーズンの記録から「同じ状況」(結果 × 前の状況 × 外野か)ごとの期待値の変化の平均と、ポジション × 打球の種類ごとのアウト率を集計(`SeasonContext`)→ ②打席ごとに、走塁の差を選択の余地があった走者に等分、守備の差(アウトか − 期待のアウト率)× アウトの価値を担当野手に加算 → ③打撃は選手の元の数から wRAA(球場補正つき)。守備アウト数は打順表の守備位置 × 守備側のアウト数。画面には出さない(③で出す)。`run_seasons` は結果を受け取る呼び出し口を持ち、指紋 (k) と `scripts/inspect_run_values.py` が使う。
- **WAR**:打撃・走塁(進塁の価値)・守備・ポジション補正・控え水準・1勝あたりの得点を組み合わせる。投手は FIP 版と失点版の両方。
- 第3弾は①選手生成の変更 → ②打撃・走塁・守備の得点 → ③WAR の順(D-155)。守備の得点は打球ごとの記録(担当野手の ID)から、走塁の得点は進塁の価値から。ポジション補正・控え水準は設定値。投手の WAR は FIP 版と失点版。1勝あたりの得点はリーグの得点環境から(D-156)。
- **ポジション別の型の出現割合**(第3弾①。D-157。`generate.py`・`config.py`):`generation.json` の `position_archetype_shifts` に、守備位置ごとの型の「足す量」(合計 0)を置く。ポジションの割合 = 全体の割合(`batter_archetypes.*.share`)+ 足す量。読み込み時に、各ポジションの合計が 0、各割合が 0〜1、球団の人数(`roster.fielders`)で重みづけした合計が型ごとに ±許容幅(`potential.share_balance_tolerance`)に入ることを検証する(全体の平均が 50 から動かないため)。投手には適用しない。

### 4.7 シーズンの間の処理(F2。D-071)
- 年度の確定 → 加齢 → 成長・衰退 → 引退 → 新人の補充 → 次のシーズンの準備、の順で行う関数の流れにする(試合の計算とは別の処理の流れ)。
- 成長・衰退は、すでにある年齢カーブ(`aging.py`)と能力の揺れを使う。好調・不調は引き直す。
- 引退の確率は、年齢とリーグ全体での能力の順位から決める(設定値)。
- 新人は、空いた枠の数だけ生成して直接加える(1球団あたり年6人前後)。ドラフトは F3。
- 古い打席ログは、直近の数シーズンだけ残し、それ以前は集計値に圧縮する。
- F2 が動いたら、初期選手の作り方を「試合なしで30年ほど回した状態から始める」方式に置き換える。

## 7. テスト方針
- テストには pytest を使う。
- シミュレーション本体は、画面なしで単体テストできるようにする。
- 乱数のシードを固定して、結果を再現できるテストを書く。
- **版をまたいだ再現性**(D-088、D-089):`src/pennant/fingerprint.py` が、決まったシードで (a) リーグの生成、(b) 1試合、(c) 30日分の試合、(d) 1シーズン(実装④で追加)を行い、(e) (d)の集計結果の元の数(実装⑤で追加)、(f) (d)を途中(1・62・125日目)で保存・読み込みして最後まで進めた結果(実装⑥で追加)とあわせて、結果の指紋(SHA-256)を作る。
  - 元にするのは、離散的な結果と、整数・文字列の情報だけ(小数は入れない。入れようとするとエラーにする)。
  - 期待値は `tests/data/fingerprints.json` に固定し、CI の Python 3.10・3.12・3.14 で一致を確かめる。
  - ブラウザのテスト用ページ(`web/`)も、同じ関数で指紋を表示する。
  - 確認用スクリプト:`python scripts/fingerprint.py`
- **乱数の使い方の決まり**:乱数は `random.Random(シード)` の中の関数だけを使う。シードは整数か文字列にする(タプルなどは版によって使えない)。集合(set)の並び順に乱数の結果を左右させない(文字列の集合の並び順は、Python を起動するたびに変わるため)。版をまたいで指紋が変わった場合は、その関数を `random()` だけを使った自前の処理に置き換える(D-089)。

## 8. 検討中の論点
<!-- まだ決定ではない。決まったら DECISIONS.md に記録し、上の各節に反映する -->
> ここに書いた内容は**まだ決定ではありません**。壁打ちで検討する候補です。

- **守備適性・兼任、投手の先発・救援の区別**:選手ごとに、主ポジション以外に守れるポジションと得意・不得意を持たせる(第1弾は主ポジション固定。守備適性・兼任は F3 で扱う。D-049)。投手は先発と救援(リリーフ)を区別する。
- **選手の永続 ID・契約情報**:選手に、移籍しても変わらない番号(永続 ID)を付け、契約情報を持たせる(F3 で扱う)。オフシーズンの処理の流れは D-071 で決定した。
- **他球団の判断ロジックを差し替え可能にする**:他球団がどの選手を獲るか等を決める仕組みを、部品として交換できるようにする。
- **投手能力の2層化への備え**:投手の能力を、後から「基礎能力 + 球種ごとの補正」の2層にできる形にしておく。
- **BABIP の検証機能**:同じ設定でシーズンを繰り返しシミュレーションし、BABIP の年ごとの相関(ある年に高い選手が翌年も高いか)を調べる検証機能。
- **年齢カーブの持ち方**:年齢カーブは「潜在能力に対する割合」ではなく、「ピークからの差(点数)」で持つ方向で検討する。20〜80 の目盛りと整合させるため(割合で持つと、目盛りの基準の 50 が動いてしまう)。
- **「奪三振力」の年齢カーブのグループ**:技術系に入れるかパワー系に入れるかは、調整時に見直す。
- **検証の方法**:シーズンを繰り返し回して、リーグ平均の率・得点が一般的な水準に収まるかを確かめ、設定値を校正する。
