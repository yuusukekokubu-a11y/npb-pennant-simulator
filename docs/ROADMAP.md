# 今後の予定(ROADMAP)

開発は段階的に進めます。計画は次の**2つの別々の軸**で整理します(D-020)。

| 軸 | 何の順番か | 中身 |
| --- | --- | --- |
| 画面の段階(段階0〜3) | **画面**をどう作っていくか | 土台 → 計算本体 → 最小のブラウザ画面 → ブラウザ画面の完成形 |
| 機能フェーズ(F1〜F4) | **機能**をどの順に増やすか | 1シーズン → 複数年 → 球団経営 → 財務 |

2つの軸は独立しています。例えば「F1 の機能を、段階1(画面なし)→ 段階2(最小のブラウザ画面)の順で作る」のように組み合わせて進めます。

### 2つの軸の関係
| 機能フェーズ | 段階1(計算本体) | 段階2(最小のブラウザ画面) | 段階3(ブラウザ画面の完成形) |
| --- | --- | --- | --- |
| F1:1シーズン | ①〜⑥(下記)を作る | ⑥の後に作る(観戦と閲覧。D-080) | ブラウザの中で完結する方式(D-081) |
| F2:複数年 | シーズンの間の処理(D-071) | 年をまたいで進める操作を足す | 同上 |
| F3:球団経営 | F3-1 ドラフト・自由契約 → F3-2 契約更改・年俸・FA → F3-3 トレード(D-075) | GM の操作を足す | 同上 |
| F4:財務 | お金の管理 | 財務の操作を足す | 同上 |

- 画面(段階2・3)は、計算本体の側に用意した操作の関数を呼ぶだけの層にする(D-009、D-080)。そのため、機能を足すときは、まず段階1で計算本体を作り、画面はそれを呼ぶ形で追いかける。

> ※ 各段階・各フェーズの詳細は、壁打ちで仕様が固まり次第、追記します。

# 軸2:機能フェーズ(F1〜F4)

## F1:1シーズンの再現
12球団・2リーグで1シーズンを打席単位でシミュレーションし、個人成績と指標を出す(D-015、D-016、D-021)。
指標は3弾に分けて実装する(D-018)。弾への振り分けは「個人の記録だけで計算できるか / リーグ全体の基準値が要るか / 守備・走塁・ポジション補正が要るか」で決める(D-026)。設計は最初から WAR まで見据える。

- **第1弾:基本の打撃・投球指標**
  - 例:打率、出塁率、長打率、OPS、ISO、BABIP、K%、BB%、防御率
- **第2弾:+指標・球場補正**
  - wOBA(重みをリーグ全体の結果から決める)、FIP(FIP 定数をリーグ全体の防御率から決める)
  - +指標:リーグ平均を100として表す指標(例:wRC+、OPS+)
  - 球場補正:球場ごとの打ちやすさ・打ちにくさを差し引く調整
- **第3弾:守備・走塁・WAR**
  - 守備指標、走塁指標、それらをまとめた WAR

日程は、まず同一リーグ内のみ(125試合)で動かし、その後に交流戦を足して143試合にする。クライマックスシリーズは後から追加する(D-021)。

## F2:複数年の継続
シーズンをまたいで続けて遊べるようにする。選手の「真の能力」が年齢で成長・衰退する(D-017)。潜在能力と、項目グループごとの年齢カーブで表す(D-030、D-031)。

シーズンの間に、次を順に行う(D-071)。
1. 年度の確定(指標の基準値と、球場補正の推定の更新。計算本体は ②b の `finish_season`。画面は F2 で作り、2シーズン目の球場補正が画面に出ることを受け入れ条件にする。D-151)
2. 加齢
3. 成長・衰退(年齢カーブと能力の揺れ。好調・不調は引き直す)
4. 引退(年齢とリーグ全体での能力の順位から決まる確率。設定値)
5. 新人の補充(空いた枠の数だけ生成して直接加える。1球団あたり年6人前後。ドラフトは F3)
6. 次のシーズンの準備(一軍の選抜、疲労のリセット、日程の作成)

- 怪我は F2 では入れない。契約・自由契約・FA・トレードは F3。
- 得点の球場補正の換算に使う基準値を、固定(`baselines.json` の既定値)からセーブデータごとの値に動かすかを再検討する(D-154)。
- 受け入れ条件:何十年回しても、一軍相当の平均が50付近に保たれること。
- 古い打席ログは、直近の数シーズンだけ残し、それ以前は集計値に圧縮する(残す年数は設定値)。
- F2 が動いたら、初期選手は、ゲーム開始前に試合なしで30年ほど回した状態から始める方式に置き換える(D-034 の完成形)。
