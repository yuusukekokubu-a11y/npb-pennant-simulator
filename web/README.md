# ブラウザの画面

計算本体(`src/pennant/`)を、スマホや PC のブラウザの中の Python で動かして遊ぶ画面です(最小のブラウザ画面①②。D-107、D-114)。
公開先:`https://yuusukekokubu-a11y.github.io/npb-pennant-simulator/`

開発者向けの測定ページ(技術検証。D-082)は、`/dev/`(公開先の URL の最後に `dev/` を付けた場所)にあります(D-111)。

## 遊び方(スマホ・PC 共通)

1. 公開先の URL をブラウザで開きます。**初回は約12MBをダウンロードします**(ブラウザの中で計算を動かすための Python 一式)。Wi-Fi をおすすめします。
2. 「**新しく始める**」を押し、12球団の名前を入れます。空欄のままなら、薄く表示されている架空の名前になります。名前に問題があると、欄の下に赤い字で理由が出ます。
3. 「**自球団にする**」で、応援する球団を1つ選び、「**この内容で始める**」を押します。始める前に、リーグの歴史(数十年分の選手の入れ替わり。試合はしません)を作ってから、画面に出ない練習のシーズン(試運転)を1回回して、wOBA などの指標の基準値(重み・リーグ平均)を求めます。スマホで数秒かかり、「リーグの基準値を求めています」と進み具合が出ます。急ぐときは、「詳しい設定」で「既定値を使う(速い)」を選べます。
4. 「進行」のタブで、「**1日**」「**1週間**」「**最後まで**」を押して進めます。0.6 秒より長くかかるときだけ「**止める**」が出ます。押すと、その日の試合が終わったところで止まります。直近の日の全試合のスコアも出て、押すと試合のページを開きます。
5. 「順位表」のタブで、リーグを切り替えて順位を見ます。★と色の付いた行が自球団です。チーム名を押すと、チームのページ(成績と選手の一覧)を開きます。チームのページの「本拠地」を押すと、球場のページ(本拠地での試合数・本塁打・得点と、本拠地とアウェイの比較の表)を開きます。球場ごとに本塁打や安打の出やすさ(真の倍率)が違いますが、ふだんは隠れています。2シーズン目からは、前のシーズンまでの結果から推定した球場補正(得点は本塁打と BABIP の推定から組み立てた値。BABIP 単独は参考値)が球場のページに出ます(1シーズン目は「まだ推定できません」)。答え合わせモードをオンにすると、真の倍率も見られます。試合のページにも球場名が出ます。
6. 「成績」のタブで、個人成績を見ます。打者/投手、「基本」「セイバー」「能力」を切り替えられます。列の見出しを押すと並べ替わり(もう一度で逆順)、上の枠にその指標の解説が出ます。表の上の「並び順」の欄からも、すべての指標(基本・セイバー)を選べ、「高い順/低い順」で向きを変えられます。並び順と絞り込みは、「基本」「セイバー」「能力」を切り替えても保たれます。並び順に使っている指標が切り替えた先の表にないときは、名前の隣に固定して出します(例:打率の高い順のまま「セイバー」を見ると、名前の隣に打率が出ます)。打者と投手を切り替えたときは、その側の既定の並び順(打者は打率、投手は防御率)に戻ります。「規定到達者だけ」(規定打席・規定投球回に届いた選手だけ)は、最初はオンです。選手名を押すと、選手のページ(通算と試合ごとの成績)を開きます。
7. 「試合」のタブで、日付を選んでその日の試合を見ます。試合を押すと、試合の流れ(1打席ずつの文章)と投手の成績が出ます。
8. 「成績」の「WAR」には、選手が控え水準の選手に比べて何勝分多く勝ちに貢献したか(野手は打撃・走塁・守備・ポジション補正・控え水準の内訳つき。投手は失点版と FIP 版)が出ます。選手のページとチームのページにも出ます。シーズン途中は「○日目まで」の値です。用語の解説は表の下にあります。
9. 「成績」の「セイバー」には、wOBA・wRC+・OPS+(打者)と FIP(投手)も出ます。基準値は、試運転(2年目からは前のシーズン)の値に、今シーズンの値を少しずつ混ぜて使います(表の近くに、今シーズンの比重が出ます)。wRC+・OPS+ の球場補正は、1シーズン目は 1.0、2シーズン目から前のシーズンまでの結果で推定した値(選手が立った球場ごとの打席数で重みづけ)です。
10. 上の「**メニュー**」の「**指標の解説を見る**」で、すべての指標の式と解説を読めます。メニューでは、答え合わせモードも選べます(最初はオフ)。オンにすると、「能力」で選手の本当の実力(20〜80 の数値)が見られます。成績から実力を推理する楽しみが減るので、見たいときだけオンにしてください。この設定は保存されず、ページを開き直すとオフに戻ります。
11. 新規開始で「自球団にする」を選ぶと、その球団の GM としてオフの手続き(契約・FA・ドラフト・市場)を自分で進められます。選ばなければ観戦のみで、手続きは自動で進みます。「詳しい設定」で、スカウト評価のずれの大きさ(小・中・大)を選べます。
12. シーズンが終わると、「進行」のタブに「**年度を確定する…**」が出ます。確認の画面で「年度を確定する」を押すと、今シーズンの成績を履歴に残し、選手の年齢が1つ進んで能力が更新され、引退する選手と入団する新人が決まり、次のシーズンが始まります(**この操作は戻せません**。直前の状態を残したいときは、確認の画面の「先に保存する」で別のファイルに保存してください)。確定のあとに「オフの結果」(引退した選手・入団した新人)が出ます。答え合わせモードがオンのときは、残った選手の能力の増減も出ます。2シーズン目からは、「成績」の表の上でシーズン(今シーズン・過去の各シーズン・通算)を選べ、選手のページに年度別の成績が出ます。球場補正も、前のシーズンまでの結果から推定した値になります。
13. 操作する球団があるときは、年度の確定のあとに「**オフの手続き**」の画面になります(UI の整理①a。D-270〜D-273)。上に段階のタブ(**契約・FA・ドラフト・市場・完了**)と、状態バー(今の段階の要約・総年俸・ボタン)が出ます。ボタンは 2 種類:「**この段階をおまかせ**」は今の段階だけを AI と同じ方針で(自分の球団の分も)進め、AI が何をしたかの一覧(「おまかせの結果」)を出して次の段階の入口で止まります。「**次の手続きへ**」は自分の操作を終えて進みます(AI は代わりに何もしません。FA では残りのラウンドで提示せず、ドラフト・市場では残りの自分の番をパス)。残りを全部 AI に任せるときは、上の「メニュー」の「**全部おまかせ**」(確認つき。やり直せないので、先に保存しておくと安心です)。ドラフトと市場の画面は下の 13-7 を見てください。完了で 70 人に満たない分は自動補充。候補の評価は自球団のスカウトの推定値 ± ふれ幅と天井(S〜D)で、真の能力とはずれています。途中で保存して後から再開できます。入団した選手のページには、入団時のスカウト評価が残ります。
13-2. 「進行」の「**ドラフトの振り返り**」(チームのページにもあります)で、入団した年度と球団を選ぶと、入団した選手の経路(ドラフトの巡・市場・自動補充)、入団時の総合の推定値 ± ふれ幅と天井、今の所属、出場と WAR の累計が 1 人 1 行で出ます。答え合わせモードをオンにすると、今の真の総合・入団時の推定値との差(+ は期待以上)・実際の天井と、球団ごとの差の平均(「見る目」の目安)も出ます。数年進めてから見ると、当たり外れが分かります。
13-3. PC のブラウザやスマホの横持ち(幅 900 px 以上)では、契約・FA・ドラフト・市場・ドラフトの振り返りの表が横スクロールなしで全列出ます。縦持ちでは、左端の名前と並べ替えた列を固定して横にずらします。
13-4. **契約と年俸**(F3-2a):新規開始の「詳しい設定」で**お金のルール**(なし・ゆるい・標準・きびしい。あとから変えられません)を選べます。普段は「なし」のままで構いません。選手のページに年俸(架空の「万円」)・契約年数・残り年数・年俸の履歴が、チームのページに総年俸(と、ルールがあれば予算・使用率)と年俸の高い順の表が出ます。年俸は見える情報(直近 3 シーズンの WAR とスカウト評価)だけから算定します。「標準」「きびしい」では、総年俸が予算の上限を超えると、自由契約で減らすまで「次の手続きへ」が押せません(市場では予算の足りない選手に「予算不足」と出ます)。「きびしい」は球団ごとに予算の格差(大・中・小)があります。
13-5. **契約**(契約更改と自由契約をまとめた画面。D-272):自球団の全選手が 1 つの表に出ます(列:名前・WAR・状態・今回の提示・ポジション・年齢・今の契約・出場。①b で「状態」と「今回の提示」を WAR のすぐ右に寄せました)。初期は WAR の低い順(手放す候補が上)。見出しをタップすると並べ替え、もう一度で逆順。絞り込みはポジション(全員・投手・捕手・内野手・外野手)と状態(未提示・保留・更改済・FA 宣言・自由契約・契約中)。投手・捕手・内野手・外野手を選ぶと、成績の種類(基本・セイバー・WAR)も選べます。状態バーの「**自動案で更改**」で、契約が満了した全員に自動案(1 年・算定した年俸)を出し、断った選手は「保留」になります(理由:「年俸が低い」「出場機会が見込めない」「優勝を争えない」)。選手をタップすると提示のパネルが開き、年数(1〜5 年)と年俸(「+5%」「+10%」「−5%」のボタン)を決めて「提示する」(1 人 3 回まで)。「**自由契約にする**」は、交渉中の選手にも、複数年契約の途中の選手にも使えます(残りの契約は消えます)。お金のルールが「なし」でも、年俸は算定の 1.0〜1.3 倍で変えられます(D-273)。満了した全員が「更改済」「FA 宣言」「自由契約」になる(標準以上は総年俸が上限以下になる)と「次の手続きへ」が押せます。AI 球団の予算超過の解消と自由契約は、この段階の終わりに行われます。選手の志望(年俸・出場機会・勝利の重み)は隠し情報で、答え合わせモードがオンのときだけ提示のパネルに出ます。
13-6. **FA**(F3-2c):一軍に登録されたシーズン(各シーズンの開幕時の一軍 29 人)が 7 シーズンに達した選手は **FA 権**(フリーエージェント:他球団と自由に契約できる権利)を持ちます。年数は選手のページの「FA 権」に出ます。FA 権を持つ選手は更改の判定が厳しく、提示を断るとその場で **FA 宣言**して球団を離れます(止められません。年数は 0 に戻ります)。契約の段階のあとが「FA」の段階で、宣言した全選手の表(ポジション・年齢・前の所属・成績・算定年俸・状態)が出ます。名前を押すと提示のパネルが開き、年数(1〜5 年)と、年俸(±% のボタンあり。「なし」は算定の 1.0〜1.3 倍)を決めて「提示する」。何人にでも出せます(空き枠と予算の範囲)。状態バーの「ラウンド N を締める」で AI 球団の提示と合わせて選手が 1 つを選び、結果が出ます。これを 3 ラウンド行い、決まらなかった選手は自由契約市場へ回ります。元の球団も他球団と同じ立場です。「次の手続きへ」を押すと、自分は提示せずに残りのラウンドを締めます(「この段階をおまかせ」なら AI と同じ方針で提示します)。志望の重みは答え合わせモードのときだけ提示のパネルに出ます。
13-7. **FA・ドラフト・市場の画面**(UI の整理①b):3 つとも、上は状態バー(要約・総年俸・ボタン)と絞り込みの 1 行だけで、すぐ下が表です。絞り込みは「全員・投手・捕手・内野手・外野手」の 1 本で、投手などを選ぶと成績の種類(基本・セイバー・WAR)も選べます。列見出しを押すと並べ替わり(もう一度で逆順)、並べ替えた列は名前のすぐ右に固定されます。「**加入後の序列**」は、その選手が入ったら自球団の同じポジションで何番手になるか(● は一軍に入る見込み)。状態バーの要約を押すと、**自球団の状況**(ポジション別の人数と目安・主な選手の WAR と年齢・空き枠・予算)が開きます。◆ は自球団の手薄なポジション(人数が目安より 2 人以上少ない、または一軍相当の見込みが下位 4 球団)。**ドラフト**の列は 総合の推定値 ± ふれ幅・天井(S〜D)・年齢・出身・ポジション・加入後の序列。状態バーの「自分の番まで」で他球団の指名を進め、自分の番になったら名前を押して「指名する」(「パス」も状態バー)。**市場**は FA と同じ提示の方式です(1 ラウンド)。手放された選手は成績も、指名されなかった候補(前の所属「候補」)は評価も見られます。名前を押して年数と年俸を提示し、状態バーの「市場を締める」で AI 球団の提示と合わせて選手が選びます。決まらなかった選手はリーグを去ります。「この段階をおまかせ」は、ドラフトと FA の段階だけ確認が出ます。
14. 上の「**保存**」で、セーブデータ(`save-日付.sav`)がダウンロードされます。**自動では保存しません**。未保存の変更があるときは、上に「● 未保存の変更があります」と出て、ページを閉じようとすると警告が出ます。
15. 続きから遊ぶときは、スタートの画面の「**セーブデータを開く**」か、上の「**開く**」で、保存したファイルを選びます。読み込めないファイルのときは、理由が日本語で出て、今のゲームはそのまま残ります。

新規開始の「**詳しい設定**」では、シード(乱数の出方を決める初期値)を入れられます。同じシードなら、同じ選手・同じ試合結果になります(D-113)。普段は空欄のままで構いません。

### セーブデータの扱い(D-085、D-112)

- セーブデータには、入力した球団名が入ります。**実在の名前を入れたファイルは、ほかの人と共有しないでください**(SNS への投稿や、共有リンクで渡すことも含みます)。
- 個人のクラウド(自分だけが使うクラウドの保存場所)に置いて、スマホと自宅の PC で受け渡すのは構いません。ただし、**作業用の PC に同期のフォルダを作る**(PC にコピーが残る)ことと、**共有リンクを作る**ことは避けてください。
- ページは、入力した名前や進み具合を、ブラウザの保存領域(localStorage・IndexedDB・Cookie など)に書きません。外部にも送りません。

## しくみ

- **Pyodide(パイオダイド)**:ブラウザの中で Python を動かす仕組みです。配布元(`cdn.jsdelivr.net`)から読み込みます。
- **計算本体はそのまま**:`src/pennant/` のコードと初期データ(架空のデータ)を `pennant.zip` にまとめて、ページが読み込みます。書き換えはしていません。
- **Web Worker**:画面とは別に、裏で計算を進めるブラウザの仕組みです。計算中も画面は固まりません。
- **通信の制限**:ページに「通信してよい先」を書いてあり(Content-Security-Policy)、このページ自身と Pyodide の配布元以外には通信できません。
- **能力値は出さない**:答え合わせモードがオフのときは、画面と通信に、選手の公開用の情報だけを使います。能力は、オンのときだけ、答え合わせ用の入口から受け取ります(D-108、D-114)。

## 公開の設定(最初の1回だけ。設定済み)

GitHub Pages(リポジトリの内容を Web ページとして公開する機能)を使います。

1. GitHub でこのリポジトリのページを開きます。
2. 上のほうにある「**Settings**」(歯車のマーク)を押します。
3. 左の一覧から「**Pages**」を押します。
4. 「Build and deployment」の「**Source**」で、「**GitHub Actions**」を選びます(選ぶだけで保存されます)。
5. 上のほうにある「**Actions**」を押します。
6. 左の一覧から「**pages**」を押します。
7. 右のほうにある「**Run workflow**」を押し、出てきた緑の「**Run workflow**」をもう一度押します。
8. 1〜2分待つと、一覧の一番上に緑のチェックが付きます(黄色の丸は実行中です)。

この後は、`main` に計算本体やページの変更が取り込まれるたびに、自動で公開し直されます。

## 測定ページ(開発者向け。`/dev/`)

1. 公開先の URL の最後に `dev/` を付けて開きます。
2. 「**測定**」を押すと、Python の起動・1日分・1シーズン・集計・保存の速さとメモリを測ります。PC で約1分、スマホでは数分かかります。
3. 「**指紋を確かめる**」で、結果の指紋(同じシードなら、どの端末でも同じになるはずの値)を計算します。PC の `python scripts/fingerprint.py` と見比べます。
4. 結果の文章は「結果をコピー」でコピーし、報告 Issue のコメントに貼ります。名前などの個人の情報は入りません。

## 手元での試し方(開発者向け)

```bash
python scripts/build_web.py                       # _site/ を作る
python -m http.server 8000 --directory _site      # http://localhost:8000/ を開く(測定ページは /dev/)
```

通信のない環境で試すときは、Pyodide を手元に用意して `--pyodide <フォルダ>` を付けて作り、`http://localhost:8000/?pyodide=local` を開きます。

ブラウザでの通しの確認(Playwright という、ブラウザを自動で操作する道具が必要):

```bash
node scripts/check_browser.mjs http://127.0.0.1:8000/?pyodide=local
```
